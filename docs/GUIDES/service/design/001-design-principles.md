# デザイン原則

本サービス固有のビジュアル・文言の方向性を定める。コンポーネント実装規則・アクセシビリティ規則・レスポンシブの技術的な作法は`docs/GUIDES/tech/frontend`を正とし、本書はそれらの上に載せるサービス固有の判断のみを扱う。

## 世界観: サッカーの試合

サービス全体をサッカーの試合になぞらえる。ただし世界観は演出で示し、操作の理解を妨げない範囲に留める。

### サッカー用語を使う箇所

サッカー用語は「マッチの局面名」に限って使う。操作ボタン(Upvote・フォロー・ローンチ予約など)や機能名(ディレクトリ・コメント・評価)は一般用語のままとする。

| 局面・場所        | UI文言     | 補足                                          |
| ----------------- | ---------- | --------------------------------------------- |
| マッチ開始(0:00)  | キックオフ | 「明日キックオフ」「キックオフまであと3時間」 |
| マッチ終了(23:40) | フルタイム | 「フルタイム！Pitch Notesの勝利」             |
| 本日のマッチ一覧  | スタメン   | トップページ内の予選一覧セクション見出し      |

以下は使わない: 「ピッチ」(トップページの言い換え)、「ゴール」(Upvoteの言い換え)、「出場」(ローンチの言い換え)、「殿堂入り」(ディレクトリ掲載の言い換え)。

### 固定の用語

要件定義書1.3節の用語(マッチ・ペアリング・予選・サポーター・ディレクトリ・ローンチ・再ローンチ・フォロー)はそのまま用いる。英語固有名詞の表記は[表記規則](003-text-and-copy-rules.md#表記規則)を参照。

## カラー

shadcn/uiのデザイントークン(`--primary`等)に以下の意味付けを行う。具体的な色値はトークン定義を正とする。

| 役割                   | 基調                                                      | 用途                                                               |
| ---------------------- | --------------------------------------------------------- | ------------------------------------------------------------------ |
| プライマリ             | ピッチの深緑                                              | 主要ボタン、リンク、アクティブ状態、ヘッダー                       |
| アクセント(勝利・受賞) | ゴールド                                                  | 勝利バッジ、Product of the Week/Year賞、決勝の演出                 |
| 敗北                   | 彩度を落としたニュートラル                                | 敗北の結果表示。赤系の警告色は使わない(敗北は失敗ではない)         |
| 破壊的操作・エラー     | 赤(shadcn/uiの`destructive`)                              | 削除、退会、入力エラー                                             |
| スポンサー広告ティア   | Silver=銀、Gold=金、Legend=光沢感のある黒のグラデーション | 広告ラベルの色分け。Legendを黒にすることで受賞のゴールドと区別する |

- ライトモードは昼間の試合、ダークモードはナイターゲームの印象とする。ダークモードでは背景を深い緑がかった黒、プライマリを明度を上げた緑にする
- 勝利・受賞のゴールドは面積を絞って使う。常時表示のUIに広く使うと受賞の価値が下がる
- Upvote数のカウントはプライマリで表示し、マッチ中は対戦相手との差が分かるようバー表示を併用する

## 文体・語調

| 対象                   | 文体                       | 例                                                                   |
| ---------------------- | -------------------------- | -------------------------------------------------------------------- |
| ボタン・ラベル・見出し | 体言止め                   | 「ローンチを予約🚀」「フォロー中」「決済期限」                       |
| 説明文・ヘルプテキスト | です・ます調               | 「ローンチ日は翌日以降を選べます」                                   |
| バリデーションエラー   | です・ます調               | 「このハンドルは既に使われています」                                 |
| 勝敗・受賞の演出       | 熱めのトーン               | 「フルタイム！12対9で勝利」「Product of the Weekの受賞おめでとう🎉」 |
| 敗北の演出             | 前向き、次の行動を示す     | 「フルタイム。次のローンチ日は9月14日以降、何度でも挑戦できます🚀」  |
| メール本文             | です・ます調、演出は控えめ | 件名に接頭辞は付けず件名のみ                                         |

- 敗北を責める表現、相手を貶める表現は使わない。「必ず半分は勝者になる」思想に沿い、敗北時は再ローンチへの導線を必ず示す
- 具体的な文言例は[文言・文字数規則](003-text-and-copy-rules.md)を参照

## 画像のプレースホルダー

プロフィール画像・プロダクトロゴが未設定、読み込み失敗、隔離中(FR-FILEU-011・FR-FILEU-012)の場合は、ニックネームまたはプロダクト名の先頭1文字を背景色付きの正方形で表示する。

- 背景色はユーザー・管理者・プロダクトIDのハッシュから決定論的に選ぶ
- 文字色は背景とのコントラスト比がWCAG 2.2 AAを満たすよう白または黒を自動選択する
- 先頭1文字は書記素単位で取り出す(絵文字・結合文字を分断しない)
- スクリーンショットの読み込み失敗時は、枠のみのスケルトンに「画像を表示できません」を重ねる

## 状態表示

UI-005の各状態とNFR-AVAIL-002の縮退運転を、本サービスでは以下のように表現する。

| 状態           | 本サービスでの表現                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------ |
| ローディング   | スケルトン。マッチカードはロゴ・名称・Upvoteボタンの形を保つ                                                             |
| 空(データなし) | 次の行動への導線を添える。例: 予選一覧が空なら「本日のマッチはありません。ローンチを予約しましょう。」                   |
| エラー         | 再試行ボタンと問い合わせへの導線。技術的詳細は表示しない                                                                 |
| 縮退運転       | 外部サービス障害時は閲覧機能を維持し、影響する操作(決済・アップロード等)のボタン近くに「現在ご利用いただけません」を表示 |

## 日時・数値の表示

- 日時は`<time datetime="ISO 8601">`で出力し、I18N-004・I18N-005に従いユーザーのタイムゾーン・ロケールで表示する
- マッチの開始・終了や決済期限など基準時刻(UTC-08:00)で定義される時刻は、ユーザーのタイムゾーンでの表示に加えて相対表現(「あと2時間」「明日」)を併記する。基準時刻そのものはWebのUIに出さない
- メール内の日時の表記は[通知メールの本文の構成](003-text-and-copy-rules.md#本文の構成)、週の表記は[表記規則](003-text-and-copy-rules.md#表記規則)を参照
- 通貨はUSDのみ(I18N-003)。`$9`・`$5.50`のようにドル記号を付け、小数点以下は全て0なら省略する(`$9.00`とは書かない)。ロケールに応じた桁区切りを適用する

## ブラウザ翻訳への耐性

UI文言の多言語切替は提供しないが、ブラウザの翻訳機能で他言語に置き換えられてもレイアウトが崩れないようにする(I18N-001)。

- ボタン・タブ・バッジは固定幅にせず、文言の1.5倍程度の長さまで折り返さずに収まる余白を持たせる
- 文字数に依存する縦横比のカード(マッチカード等)は、タグラインを2行で省略表示する
- 英語固有名詞(Upvote等)はブラウザ翻訳で変化し得るため、アイコンを併記して意味を保つ
