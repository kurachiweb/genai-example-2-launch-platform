# 文言・文字数規則

入力欄の文字数上限、UI文言の表記、通知メールの文面規則を定める。文体・語調の方針は[デザイン原則](001-design-principles.md)を参照。

## 入力欄の文字数上限

上限値・必須区分・文字種の制約は対応要件を正とし、本表はその索引である。

文字数は原則書記素(ユーザーが1文字と認識する単位)で数えるが、パスワードに限りコードポイント数で数える。全角・半角・絵文字を区別しない。上限はフロントエンドでフォーカスアウト時(UI-005)に検証し、サーバー側でも同じ値で検証する(NFR-SECUR-012)。

### 容量の単位

要件定義書とUIでファイルサイズの上限を`kB`・`MB`で書く場合、1,024を基数とする(1kB = 1,024バイト、1MB = 1,048,576バイト)。実装の定数とテストの境界値はこの換算で求めたバイト数にし、1,000を基数とする値(500,000バイト・20,000,000バイトなど)を使わない。UIの表記は要件定義書と同じ`kB`・`MB`のままとし、`KiB`・`MiB`と書かない。

| 表記  | バイト数   |
| ----- | ---------- |
| 500kB | 512,000    |
| 5MB   | 5,242,880  |
| 10MB  | 10,485,760 |
| 20MB  | 20,971,520 |

外部サービスが定める上限は、そのサービスの仕様のバイト数に従い、この規則の対象外とする。

### 共通のエラー応答の文言

フロントエンドサーバーとAPIサーバーの間の中継・通信で起きる失敗は、エラーコードごとに次の文言を返し、画面にもそのまま表示する。問い合わせの導線が無い管理者側の画面にもそのまま出るため、どの文言も問い合わせを促す文を含めない。

| 状況                                      | エラーコード(状態コード)                                 | 文言                                                                           |
| ----------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------ |
| CSRF対策による操作の拒否                  | `csrf_rejected`(403)                                     | この操作を受け付けられませんでした。ページを再読み込みして再度お試しください。 |
| 受け付けない操作の方法・形式              | `method_not_allowed`(405)・`unsupported_media_type`(415) | この操作を受け付けられませんでした。ページを再読み込みして再度お試しください。 |
| 中継先(APIサーバー)の障害・応答の時間切れ | `upstream_unavailable`(503)・`upstream_timeout`(503)     | 現在ご利用いただけません。時間をおいて再度お試しください。                     |
| 中継先からの応答の形式が不正              | `invalid_response`                                       | 現在ご利用いただけません。時間をおいて再度お試しください。                     |
| ブラウザからの通信の失敗                  | `network_error`                                          | 通信に失敗しました。時間をおいて再度お試しください。                           |
| 中継の対象に無い要求                      | `not_found`(404)                                         | お探しの内容は見つかりませんでした。                                           |
| サーバー内部の失敗                        | `internal_error`(500)                                    | 問題が発生しました。時間をおいて再度お試しください。                           |
| 要求の集中                                | `rate_limit_exceeded`(429)                               | 操作が集中しています。しばらく待ってから再度お試しください。                   |

ページの要求が集中した場合の画面(429)は`rate_limit_exceeded`と同じ文言を表示する。フロントエンドサーバーの設定の不備や想定外の例外でページを描画できない場合の画面(500)は、[想定外のエラーの画面](#状態案内の文言)の見出しと案内をつなげた文言を表示する。

| 画面                                 | 静的な500の画面の文言                                                                                |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 問い合わせの導線がある画面(利用者側) | ページを表示できませんでした。時間をおいて再度お試しください。解決しない場合はお問い合わせください。 |
| 問い合わせの導線が無い画面(管理者側) | ページを表示できませんでした。時間をおいて再度お試しください。                                       |

### 本文の構成

1. 宛名(ニックネーム) ... 未ログインの申出者(FR-REPOT-003)なら省略
2. 本文(1〜3段落、です・ます調)
3. 主要な行動へのボタン(マッチを見る、参加費を支払う、ダウンロードなど)
4. 通知種別ごとの配信停止リンク(FR-NOTIF-001・004・006・007のみ)
5. 送信者情報: 事業者名・連絡先・物理的郵送先住所(FR-NOTIF-010)

- メール内の日時(決済期限・キックオフ時刻等)は受信者のタイムゾーンを知り得ないため、UTCのみで表記しタイムゾーンを明記する。例: 「9月15日07:40(UTC)」。リンク先のWebページではブラウザのタイムゾーンで表示する
- 予選勝利の結果通知にはWeekトーナメントの決済期限を明記する
- Weekトーナメント決勝勝利の結果通知にはYearトーナメントの決済期限を明記する
- 配信停止リンクを付ける通知種別と付けない通知種別は[通知メールのオプトアウト](../legal/001-compliance-policy.md#通知メールのオプトアウトlr-005)を正とする
