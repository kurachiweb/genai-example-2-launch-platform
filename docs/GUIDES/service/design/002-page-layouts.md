# ページ構成とレイアウト

利用者側・管理者側それぞれのページ一覧と、主要ページの情報配置を定める。各ページに表示する項目や操作の規則は対応要件を正とし、本書は要件定義書に無いURL・配置・並び順・UI上の振る舞いを定める。共通コンポーネントの実装規則は`docs/GUIDES/tech/frontend`を正とする。

### 旧ハンドルの保持とリダイレクト

保持・リダイレクト・削除時の例外はFR-USER-019・FR-UPROF-010・012・013・FR-PRDCT-020・021・023・FR-ADMAG-026・028・029・FR-HELP-011を正とする。

ハンドルの規則は利用者のハンドルを例に定める。文字種・大文字小文字を区別しない一意性の規則は、利用者・プロダクト・ヘルプ記事・プロダクトカテゴリの全ての対象で同じに従う。予約語の規則は利用者とプロダクトだけに適用し、ヘルプ記事(FR-ADMAG-029)とプロダクトカテゴリ(ディレクトリの絞り込みのURLクエリにだけ使い、なりすましの対象にならない)には適用しない。旧ハンドルを保持するのは利用者・プロダクト・ヘルプ記事で、プロダクトカテゴリは旧ハンドルを保持する根拠が要件に無いため、保持の対象に含めない。

- 変更前のハンドルは旧ハンドルとして1つだけ保持し、既に保持していた旧ハンドルは置き換える
- 旧ハンドルで公開プロフィールのURLを開くと、現在のハンドルのURLへ一時的なリダイレクト(HTTP 302)で移し、URLのクエリを引き継ぐ。ハンドルの一致は大文字小文字を区別しない
- 大文字小文字の表記だけを変えた場合は、表記を更新するだけで旧ハンドルは保持しない
- 自分が保持している旧ハンドルを新しいハンドルとして設定できる。その場合、変更前のハンドルが新しい旧ハンドルとして保持される
- 他の利用者が保持している旧ハンドル(退会後に物理削除されていない利用者の分を含む)も、新しいハンドルとして設定できる。設定を確定した時点で、元の保持者のその旧ハンドルを削除し、旧URLの転送を止める。以後そのURLは新しい設定者の公開プロフィールになる
- 旧ハンドルは、保持者が次にハンドルを変更して置き換えるまで、他の利用者がその文字列を設定するまで、または退会した保持者が物理削除されるまで保持する
- 保持者が退会済み、または停止中で閲覧者が本人でない場合は、転送せず存在しないハンドルと同じ404を表示する。保持者本人が閲覧する場合は、停止中でも現在のハンドルのURLへ転送する
- プロフィール編集画面は保持中の旧ハンドルを表示し、次にハンドルを変更するまで以前のURLが転送されること、他の利用者が同じハンドルを設定すると転送が止まることを案内する

運営・権限者を装うなりすまし対策として、ユーザー及びプロダクトのハンドル文字列には、以下の予約語を大文字小文字の区別無く使用できない。

`admin`・`administrator`・`root`・`superuser`・`staff`・`moderator`・`mod`・`official`・`support`・`security`・`team`・`launchstadium`・`launch-stadium`・`launch_stadium`

## 共通レイアウト(利用者側)

- ヘッダーには左からロゴ(「⚽️ Launch Stadium」、トップページへ遷移)・ディレクトリ・ヘルプを、右端にダークモードの切替ボタン・「ローンチする」・未ログイン時のログインと登録(ログイン済みならユーザーメニュー)を表示する。幅が足りない時は、右端の部品を次の行の右端へ折り返す
- 幅768px未満では、ディレクトリ・ヘルプ・「ローンチする」・ログインと登録(ユーザーメニュー)を「メニュー」ボタンで開くシートにまとめ、ヘッダーにはロゴ・ダークモードの切替ボタン・「メニュー」ボタンを残す
- ヘッダーの「ローンチする」は未ログイン時はログインページへ(ログインの後にプロダクト登録ページへ戻る)、ログイン済みならプロダクト登録ページへ遷移する
- ユーザーメニュー: プロフィール、自身のプロダクト、設定、ログアウト(FR-USER-011)
- ヘッダーのアカウント表示: 未ログイン時は「ログイン」「登録」のボタンを、ログイン済みならユーザーメニューを開くボタンを表示する。ボタンにはニックネームの先頭1文字(書記素単位)を丸で示し、幅640px以上ではニックネームを並べる(長いニックネームは折り返す)。メニューの先頭にはニックネームと`@`付きのハンドルを表示する。ログアウトするとトーストで知らせ、表示中のページをログアウトした状態で表示し直す
- フッターにはFR-HELP-006・LR-001で定めるリンクを常に表示する。左からサービス名と説明文、「ヘルプ」の列(ヘルプトップとピン留めされたヘルプ記事)、「規約・問い合わせ」の列(利用規約・プライバシーポリシー・法的通知・料金・お問い合わせ)を並べる
- 検索欄は共通ヘッダーに置かず、ディレクトリとヘルプの各ページ内に置く
- 存在しないページ・想定外のエラーの表示も、ヘッダーとフッターを保った共通レイアウトの本文の中に出す

### ダークモードの切替ボタン

- 月(ライトモード表示中)または太陽(ダークモード表示中)のアイコンのボタンとし、切り替え先を示す名前「ダークモードに切り替え」「ライトモードに切り替え」をツールチップと支援技術向けの名前に使う。押されているかどうかの状態(`aria-pressed`)は持たない
- 選んだ配色はブラウザに保存し、次回以降の表示にも使う。保存が無い場合は、ページを読み込んだ時点のOSの配色の設定に従う(表示中にOSの設定を変えても追従しない)
- 最初の描画の前に配色を決め、ライトモードからダークモードへの切り替わりのちらつきを出さない

## トップページ

当日の予選マッチの全てを、残り時間とUpvoteの動きと共に見せ、その場でUpvoteさせるページ。後続の機能(トーナメント・スポンサー広告)は、このページを書き換えずに区画を登録して加える([トップページの区画の登録](#トップページの区画の登録))。文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)・[操作とナビゲーションの名前](003-text-and-copy-rules.md#操作とナビゲーションの名前)・[演出文言](003-text-and-copy-rules.md#演出文言)を参照。

上から順に以下を配置する。該当するマッチが無い区画は表示しない。ただし予選の区画はマッチが無くても[空の状態](#予選の区画の空の状態)を表示する。

1. 上部の行: 先頭に[自動更新の切り替え](#自動更新の切り替え)を置き、続けてフルタイムまでのカウントダウン(予選のマッチ中のみ)とLegendのスポンサー広告を、画面幅に応じて1〜4列のグリッドで並べる。カウントダウンは「フルタイムまであと」と残り時間の「時:分:秒」に、終了の時刻を「(23:40終了)」の形で併記する
2. 未ログインの案内(未ログインの閲覧者のみ): サービス名・キャッチコピー・説明と、「登録してローンチする」(ユーザー登録へ)・「ログイン」(トップページを戻り先にしてログインへ)
3. 全幅の注目の区画: トーナメントの決勝(開催中の場合)
4. 本文の列と横の列: 本文の列に上から次の3つを置き、横の列にGoldのスポンサー広告を置く。横の列は画面幅1024px未満では本文の下に移す
   1. Yearトーナメントのマッチ(開催中の場合)。ラウンド名(1回戦/準々決勝/準決勝/決勝)と決勝日を見出しに表示
   2. Weekトーナメントのマッチ(開催中の場合)。複数の週のトーナメントが重なる場合はFR-TOURW-013の順。第◯週とラウンド名を見出しに表示

- 初回の表示はサーバーで描画する。予選の一覧の取得に失敗した場合は、取得エラーの文言と再試行ボタン・問い合わせへの導線を表示する。部分的な対戦カード(プロダクトの情報が欠けたもの)は出さない

### トップページの区画の登録

後続の機能は、次の置き場所に順の値を付けて区画を登録する。同じ置き場所の区画は順の値の小さい順に並べる。区画はそれぞれ自分でデータを取得し、該当しなければ何も表示しない。区画には、当日の予選の日付・時間帯(マッチ中・結果)・サーバーの時刻、閲覧者がログインしているか、[自動更新の切り替え](#自動更新の切り替え)の状態を渡す。区画は定期の取り直し・数値の毎秒の更新・演出を持つ間はその旨をページへ申告し、ページは切り替えを描くかどうかの判定に使う。区画が失敗して表示を止めた時とページから外れた時は、その区画の申告を取り消す。

| 置き場所     | 表示の位置                               | 登録する区画(順の値)                                                                             |
| ------------ | ---------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 上部の行     | 自動更新の切り替えの後                   | フルタイムまでのカウントダウン(10)、Legendのスポンサー広告(スポンサー広告の機能が順を決める)     |
| 全幅の注目   | 未ログインの案内の下                     | トーナメントの決勝(トーナメントの機能)                                                           |
| 本文         | 本文の列                                 | Yearトーナメント(10)・Weekトーナメント(20)・予選(30)。予選より前に置く区画は30より小さい値を使う |
| 横の列       | 本文の列の横(画面幅1024px未満は本文の下) | Goldのスポンサー広告(スポンサー広告の機能)                                                       |
| フッター直上 | フッターの上                             | Silverのスポンサー広告(スポンサー広告の機能)                                                     |

予選の一覧には、対戦カードの指定の件数ごとに区画を差し込む登録口も置く。差し込む区画には何番目の差し込みかを渡し、表示する画面幅の判定は区画が持つ。スポンサー広告の機能が、モバイルのGoldを2件ごとに差し込む([スポンサー広告スペース](#スポンサー広告スペース))。

### 自動更新の切り替え

2026-11-10に開発者が確定した決定である。トップページは定期的に取り直す区画と、止まらずに動く演出を複数持つため、区画ごとではなくページ全体で1つの切り替えを置く。

- 上部の行の先頭に「自動更新」の切り替え(スイッチ)を1つだけ置く。登録された区画とは別に描き、区画の失敗や結果の時間帯でも消えない。各区画の見出しの近くには置かない
- キーボードで操作でき、オン・オフの状態を支援技術へ伝え、取り直しの間隔と止める範囲の説明を結び付ける。ページを開くたびにオンから始める
- オフの間は、全ての区画(トーナメントの区画を含む)のUpvote数の定期の取り直し、カウントダウンの毎秒の更新、対戦カードと区画の演出(観客・旗・ボールの動き・点滅・比率のバーの動き)を止める。カウントダウンは毎秒の数字を出さず、終了の時刻の表示だけを残す
- オフでも、終了(23:40)と翌日の開始(0:00)の時刻の直後の取り直しと、Upvoteなどの操作の後の更新は止めない
- 切り替えは、予選のマッチ中の時間帯、当日の予選の対戦カードがある間、または区画が定期の取り直し・数値の毎秒の更新・演出を持つと申告している間に描く。結果が確定して定期の取り直しが止まっても演出が残るなら描き、どれにも当たらない(結果の時間帯で対戦カードが無く、申告している区画も無い)ときは描かない
- ページの根の要素に切り替えの状態を`data-auto-refresh`の`"on"`・`"off"`で示し、演出は`"on"`の下でだけ動かす。視差効果を減らす設定の閲覧者には、オンでも演出を動かさない。トップページの外で対戦カードを使うページは、自分で停止の手段を置いて同じ属性を付けない限り演出を動かさない。プロダクト詳細は[プロダクト詳細の自動更新の切り替え](#プロダクト詳細の自動更新の切り替え)で同じ切り替えを置く

### 予選の区画

- 見出し「予選」に、本日の予選マッチの試合数と時刻を添える。試合数は対戦カードの数に即時に終了したマッチ(早期勝利)を加えた数とし、対戦相手がいない・マッチ直前の相手の退会等による不戦勝は数えない。両者敗北のマッチ(マッチの直前に両方の側が退会等に該当した場合と、両方の側が同じ投稿者でマッチ中に該当した場合)は、対戦カードにも不戦勝にも出さず試合数にも数えないため、それだけの日は空の状態になる。時刻は、マッチ中は「フルタイム」と終了の時刻、23:40以降は「明日のキックオフ」と翌日の開始の時刻を示す
- 対戦カードを[並び順](#予選マッチの並び順)に、画面幅1280px以上は2列(先頭のカードだけ全幅)で並べ、末尾に[不戦勝](#マッチの不戦勝表示)の一覧を置く
- 0:00から23:40まではマッチ中としてUpvoteを受け付ける。23:40から24:00までは各カードに結果を示し、結果の確定の前は「結果を集計しています」と示す
- 自動更新がオンの間は、30秒ごとに表示中のマッチのUpvote数を取り直し、カードの並び順は最初の取得の順のまま値だけを差し替える。結果がすべて確定した後と、マッチの無い日は定期の取り直しを止める
- 終了(23:40)と翌日の開始(0:00)の時刻の1秒後に取り直す。その直後の取得がまだ結果の確定の前・マッチの開始の前の状態を返す間は、自動更新がオフでも、ページを表示した時点と最後の境界の取り直しのうち後の時点から取得が10回に達するまで30秒ごとに取り直す。10回に達しても状態が変わらなければ、見出しの下の状態の文(支援技術へ伝える)を、ページを開き直す案内に切り替える

### 予選の区画の空の状態

当日の予選の対戦カードも不戦勝も無い場合は、他の区画と違って区画を消さず、見出し(試合数は0)を残したまま、人のいないピッチの図を背景に「本日のマッチはありません。ローンチを予約しましょう。」と導線「ローンチを予約🚀」(未ログインは「ログインしてローンチを予約🚀」)を置く。導線の遷移先は共通ヘッダーの「ローンチする」と同じとする。

### 予選マッチの並び順

合計Upvote数(両プロダクトの和)が最も多いマッチを先頭に置き、それ以外は合計Upvote数が少ない順に並べる。注目のマッチを見せつつ、注目されていないマッチにも露出を回す意図である。同数の場合はマッチID順。並び替えはページ読み込み時に行い、閲覧中はリアルタイムに動かさない。

### マッチの不戦勝表示

不戦勝(対戦相手なし、FR-GAME-004・016、FR-TOURW-020・023、FR-TOURY-023・026)はUpvoteを受け付けないため対戦カードを出さず、該当の一覧末尾「不戦勝」セクション([表記規則](003-text-and-copy-rules.md#表記規則))に当該プロダクト情報のみを表示する。予選のペアリングの余り(FR-GAME-004)は1日のローンチ数が奇数の場合に最大1件のみ生じるが、マッチ直前の対戦相手の退会等及びブラケット内の不戦勝連鎖(FR-GAME-016、FR-TOURW-020・023、FR-TOURY-023・026)は件数に上限が無い。

### マッチの早期勝利表示

マッチ中に対戦相手側で投稿者の退会・停止またはプロダクトの非公開化が発生した場合(FR-GAME-015)、Upvote受付が打ち切られてマッチが終了し、勝者となったプロダクトは進行中の対戦カードから外れる。不戦勝表示と同じく予選一覧の末尾「不戦勝」セクション([表記規則](003-text-and-copy-rules.md#表記規則))に当該プロダクト情報のみを表示する。Week・Yearトーナメントのマッチ中の早期勝利(FR-TOURW-019・FR-TOURY-022)も、該当トーナメントの一覧末尾に同様に表示する。

### マッチカード

表示項目と導線はFR-GAME-007・FR-GAME-008、Upvoteボタンの活性条件はFR-VOTE-003・FR-VOTE-005を正とする。

- カードにはカテゴリを表示する
- カードの見出しの行には、マッチ中は呼び出し元(トーナメントの区画など)が渡す補足を、終了の時刻を過ぎて結果の確定を待つ間は「結果を集計しています」を、確定の後は結果の文言(最終Upvote時間で勝敗が決まった場合はその注記を添える。0対0は両者敗北)を示し、右端に種別の印(予選は「予選」、トーナメントはラウンド)を置く。文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)
- 名称は、ディレクトリに掲載されているか閲覧者自身のプロダクトであればプロダクト詳細へのリンクにする
- 「サイトを開く」は外部Webサイトを別タブで開く。`rel`属性は[外部Webサイトへのリンク](#外部webサイトへのリンク)に従う
- Upvoteボタンは押下でトグル(Upvote/取り消し)。もう一方の側にUpvote済みなら、押下で新しい側へ付け替える。無効化時は理由を`aria-describedby`やツールチップで示す
  - 閲覧者自身のプロダクトの側にはボタンを出さず、Upvote数だけを表示する。その対戦相手の側のボタンは無効にする
  - 無効にする理由は、自分のプロダクトの対戦相手・マッチ外(開始前・集計中・終了後)・メールアドレス未確認の3つ。未ログインの閲覧者にはボタンを押せる状態で示し、押下でログインの案内のダイアログを開き、ログインの後は表示中のページへ戻す
  - Upvote・取り消し・付け替えが成功したら、Upvote数・比率のバー・ボタンの状態をサーバーの結果で更新し、トーストで知らせる。拒否・失敗した場合は表示を操作の前のまま変えず、理由の文言をトーストで示す
- 側のプロダクトが表示できない(非公開化・投稿者の退会や停止・論理削除・物理削除で紐付けを解除済み)場合は、名称の代わりに「非公開のプロダクト」と汎用のアイコンを表示し、リンク・「サイトを開く」・Upvoteボタンを出さない。理由は推測させない
- 中央のバーは両者のUpvote数の比率。0対0のときは空のバー。支援技術には両者の名称とUpvote数を読ませる
- Upvoteの演出(観客の盛り上がり・ボール)と常に動く演出(旗・ボールの回転・点滅)は、[自動更新の切り替え](#自動更新の切り替え)がオンの間だけ動かし、視差効果を減らす設定の閲覧者には動かさない
- カテゴリ横断マッチはカテゴリを両プロダクト分表示する
- 予選及び準決勝以前のトーナメントにおいて、不戦勝のプロダクトはマッチカードとして並べず、各セクションのマッチカード一覧の下に「不戦勝」一覧としてUpvoteボタンなしで表示する
  - 対戦相手が元々いない場合(FR-TOURW-023・FR-TOURY-026)に加え、対戦相手の退会・停止・非公開化でマッチが早期終了した場合(FR-GAME-015・FR-TOURW-019・FR-TOURY-022)もこの一覧に移すと共に、終了時点で確定したUpvote数を添える
- 画面幅640px未満では2つのプロダクトを縦に積み、Upvote比率バーをその間に置く。それ以上の画面幅でも、カードの幅が768px未満(本文の2列の配置など)なら同じく縦に積む
- 「不戦勝」一覧の各項目には、ロゴ・「不戦勝」のバッジ・カテゴリ・名称・タグライン・「サイトを開く」と、マッチの種別(予選・トーナメント)と早期勝利かどうかで切り替える説明文([状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言))を表示する

## ディレクトリ(`/p`)

表示項目・絞り込み・検索・ソート・ページネーションはFR-DIR-002・FR-DIR-007・009〜012を正とする。後続の機能(スポンサー広告など)は、このページを書き換えずに区画を登録して加える([ディレクトリの区画の登録](#ディレクトリの区画の登録))。文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)・[操作とナビゲーションの名前](003-text-and-copy-rules.md#操作とナビゲーションの名前)を参照。

上から順に以下を配置する。

1. ページ上部の区画(登録された区画がある場合のみ)
2. 見出し: ページの`h1`「ディレクトリ」と1行の説明文
3. 検索欄
4. 絞り込み・並び順: PC(768px以上)は検索欄の下にカテゴリ・期間・並び順の選択欄を横並びにし、選んだ時点で一覧に反映する。モバイルは「絞り込み・並び順」ボタン(既定値から変更中の項目数を添える)から下部シートを開き、「適用」でまとめて反映する
5. 件数: 「1,234件中21〜40件」。1ページに収まる場合は「3件」
6. 一覧(1列)とページネーション。横の列の区画を登録された場合は一覧の横(画面幅1024px未満は一覧の下)に置く
7. ローンチ予約への導線: 一覧の末尾に控えめに置く(該当するプロダクトがある場合のみ)。遷移先は共通ヘッダーの「ローンチする」と同じ(未ログインはログインへ、ログイン済みならプロダクト登録ページへ)とし、0件(条件なし)の導線も同じとする
8. ページ末尾の区画(登録された区画がある場合のみ)

- 初回の表示は、URLクエリから復元した条件でサーバーで描画する。ページのタイトルは「ディレクトリ」、説明は見出しの説明文とし、正規のURLは`/p`とする
- アニメーション演出は使わず、読み物として静止させる(動くのはスケルトン・進捗バー・ホバー等の状態変化のみ)

### ディレクトリの区画の登録

2026-10-24に開発者が確定した決定(directory-discoveryの仮3)である。要件定義書(FR-SPONS-009)がディレクトリにも広告スペースを挙げるため、ディレクトリにも区画の登録口を設ける。広告を表示するかどうかと中身はスポンサー広告の機能が決め、ディレクトリの機能は何も登録しない。

後続の機能は、次の置き場所に順の値を付けて区画を登録する。同じ置き場所の区画は順の値の小さい順に並べる。区画はそれぞれ自分でデータを取得し、該当しなければ何も表示しない。区画には、閲覧者がログインしているかと、正規化した検索・絞り込み・並び順・ページの条件を渡す。区画の取得や描画の失敗はその区画の位置だけに閉じ込め、一覧の表示を止めない。登録が無い置き場所と、何も表示しない区画は、枠と間隔を残さない。

| 置き場所       | 表示の位置                               | 登録する区画の例                                                       |
| -------------- | ---------------------------------------- | ---------------------------------------------------------------------- |
| ページ上部     | 共通ヘッダーの下、見出しの上             | Legendのスポンサー広告(スポンサー広告の機能が表示するかを決める)       |
| 横の列         | 一覧の横(画面幅1024px未満は一覧の下)     | Goldのスポンサー広告(同上)                                             |
| ページ末尾     | ローンチ予約への導線の下(フッターの直上) | Silverのスポンサー広告(同上)                                           |
| 一覧の差し込み | 一覧の指定の件数ごと                     | モバイルのGoldのスポンサー広告(同上。表示する画面幅の判定は区画が持つ) |

一覧の差し込みは、指定の件数ごとに(一覧の項目の数が指定の件数で割り切れるときは最後の項目の後にも)区画を置き、何番目の差し込みか(1から)を渡す。

一覧の項目には、後続の機能がプロダクトごとの値(コメント数など)を順の値を付けて加える。値の取得に失敗した場合は、その値だけを表示せずに一覧を表示する。

### 検索

- Enterキーまたは検索ボタンで実行し、入力中は一覧を更新しない。IME変換中の誤操作と全文検索への問い合わせ回数を抑えるためである。入力欄内には消去ボタンを置く
- 40文字を超えたら「45/50」の文字数カウンターを表示する。50文字を超えた場合はフォーカスアウト時と送信時にエラーを示し、検索を実行しない
- 名称・タグライン中の検索語との一致箇所を`<mark>`で強調する。大文字小文字・全角半角・発音区別符号の違いは無視する。説明文やキーワード抽出結果のみで一致したプロダクトには強調が付かない

### 絞り込み

- カテゴリ: 絞り込み入力付きのリストボックス(コンボボックス)とし、数十件に増えても文字入力で選べるようにする。選択肢は既定値の「全て」に続けて掲載数が多い順、同数は名称順に並べ、システム標準の「その他」は具体的なカテゴリを埋もれさせないよう末尾に固定する。掲載数は表示しない
- URLクエリの`category`にはカテゴリのハンドル文字列(FR-ADMCF-008)を用いる(例: `?category=developer-tools`)。カテゴリ名を変更しても共有済みのリンクが壊れないためである。「その他」のハンドル文字列は`other`とする。ハンドル文字列を変更した場合、変更前の値は保持せず、旧URLは「全て」として扱う
- 期間: 「昨日/今週/今月/今年/全期間」のプリセットと「期間を指定…」から選ぶ。既定値は全期間。週(月曜日始まり)・月・年は基準時刻(UTC-08:00)の暦日で区切り、URLクエリには`from`・`to`(YYYY-MM-DD)へ区切り全体として展開する(例: 今週は月曜日〜日曜日)。同じ週・月の間はURLが変わらず、共有したリンクもその期間中は「今週」「今月」として表示される
- 期間を指定: 開始日・終了日の日付入力をポップオーバー(モバイルは絞り込みシート内)に置く。片方のみの指定も可とし、その日以降・以前で絞り込む。開始日が終了日より後の場合は「開始日は終了日以前の日付を選んでください。」、未来の日付は「未来の日付は選べません。」をフォーカスアウト時に示し、適用ボタンを無効化する
- プリセットと一致しない`from`・`to`(期間を指定した場合や、過去に共有された「今週」のリンクなど)は、選択欄に「9月14日〜9月20日」「9月1日以降」のように表示する
- 不正なURLクエリ(存在しないカテゴリ、実在しない日付、開始日が終了日より後の期間、検索語が無い場合の関連度など)は黙って既定値に戻す。50文字を超える検索語は50文字に切り詰める
- 検索・絞り込み・並び順を変更したら1ページ目へ戻す

### 並び順

- 「関連度/ローンチ日が新しい順/ローンチ日が古い順/Upvote数が多い順」から選ぶ。URLクエリの`sort`は`relevance`・`newest`・`oldest`・`upvotes`とし、既定値はURLから省略する
- 「関連度」は検索語がある場合のみ選択でき、検索時の既定値とする。選べない間は「検索キーワードを入力すると選べます」を併記する。検索語が無い場合の既定値はローンチ日が新しい順
- 「Upvote数が少ない順」は注目されなかったプロダクトの一覧に見えるため設けない

### 一覧項目

PC(1024px以上)は「プロダクト情報・勝利した予選マッチ・操作ボタン」の3列、タブレットは2列(操作ボタンは勝利した予選マッチの下)、モバイルは縦に積む。

- プロダクト情報: ロゴ(`square-sm`)、受賞バッジ、名称、タグライン(2行で省略)、カテゴリ、投稿者(アバター・ニックネーム)、コメント数(全ローンチの合計で、削除・非公開化されたものを除く)
  - コメント数はコメントの機能が一覧の項目の値として加える([ディレクトリの区画の登録](#ディレクトリの区画の登録))。登録が無い間と値の取得に失敗した間は表示しない
- 項目全体をプロダクト詳細へのリンクとする(名称のリンクを項目全体に広げる)。カテゴリ・投稿者・コメント数・ボタンは個別に操作でき、カテゴリは他の条件を維持したままそのカテゴリで絞り込み、投稿者は公開プロフィールへ、コメント数はプロダクト詳細のマッチ履歴とコメントへ移動する
- 受賞バッジ: Product of the Week/Year受賞プロダクトにはゴールドのバッジを賞の種類ごとに1つ付け、Yearを先頭に置く。複数回の受賞は「×3」のように回数を添え、受賞した週([表記規則](003-text-and-copy-rules.md#表記規則))・年はツールチップで示す
- 投稿者本人のプロダクトには、投稿者の代わりに「あなたのプロダクト」バッジを付け、「編集」ボタンを置く
- 「サイトを開く」は外部Webサイトを別タブで開く。`rel`属性は[外部Webサイトへのリンク](#外部webサイトへのリンク)に従う
- 勝利した予選マッチ: 項目ごとに「予選勝利」とローンチ日(今年なら年を省略)、自身のUpvote数(「1,234票」)を表示する。対戦相手のロゴ・名称・Upvote数と比率バーは表示しない
  - 複数回勝利したプロダクトは基準勝利マッチ1件の情報を表示する。基準勝利は、ローンチ期間で絞り込む場合は期間内の最新の勝利、それ以外は直近の勝利とする
  - ソートキーの「ローンチ日」「Upvote数」も基準勝利の値を用いる
  - 同数で最終Upvote時間により勝敗が決まったマッチでも特別な文言は出さない
  - 対戦相手がいない不戦勝(FR-GAME-004・FR-GAME-016)はUpvote数を出さず、「不戦勝」に「対戦相手がいないため」を添える。早期勝敗決定による不戦勝(FR-GAME-015)は、「不戦勝」に確定時点の自身のUpvote数を添える

#### 一覧の単位と基準勝利

2026-10-24に開発者が確定した決定(directory-discoveryの仮1・仮2)である。

- 1つのプロダクトは、予選の勝利の回数によらず一覧の1項目とし、基準勝利の1件の情報を表示する(仮1)
- 基準勝利は、ローンチ期間で絞り込む場合は期間内でローンチ日が最も新しい勝利、それ以外は直近の勝利とする。期間内に予選の勝利が1つも無いプロダクトは、期間の絞り込みで一覧から除く。期間の開始日・終了日と同じローンチ日の勝利は期間内に含める(仮2)
- 並び順の「ローンチ日」「Upvote数」は基準勝利のローンチ日と基準勝利での自身のUpvote数を使う。値が同じ項目は基準勝利のローンチ日の新しい順、次にプロダクトの識別の順に並べ、同じ条件ではページをまたいで項目を重複・欠落させない(仮2)
- 予選の勝利には不戦勝と相手の退会等による勝利を含め、Week・Yearトーナメントの勝敗は掲載にも基準勝利にも使わない。予選の勝利が確定すると数分以内に一覧と検索の結果に載る

### ページネーション

- PCは「前へ」「次へ」と、先頭・末尾・現在ページの前後1つのページ番号を並べ、間を「…」で省略する(1ページ分しか空かない場合は省略せずその番号を出す)。モバイルは「前へ」「5 / 62」「次へ」とする
- ページを移動したら一覧の先頭へスクロールし、一覧の見出しへフォーカスを移す
- `page`クエリの範囲外は空状態「このページにはプロダクトがありません。」と全ページ数を示し、「1ページ目へ」の導線を添える

### ディレクトリの状態表示

[デザイン原則の状態表示](001-design-principles.md#状態表示)を、ディレクトリでは以下のように表す。

| 状態                   | 表現                                                                                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 初回ローディング       | 検索欄・期間・並び順はURLクエリから復元して通常表示し、カテゴリ欄はマスタ取得中として無効化する。件数・一覧・ページネーションは、ロゴ・名称・ボタンの形を保ったスケルトンにする                                            |
| 条件変更後の再読み込み | 検索欄・絞り込み欄は操作できる状態を保ち、直前の一覧を薄く残して操作を止め(`aria-busy`)、一覧の上端に進捗バーを出す。件数欄は「読み込み中…」とする                                                                         |
| 取得エラー             | 検索欄・絞り込み欄を残し、一覧の位置に再試行ボタンと問い合わせへの導線を表示する。技術的詳細は出さない                                                                                                                     |
| 0件(条件の指定中)      | 「条件に一致するプロダクトはありません。」と、指定中の条件(キーワード・カテゴリ・期間)ごとの解除・「条件をすべて解除」。指定中の条件が1つだけなら、その条件の解除だけを置く。解除は他の条件と並び順を保ち、1ページ目へ戻す |

| `page`クエリの範囲外   | 「このページにはプロダクトがありません。」と全ページ数、「1ページ目へ」([ページネーション](#ページネーション))                                                                                                             |
| メールアドレス未確認   | 共通ヘッダー直下に確認の帯を表示する。閲覧・検索は制限しない                                                                                                                                                               |

## プロダクト詳細(`/p/{handle}`)

表示項目はFR-DIR-004・FR-DIR-005・FR-COMNT-003〜004・FR-RATNG-001・FR-REPOT-001を正とする。PC(1024px以上)では本文とサイドバー(幅320〜352px、スクロールに追従)の2カラム、モバイルでは1カラムとし、サイドバーの内容はヘッダーの直後(開催中のマッチの前)に置く。ページ上部の区画は2カラムの上に全幅で置く。後続の機能(評価・コメント・トーナメント・スポンサー広告・通報)は、このページを書き換えずに区画を登録して加える([プロダクト詳細の区画の登録](#プロダクト詳細の区画の登録))。文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)・[操作とナビゲーションの名前](003-text-and-copy-rules.md#操作とナビゲーションの名前)を参照。

本文には上から順に以下を配置する。

1. 自動更新の切り替え(描く条件を満たす場合のみ、[プロダクト詳細の自動更新の切り替え](#プロダクト詳細の自動更新の切り替え))
2. パンくずリスト: ディレクトリ > カテゴリ > プロダクト名。カテゴリはそのカテゴリで絞り込んだディレクトリへのリンクにする
3. 未掲載の案内(投稿者本人が未掲載のプロダクトを閲覧する場合のみ): 「このページはあなたにだけ表示されています。」と、予選で勝利すると掲載される旨
4. ヘッダー: ロゴ(`square-md`)、カテゴリ、受賞回数、名称(ページの`h1`)、タグライン、投稿者(アバター・ニックネーム・ハンドル)とフォローボタン(本人には表示しない)、「リンクをコピー」、「サイトを開く」、初ローンチ日・ローンチ回数・通算成績(◯勝◯敗)
5. 開催中のマッチ(予選・トーナメントのマッチ中と結果の集計中のみ): トップページと同じマッチカードを置き、閲覧者を問わずその場でUpvoteできる。トップページの該当マッチと同じ演出・残り時間表示とする
6. トロフィー(受賞がある場合のみ): Product of the Yearを先頭に、Product of the Weekは受賞が新しい順にトロフィーを棚に並べ、受賞した週(表記は[表記規則](003-text-and-copy-rules.md#表記規則))または年と受賞日を添える
7. スクリーンショット(任意項目のため0枚なら区画ごと非表示): `screenshot-thumb`を高さを揃えて原本の縦横比のまま横スクロールで並べ、クリックで`screenshot-full`をライトボックス表示する。ライトボックスは前後移動ボタン・左右キー・スワイプで移動でき、「3 / 10」の位置を表示する。ライトボックスを閉じると、開いたスクリーンショットへフォーカスを戻す
8. 説明文(マークダウン描画): 高さ480pxを超える場合は折りたたみ、「続きを読む」で全文を表示する
9. マッチ履歴とコメント: ローンチ単位のブロックを新しいローンチから並べる(後述)
10. 通報リンク(ページ末尾、控えめだが見つけやすい位置。本人には表示しない)

サイドバーには以下を配置する。

- 投稿者本人向けの操作(本人のみ): 「あなたのプロダクト」として破線枠で区別し、進行状況・トーナメント参加費の決済・編集ボタン・再ローンチ予約ボタンをまとめる(後述)
- 5段階評価: 平均値と評価数、自身の評価入力(星5つ)と取り消し。評価が0件なら平均値の代わりに評価がまだ無いことを示す。本人には入力欄の代わりに自身のプロダクトは評価できない旨を示す(FR-RATNG-008)

サイドバーの区画がいずれも何も表示しない場合(本人以外の閲覧で他の区画が無いときなど)は、サイドバーの列を置かず本文を全幅にする。

- 初回の表示はサーバーで描画する。ページのタイトルは名称、説明はタグラインとし、正規のURLは現在のハンドルの`/p/{handle}`とする。投稿者本人に未掲載のプロダクトを表示する場合は、検索エンジンに載せない
- アニメーション演出は開催中のマッチに限り、それ以外は読み物として静止させる

### プロダクト詳細の区画の登録

後続の機能は、次の置き場所に順の値を付けて区画を登録する。プロダクト詳細の機能自身の区画(スクリーンショット・説明文・マッチ履歴とコメント・投稿者本人向けの操作)も同じ置き場所に登録し、後続の機能の順の値を空けておく。同じ置き場所の区画は順の値の小さい順に並べる。区画はそれぞれ自分でデータを取得し、該当しなければ何も表示しない。区画の取得や描画の失敗はその区画の位置だけに閉じ込め、他の区画とページの表示を止めない。何も表示しない区画は、枠と間隔を残さない。

| 置き場所             | 表示の位置                                                           | 登録する区画(順の値)                                                                                                                          |
| -------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| ページ上部           | 共通ヘッダーの下、本文とサイドバーの上(全幅)                         | Legendのスポンサー広告(スポンサー広告の機能)                                                                                                  |
| 本文                 | 開催中のマッチの下                                                   | トロフィー(10、トーナメントの機能)・スクリーンショット(20)・説明文(30)・マッチ履歴とコメント(40)                                              |
| サイドバー           | 本文の横(画面幅1024px未満はヘッダーの直後)                           | 投稿者本人向けの操作(10)・5段階評価(20、評価の機能)・Goldのスポンサー広告(30、スポンサー広告の機能)                                           |
| ページ末尾           | 本文の末尾                                                           | 通報(10、通報の機能)・Silverのスポンサー広告(20、スポンサー広告の機能)                                                                        |
| ローンチのブロック   | 各ブロックのマッチの一覧の下                                         | コメント(10、コメントの機能)                                                                                                                  |
| 投稿者本人向けの操作 | 投稿者本人向けの操作の進行状況の下、「編集」「再ローンチを予約」の上 | Weekトーナメント参加費の決済(10)・Yearトーナメント参加費の決済(20)(トーナメントの機能。[トーナメント参加費の導線](#トーナメント参加費の導線)) |

- 区画には、プロダクトの識別・ハンドル・名称・掲載中かどうか・投稿者のハンドルと、閲覧者がログインしているか・投稿者本人かどうかを渡す
- ページ上部・本文・サイドバー・ページ末尾の区画には、[自動更新の切り替え](#プロダクト詳細の自動更新の切り替え)の状態も渡す。区画は定期の取り直し・数値の毎秒の更新・演出を持つ間はその旨をページへ申告し、ページは切り替えを描くかどうかの判定に使う。区画が失敗して表示を止めた時とページから外れた時は、その区画の申告を取り消す
- ローンチのブロックの区画には、加えてローンチの識別・回・キックオフ済みかどうか・キックオフ済みで最も新しいローンチかどうかを渡す

### プロダクト詳細の自動更新の切り替え

開催中のマッチは定期的に取り直し、残り時間と演出を動かすため、[トップページの自動更新の切り替え](#自動更新の切り替え)と同じ切り替えをページ全体で1つ置く。

- 本文の先頭(ページ上部の区画の下、パンくずリストの前)に「自動更新」の切り替え(スイッチ)を置く。登録された区画とは別に描き、区画の失敗では消えない。ページを開くたびにオンから始める
- 切り替えは、開催中のマッチがある間、結果の反映を待つ状態(集計中のマッチがある・キックオフ済みのローンチの予選マッチがまだ作られていない・開始の時刻を過ぎてもマッチが始まっていない)の間、または区画が定期の取り直し・数値の毎秒の更新・演出を持つと申告している間に描く。どれにも当たらないときは描かない
- オンの間は、開催中のマッチと結果の反映を待つ状態の間、30秒ごとに開催中のマッチを取り直す。オフの間は、Upvote数の定期の取り直し、カウントダウンの毎秒の更新、対戦カードの演出を止め、カウントダウンは終了の時刻の表示だけを残す
- オフでも、開催中のマッチの終了の時刻と、予約済みのローンチの最も近いキックオフの時刻の1秒後の取り直しと、Upvoteなどの操作の後の更新は止めない。結果の反映を待つ状態の間は、オフでも、ページを表示した時点と最後の境界の取り直しのうち後の時点から取得が10回に達するまで30秒ごとに取り直し、10回に達しても状態が変わらなければ、開催中のマッチの区画の状態の文(支援技術へ伝える)をページを開き直す案内に切り替える
- マッチの結果が確定した、または開催中のマッチが無くなったら、ページ全体(マッチ履歴を含む)を取り直す
- ページの根の要素に切り替えの状態を`data-auto-refresh`の`"on"`・`"off"`で示し、演出は`"on"`の下の開催中のマッチだけで動かす。視差効果を減らす設定の閲覧者には、オンでも演出を動かさない

### 開催中のマッチの区画

- 開催中のマッチがある間だけ、見出し(「LIVE」の印と種別の印)、マッチ中なら閲覧者に応じた1行の説明、フルタイムまでのカウントダウン、マッチカードを置く。カウントダウンと結果の集計中・確定の表示はトップページと同じ文言とする
- 同じプロダクトの開催中のマッチが複数ある場合は、最も新しいマッチだけを置く
- 開催中のマッチがある間だけ、画面に表示しないbot判定をこの区画の中に置き、Upvote・取り消し・付け替えに添える。判定の失敗の文言はマッチカードの下に示す

### プロダクト詳細の状態表示

[デザイン原則の状態表示](001-design-principles.md#状態表示)を、プロダクト詳細では以下のように表す。

| 状態                             | 表現                                                                                                                        |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 初回ローディング                 | パンくずリスト・ヘッダー・本文・サイドバーの形を保ったスケルトン                                                            |
| 取得エラー                       | ページ全体を「プロダクト情報を読み込めませんでした。…」と再試行ボタン・問い合わせへの導線に置き換える。技術的詳細は出さない |
| 存在しない・閲覧できない         | [公開範囲](#プロダクト詳細の公開範囲)のとおり、存在しないページと同じ404(トップページとディレクトリへの導線)                |
| 開催中のマッチの取得エラー       | ページは表示を続け、開催中のマッチの区画の位置に失敗の文言と再試行ボタンを表示する                                          |
| 登録された区画のエラー           | その区画の位置だけに失敗の文言と再試行ボタンを表示し、他の区画の表示を続ける                                                |
| 投稿者本人向けの操作の照会の失敗 | 区画を表示したまま「再ローンチを予約」を無効にし、時間をおいて再度試す旨を示す                                              |

### マッチ履歴とコメントのローンチ単位ブロック

区画の見出しは「マッチ履歴とコメント」とし、ローンチ数と結果が確定したマッチ数を添える。この見出しのローンチ数は取り消されていない全てのローンチ(キックオフ前の予約を含む)を数え、ヘッダーのローンチ回数(キックオフ済みで取り消されていないローンチだけを数える)とは数える対象が違う。ディレクトリの一覧項目のコメント数のリンクは、この見出しへ移動する。非公開化・停止で取り消したローンチ(FR-ADMUG-010)はブロックを出さず、「第◯回」の回数にも数えない(回数は[ローンチ履歴](#ローンチ履歴)と同じ)。

各ブロックの見出しには「第◯回ローンチ」、ローンチ日、結果の要約(Product of the Week・ディレクトリ掲載・予選敗北・Week準々決勝敗退・キックオフ予定など)を表示する。結果の要約は後続の機能(トーナメント)が供給し、供給が無いローンチと供給に失敗したローンチは予選の結果から「キックオフ予定」「予選マッチ中」「ディレクトリ掲載」「予選敗北」を作る([ローンチ履歴](#ローンチ履歴)と同じ)。

- マッチは結果が確定したものだけを新しい順に常に表示する。各マッチには種別とラウンド(予選・Week 準決勝・Year 決勝など)、マッチ日、対戦相手、Upvote数の比率バー、「自分対相手」のスコア([表記規則](003-text-and-copy-rules.md#表記規則))、勝敗を表示する
  - 対戦相手の表示は[公開範囲仕様](#プロダクト詳細の公開範囲)に従い、「非公開のプロダクト」はロゴの代わりに汎用アイコンを表示する
  - 同数で最終Upvote時間により勝敗が決まったマッチは「接戦」として枠を強調し、最終Upvote時間により勝敗が決まった旨を添える
  - 対戦相手がいない不戦勝(FR-GAME-004等)はUpvote数と比率バーを出さず「対戦相手なし」「不戦勝」と表示する。マッチ直前の相手の退会等による不戦勝(FR-GAME-016等)は、対戦相手を「非公開のプロダクト」として同じく表示する
  - 早期勝敗決定による不戦勝(FR-GAME-015・FR-TOURW-019・FR-TOURY-022)は、対戦相手を「非公開のプロダクト」とし、確定時点の自身のUpvote数のみを添える(相手のUpvote数と比率バーは出さない)
  - 両者敗北は勝敗を「両者敗北」とする
  - 各マッチの「サポーター◯人」を押すと、このプロダクトにUpvoteしたユーザーの一覧(FR-DIR-005)をマッチの下に開く。高さを制限した枠内で20件ずつ無限スクロールし、退会・停止したユーザーは表示されない旨を添える(FR-DIR-014)。対戦相手側のサポーターは表示しない
  - サポーターの一覧の各行は、Upvoteした日時が早い順の番号、プロフィール画像、ニックネームを表示し、行全体を公開プロフィールへのリンクにする。続きの取得に失敗した場合は、取得済みの行を保ったまま失敗の文言と再試行ボタンを表示する
- コメントはローンチ毎に開閉でき、キックオフ済みで最も新しいローンチのみ既定で展開する。キックオフ前のローンチにはコメント欄を置かず、キックオフ後にコメントできるようになる旨を示す
- マッチ履歴が0件の場合(本人が予選前の未掲載プロダクトを閲覧する場合など)は、キックオフ日と当日はトップページで対戦が始まる旨を示し、本人には「リンクをコピーして応援を呼びかける」、他者にはトップページへの導線を添える
- キックオフ済みで予選マッチが開催中(マッチ中・結果の集計中)のため確定したマッチが無いブロックは、勝敗はフルタイム後に表示される旨と、[開催中のマッチの区画](#開催中のマッチの区画)へ移動する「マッチを見る」を示す
- ローンチ日・マッチ日・初ローンチ日・キックオフの日付は基準時刻の暦日のまま、閲覧者のタイムゾーンで日をずらさずに表示し、今年なら年を省く

#### サポーターの数

2026-10-24に開発者が確定した決定(directory-discoveryの仮5)である。「サポーター◯人」の数は、そのマッチのこのプロダクトの側の確定のUpvote数とする。一覧から除いた退会済み・停止中の利用者も数に含めるため、一覧の数と一致しないことがあり、一覧に除いた旨を添える。確定のUpvote数が0のマッチには「サポーター◯人」を出さない。

### コメント

- トップレベルのコメントは新しい順、返信は古い順に並べ、返信は3階層までインデントで表す(FR-COMNT-002)。「さらに読み込む」で次の10件を取得する(FR-COMNT-004)
- 投稿欄はマークダウンの書式ツールバー(見出しレベル1と画像を除く、FR-MDOWN-002)、「書く/プレビュー」の切り替え(FR-MDOWN-003)、文字数カウンターを持つ。ツールバーの項目は見出し・太字・斜体・リンク・箇条書き・番号付きリスト・引用・コード・コードブロック・表とする(文言は[操作とナビゲーションの名前](003-text-and-copy-rules.md#操作とナビゲーションの名前))。「書く」では、マークダウンの記号ではなく書式を適用した見た目のまま編集し、投稿する値はマークダウンの原文とする。トップレベルの投稿時には任意の5段階評価を添えられる(FR-RATNG-002、本人を除く)
- 未ログインの閲覧者には投稿欄の代わりにログインへの導線を、メールアドレス未確認のユーザーには確認が必要な旨と確認メールの再送導線を表示する(FR-USER-006)
- プロダクトの投稿者本人によるコメントには「投稿者」バッジを付ける。編集済みのコメントには「(編集済み)」を表示する
- 投稿日時は「3時間前」のような相対表現で表示し、ホバー・フォーカスで完全な日時を示す。30日以上前は日付で表示する
- 返信以外の操作は「…」メニューにまとめる。自身のコメントは編集(その場で投稿欄を開く)・削除(確認ダイアログを経る)、他者のコメントは通報とする(FR-REPOT-005)
- 退会・停止・本人削除・管理者による非公開化のいずれでも、置き換え表示は「このコメントは削除されました。」に統一し、アバター・名前・日時も表示しない。停止などの事情を推測させないためである。返信はそのまま残す(FR-COMNT-007)

### 投稿者本人向けの操作

投稿者本人には編集ボタンと再ローンチ予約ボタンを表示し、進行状況を見出しで示す。

- 区画の見出しは「あなたのプロダクト」とし、投稿者にのみ表示している旨の印を添える。進行状況は、取り消されていない直近のローンチの結果の要約([マッチ履歴とコメントのローンチ単位ブロック](#マッチ履歴とコメントのローンチ単位ブロック)の見出しと同じ文言)で示す
- 「編集」と「再ローンチを予約」はどちらも編集画面(`/my/products/{handle}/edit`)へ移す。予約と編集の可否は保存の時点の判定に委ね、この区画の表示だけに頼らない
- 予約の可否の照会に失敗した場合は、ページ全体を失敗させず、再ローンチ予約ボタンを無効にして時間をおいて再度試す旨を示す
- 再ローンチ予約ボタンを無効化するのは、次回ローンチの予約自体を禁止するFR-RELCH-004・FR-RELCH-006の間のみとし、理由を併記する。解禁日が確定している場合はその日付も併記し、FR-RELCH-004でトーナメントの参加資格を得る前は決済期限を解禁日として「参加しない場合は◯日に解除」と示す([再ローンチ規則](../overview/006-relaunch-rules.md#間隔制限の解釈)、文言は[エラーメッセージ](003-text-and-copy-rules.md#エラーメッセージ))
- 予選敗北後の間隔制限中(FR-RELCH-002・FR-RELCH-003)は選べるローンチ日が制約されるだけで予約自体はできるため、ボタンは有効のまま「このプロダクトは◯日以降のローンチ日を選べます。」を併記する
- マッチ直前・マッチ中は、編集画面でローンチ日・カテゴリの変更と削除ができない旨を添える(FR-PRDCT-014)
- トーナメント参加費の決済ボタンと決済期限は[トーナメント参加費の導線](#トーナメント参加費の導線)に従う

### メールアドレス未確認のユーザー

共通ヘッダーの直下に、確認が必要な操作(評価・コメント・フォロー・Upvote)と確認メールの再送導線を示す帯を表示する。各操作は無効化して理由を併記またはツールチップで示す。

### プロダクト詳細の公開範囲

投稿者本人が閲覧する場合を除き、ディレクトリに掲載されている(FR-DIR-001)プロダクト以外には404を返す。

上記を満たす場合でも、次のいずれかに該当するプロダクトには投稿者本人による閲覧を含め常に404を返す。

- 管理者が非公開化した(FR-ADMUG-009)
- 投稿者が退会済みまたは停止中である(FR-DIR-013と同じ判定)
- 投稿者が自分で論理削除した(FR-PRDCT-013)

404の画面は、存在しない・未掲載・閲覧不可のいずれの場合も同一とし、存在や非公開の理由を推測させない。

マッチ履歴の対戦相手が上記の常に404となるプロダクトである場合、または物理削除により紐付けを解除済み(FR-PRDCT-017)の場合は、名称を出さず「非公開のプロダクト」と表示する。それ以外で404となる(未掲載の)場合は、ロゴと名称を表示しリンクさせない。

## ユーザー公開プロフィール(`/@{handle}`)

表示項目はFR-UPROF-001・FR-UPROF-014・FR-FOLOW-005・FR-PRDCT-018〜019・FR-VOTE-011〜012を正とする。スポンサー広告は表示しない。PC(1024px以上)は左に人物情報のサイドバー(幅320〜352px、スクロールに追従しない)、右にタブの2カラムとし、モバイルは人物情報の下にタブを置く1カラムとする。

サイドバーには1枚のカードに上から順に以下を配置する。任意項目が未入力の区画は区画ごと表示しない。

1. 人物: アバター(96px、画面幅640px未満は80px。`square-md`)、ニックネーム(ページの`h1`)、ハンドル、ヘッドライン。アバターとニックネームは画面幅によらず横に並べる
2. フォロー: フォロワー数、受賞バッジ、フォローボタンと「…」メニュー
3. 自己紹介(マークダウン描画、画面に見えない見出し「自己紹介」を付ける): 高さ240pxを超える場合は折りたたみ、「続きを読む」で全文を表示する
4. 外部Webサイトリンク: 1件1行の縦リストで、名前と小さくホスト名を表示する。名前は任意入力のため、空ならホスト名を名前の位置に出す。`rel`は[外部Webサイトへのリンク](#外部webサイトへのリンク)に従う

右カラムにはタブ「ローンチ履歴」(FR-PRDCT-018)・「Upvote履歴」(FR-VOTE-011)を置く。アニメーション演出は使わず、読み物として静止させる。

### 区画の登録と登録が無いときの表示

後続の機能は次の箇所に区画を登録する。区画には、表示中の利用者のハンドル・ニックネーム・閲覧者が本人かどうか・停止中かどうかを渡す。

| 登録箇所            | 表示の位置                                                   | 登録が無いときの表示                                          |
| ------------------- | ------------------------------------------------------------ | ------------------------------------------------------------- |
| タブ                | 右カラム(モバイルは人物情報の下)。登録された順に件数を添える | 右カラムを出さず、人物情報だけを表示する                      |
| 受賞バッジ          | フォロワー数の下                                             | 区画を出さない                                                |
| 「…」メニューの項目 | フォローボタンの横                                           | 「…」ボタンを出さない。本人には項目が登録されていても出さない |

### 人物情報

- フォロワー数は「フォロワー」のラベルに続けて「12,345人」のように3桁区切りで省略せずに表示し、0人も同じ形とする。フォロー・フォロー解除はその場で数に反映する
- フォロー中・フォロワーの一覧は本人の設定ページ(`/settings/follows`)内でのみ閲覧できるため、本人のフォロワー数だけをそこへのリンクにする
- 受賞バッジは閲覧者に表示されるプロダクトの受賞を集計し、[ディレクトリの一覧項目](#一覧項目)と同じく賞の種類ごとに1つのゴールドのバッジ(Yearを先頭、複数回は「×4」)にまとめる。ツールチップには受賞したプロダクト名と週([表記規則](003-text-and-copy-rules.md#表記規則))・年を列挙する。各バッジはキーボードでフォーカスでき、ツールチップと同じ内容を読み上げ用の文言で示す。集計の対象は[ローンチ履歴](#ローンチ履歴)と同じプロダクトとする
  - 受賞が無い時・受賞の取得に失敗した時・読み込み中は区画を出さず、再試行の操作も置かない。人物情報の表示をずらしたり止めたりしないためである
- フォローボタンの位置には、本人には「プロフィールを編集」(`/settings/profile`)を置く(停止中の本人には置かない)。未ログインの閲覧者にはログインへの導線を、メールアドレス未確認のユーザーには無効化して理由を示す
- 「…」メニューには「このユーザーを通報」を置く。ログイン状態を問わず通報でき(FR-REPOT-001)、本人には表示しない(FR-REPOT-005)
- Ultrasの特典を提供している間([状態ごとの特典の適用](../overview/002-pricing-and-plans.md#状態ごとの特典の適用)の「適用する」状態)は、アバターをプライマリ色の輪で縁取る(FR-UPROF-014)。色だけに頼らないよう、ツールチップと読み上げ用の文言で加入中であることを示す。本人による表示・非表示の切り替えは設けない
- 必須項目(ニックネーム・ハンドル)のみの本人には、自己紹介の位置に未入力の項目(プロフィール画像・ヘッドライン・自己紹介・外部Webサイト)を挙げた破線枠と「プロフィールを設定」ボタンを置く

### タブ

- 下線型のタブに件数を添え、共通ヘッダーの直下に追従させる。タブバーが追従している状態で切り替えた場合は、切り替えた内容を先頭から読めるようタブの位置までスクロールを戻す
- 選択中のタブはURLクエリ`tab`に保持し、共有やブラウザの戻る・進むで復元する。登録された順序が最小のタブ(「ローンチ履歴」の`launches`)は既定としてURLから省略し、登録されていない値は既定のタブとして扱う。「Upvote履歴」の値は`upvotes`
- 各タブの一覧は「さらに読み込む」ボタンで20件ずつ取得する(カーソルベースページネーション)。無限スクロールにしないのは、一覧の下にあるフッターへ到達できるようにするためである

### ローンチ履歴

プロダクト単位の項目を、最新ローンチ日が新しい順(キックオフ予定・マッチ中のプロダクトが先頭)に並べる。並び替えの操作は設けない。

- 項目: ロゴ(`square-sm`)、受賞バッジ、名称、タグライン(2行で省略)、カテゴリ(他の条件なしでディレクトリを絞り込む)、「サイトを開く」、本人には「編集」。名称のリンクを項目全体に広げ、プロダクト詳細へ遷移させる
- ローンチ履歴: 「第◯回」・ローンチ日・結果の要約([プロダクト詳細のローンチ単位ブロック](#マッチ履歴とコメントのローンチ単位ブロック)の見出しと同じ文言)を新しい順に3件まで表示し、残りは「他◯回を表示」で開く
  - マッチ中は「予選マッチ中」「Week準決勝マッチ中」と、トップページへの「トップページで見る」を添える
  - キックオフ予定はユーザーのタイムゾーンでのキックオフ日時と相対表現(「あと2日」)を添える
  - 非公開化・停止で取り消したローンチ(FR-ADMUG-010)は表示せず、「第◯回」の回数にも数えない。回数は取消を除いたローンチをローンチ日の古い順に1から数える
  - 結果の要約は後続の機能(トーナメント)が供給する。供給が無いローンチは予選の結果から「キックオフ予定」「予選マッチ中」「ディレクトリ掲載」「予選敗北」を作る
- 本人にだけ表示する未掲載のプロダクト(FR-PRDCT-018)には「未掲載・あなたにだけ表示」のバッジを付け、一覧の上に[案内文](003-text-and-copy-rules.md#状態案内の文言)を1行置く
- 0件は事実だけを示し、本人には次の行動の説明と「新しいプロダクトを登録」(`/my/products/new`)の導線を添える。最初の取得の失敗はタブの内容の位置に失敗の文言と再試行ボタンを、続きの取得の失敗は「さらに読み込む」の上に失敗の文言を示し、同じボタンで読み込み直す(文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言))

### Upvote履歴

マッチ日ごとの小見出し(「2026年10月2日(金)」と件数)にまとめ、新しい順に並べる。誰でも閲覧できる公開情報のため、生活時間帯を推測させるUpvoteの時刻は表示しない。

- 小見出しの件数は、読み込み済みの項目の数ではなく、その日のUpvoteの総数(FR-VOTE-012で除外したプロダクトへのUpvoteを除く)を示す。「さらに読み込む」で同じ日の続きを読み込んでも件数は変わらない。タブに添える件数も、除外を除いたUpvoteの総数とする
- 0件の本人には、トップページの開催中のマッチへの導線を添える

- 項目: Upvoteしたプロダクトのロゴ・名称、投稿者(アバター・ニックネーム、投稿者の公開プロフィールへ遷移)、マッチの種別とラウンド(予選・Week 準決勝など)。勝敗やスコアは表示しない
- ディレクトリに掲載されているプロダクトは名称からプロダクト詳細へ遷移する。予選で敗北した、または初めての予選マッチ中の未掲載のプロダクトはロゴと名称を表示してリンクせず、「未掲載」の小さなバッジを付ける
- 開催中のマッチへのUpvoteには「マッチ中」と「トップページで見る」を添える。Upvoteの取り消しはマッチカードの操作に一本化し、ここには置かない
- FR-VOTE-012で除外したプロダクトがあることを、一覧の上に「公開を停止・削除されたプロダクトは表示されません。」と注記する

### ユーザー公開プロフィールの状態表示

[デザイン原則の状態表示](001-design-principles.md#状態表示)を、ユーザー公開プロフィールでは以下のように表す。文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)を参照。

| 状態                     | 表現                                                                                                     |
| ------------------------ | -------------------------------------------------------------------------------------------------------- |
| 初回ローディング         | 人物情報(アバター・ニックネーム・フォローボタン)・タブ・一覧項目の形を保ったスケルトン                   |
| タブ切り替え後の読み込み | 人物情報を保ったまま、タブの内容部分のみスケルトンにする                                                 |
| 取得エラー               | ページ全体を再試行ボタンと問い合わせへの導線に置き換える。技術的詳細は出さない                           |
| タブの内容の取得エラー   | 人物情報を保ったまま、タブ内に再試行ボタンを表示する                                                     |
| 続きの取得エラー         | 表示済みの項目を保ったまま、一覧の末尾に再試行ボタンを表示する                                           |
| 0件                      | 事実のみを示す。本人には次の行動の説明と、ローンチ予約またはトップページの開催中のマッチへの導線を添える |
| メールアドレス未確認     | 共通ヘッダー直下に確認の帯を表示し、フォローボタンを無効化する                                           |

### ユーザー公開プロフィールの公開範囲

退会済み・存在しないハンドルは、閲覧者を問わず[プロダクト詳細](#プロダクト詳細の公開範囲)と同一の404を表示する。

管理者により停止されたユーザーの公開プロフィールは、ログインユーザー自身のプロフィールである場合を除き404を返す。本人には以下のように表示する。

- ページ上部に停止中である旨と問い合わせへの導線を示す帯を表示する
- 書き込みは拒否される(FR-USER-026)ため、「プロフィールを編集」・プロフィール設定・ローンチ予約・Upvoteへの導線を出さない
- プロダクト詳細は本人にも404となるため、ローンチしたプロダクトは「非公開」のバッジを付けて薄く表示し、リンクと「サイトを開く」「編集」を出さない
- プロフィール画像とロゴは隔離される(FR-ADMUG-048)ため、頭文字のプレースホルダーを表示する

## 認証(`/auth/*`)

| パス                            | ページ                     | 備考                                                                                                                                                                                                                 |
| ------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/auth/register`                | ユーザー登録               | ニックネーム・メールアドレス・パスワードと、利用規約・プライバシーポリシーへの同意と18歳以上であることの表明                                                                                                         |
| `/auth/login`                   | ログイン                   | クエリ`redirect`: ログインの後の戻り先(同じオリジンのパスだけを受け付け、それ以外はトップページへ戻る)。多要素認証を有効にした利用者には、同じページでパスワードの後に認証コード(またはリカバリコード)の入力を求める |
| `/auth/password-reset`          | パスワードの再設定の要求   | メールアドレスの登録の有無によらず同じ案内を表示する(NFR-SECUR-043)                                                                                                                                                  |
| `/auth/verify-email`            | メールアドレスの確認       | メールのリンクから開く。検索エンジンに載せない                                                                                                                                                                       |
| `/auth/password-reset/confirm`  | 新しいパスワードの設定     | 同上                                                                                                                                                                                                                 |
| `/auth/email-change/confirm`    | メールアドレスの変更の確定 | 同上                                                                                                                                                                                                                 |
| `/auth/password-change/confirm` | パスワードの変更の確定     | 同上                                                                                                                                                                                                                 |

- どのページも、共通レイアウトの本文の中央に、ページの題名と白い面(カード)に載せたフォームを幅を絞って置く
- メールのリンクから開くページは、トークンをURLのフラグメント(`#token=`)で受け取り、読み取った直後にアドレスバーのURLから消す。開いただけでは確定せず、ボタンを押して確定する(メールの安全確認などがリンクを先に開いてもトークンを使い切らせないため)。リンクが無効か期限切れなら、その旨と次の操作(確認メールの再送、アカウントの設定ページ、パスワードの再設定)への導線を表示する
- ログイン必須のページ(`/settings/*`など)を未ログインで開くと、開こうとしたページを戻り先にしてログインページへ移す
- 登録・ログイン・パスワードの再設定の要求のフォームと、設定ページのメールアドレス変更・パスワード変更・退会の操作は、画面に表示しないbot判定の結果を添えて送る(FR-USER-012)

| パス                      | 内容                                                                                                  | 対応要件                              |
| ------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------- |

### 設定ページのシェル

- 全ての設定ページは、設定の項目のナビゲーション(名前「設定」)と、ページの題名と内容を並べた共通の枠に表示する。幅1024px以上ではナビゲーションを左の列(幅13rem)に縦に並べ、それより狭い画面では内容の上に横に並べて折り返す。表示中の項目は強調し、支援技術には現在のページとして伝える
- ナビゲーションの項目は上の表の順(プロフィール・アカウント・セキュリティ・通知・フォロー・プラン・決済履歴・スポンサー広告・APIキー・データエクスポート)に並べる。項目は各ページを実装した時点で加え、未実装のページの項目は出さない
- `/settings`を開くと、ナビゲーションの最初の項目のページ(プロフィール編集の`/settings/profile`)へ移す
- アカウントの設定ページ(`/settings/account`)は、メールアドレスの変更・パスワードの変更・退会の区画を順に並べる。セキュリティの設定ページ(`/settings/security`)は、ログイン中の端末・多要素認証・リカバリコード(多要素認証が有効な時だけ)の区画を順に並べる
- メールアドレス変更・パスワード変更・退会は、送信の前に本人確認として現在のパスワード(多要素認証が有効なら加えて認証コードかリカバリコード)の入力を求める。退会は、取り消せないことなど退会の結果を示した確認のダイアログで本人確認の入力を受け付ける

### プロフィール編集(`/settings/profile`)

題名「プロフィール」の下に、ログイン中の利用者の公開プロフィールの欄を次の順に並べ、最後に保存を置く。未ログインの場合はログインへ誘導する。

1. プロフィール画像: 現在の画像と「画像を削除」。クリックまたはドラッグ&ドロップで選び、SVG以外は正方形の切り取りとリサイズの編集を経てアップロードする
2. ニックネーム(必須)
3. ハンドル(必須): `@`の接頭辞付きの欄。フォーカスを外すと形式と使用可否を確かめ、使えない場合はその場で理由を示す。保持中の旧ハンドルがあれば、欄の下に[旧ハンドルの保持とリダイレクト](#旧ハンドルの保持とリダイレクト)の案内を示す
4. ヘッドライン
5. 自己紹介: 書式のツールバー・「書く」と「プレビュー」の切り替え・文字数のカウンターを持つマークダウンの入力欄
6. 外部Webサイト: 行ごとに名前(任意)とURL、行の「削除」。「外部Webサイトを追加」は10件に達すると無効にする
7. 保存

- 各欄はフォーカスを外した時に検証し、違反の文言をその欄の近くに示す([エラーメッセージ](003-text-and-copy-rules.md#エラーメッセージ))
- 保存は、画面に表示しないbot判定の結果を添えて送る(FR-USER-012)。保存に成功すると「プロフィールを保存しました。」をトーストで示し、「公開プロフィールを見る」の導線を出す。ヘッダーのユーザーメニューの公開プロフィールへのリンクも新しいハンドルに更新する
- 画面を開いた後に別の画面でハンドルが変わっていた場合は保存せず、最新の内容を読み込んでから保存するよう示す
- メールアドレスの確認が済んでいない利用者も編集できる
- 停止中の利用者は全欄と保存を無効にし、題名の直下に「このアカウントは停止されているため、プロフィールは変更できません。」を表示する

### フォロー一覧(`/settings/follows`)

題名「フォロー」の下に、「フォロー中」「フォロワー」のタブと一覧を置く。一覧は本人にだけ提供し、他の利用者の一覧を見る手段は設けない。

- 選択中のタブはURLクエリ`tab`(`followers`。既定の「フォロー中」は省略)に保持し、共有やブラウザの戻る・進むで復元する
- 各一覧は、フォローした(された)日時の新しい順に20件ずつ表示し、「さらに読み込む」で続きを取得する
- 各項目は、利用者のプロフィール画像・ニックネーム・`@`付きのハンドル・フォローした日時を表示し、項目全体を公開プロフィールへのリンクにする
- 退会済み・停止中の利用者は一覧から除く。除かれた利用者がいても、ページの件数と続きの有無は正しく示す
- 0件の表示は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)による
- 読み込み中はスケルトン、最初の取得の失敗は題名とタブを残したまま一覧の位置に失敗の文言と再試行ボタンを表示する。再試行を押すと題名へフォーカスを移す
- 続きの取得の失敗は、読み込んだ項目と「さらに読み込む」を残したまま、ボタンの上に失敗の文言を示し、同じボタンで読み込み直す。再試行ボタンは置かず、失敗でフォーカスを動かさない。失敗の文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)の「フォロー一覧の取得エラー」による
- 未ログインの閲覧者はログインへ誘導する

### プラン管理画面(`/settings/plan`)

題名「プラン」の下に、ログイン中の利用者のUltrasの加入状態の区画と、Customer Portalを開く「解約・支払い方法の管理」ボタンを置く。検索エンジンに載せない。加入状態と特典の適用は[料金とプラン](../overview/002-pricing-and-plans.md#状態ごとの特典の適用)を、文言は[Ultrasの画面の文言](003-text-and-copy-rules.md#ultrasの画面の文言)を正とする。

- 支払い方法の更新・課金期間の末日に終わる解約・解約の取り消しは、すべてStripe Customer Portalで行う(FR-PPLAN-003・FR-PPLAN-010)。画面にはこれらの操作のフォームを置かず、加入状態の表示と「解約・支払い方法の管理」ボタンだけを置く。Customer Portalではプランの変更と請求書の履歴を使えないようにし、決済履歴は本サイト内の[決済履歴](#決済履歴settingsbilling)で扱う
- 加入状態ごとに次を表示する。日時は閲覧者のタイムゾーンで表示する(I18N-004)

| 加入状態                          | 表示                                                                                                                                                                                                                                                                                           |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `active`(有効)                    | 加入中である旨、加入の開始日時、次回の更新日時、特典の一覧                                                                                                                                                                                                                                     |
| `past_due`(支払いの再試行中)      | 支払いに失敗し再試行中である旨、特典は継続している旨、再試行がすべて失敗すると特典が終了する旨、支払い方法の更新を促す案内                                                                                                                                                                     |
| `canceled`(解約済み)              | 解約済みである旨、解約の操作の日時、特典の終了日時、それまで特典が続く旨、Customer Portalで解約を取り消せる旨                                                                                                                                                                                  |
| `ended`(終了)・加入したことが無い | 未加入である旨。機能フラグ(FR-ADMCF-022)がオンなら、加入ボタンの上に料金ページと同じ価格の行(月額の価格。照会できなければ「現在表示できません」を示し、加入ボタンを無効にする理由として結び付ける)と「Ultrasに加入」ボタン(押した後は料金ページと同じ)、オフなら新規の加入を受け付けていない旨 |

- 「解約・支払い方法の管理」ボタンは、加入したことがある(Stripe Customerと加入を持つ)利用者にだけ表示する。押すとCustomer Portalのセッションを作ってCustomer Portalへ移り、戻り先は`/settings/plan?portal=returned`とする。停止中・加入したことが無い利用者の拒否と、1時間に20回を超えた拒否は、ボタンの近くに文言を示す。決済サービスの障害の間は、[決済の縮退の表示](#決済の縮退の表示)と同じ注記の枠(題名「現在ご利用いただけません。」とCustomer Portalを現在利用できない理由)をボタンの近くに表示する
- Customer Portalから戻った直後(クエリ`portal=returned`)は、Portalでの操作がWebhook(FR-PPLAN-011)で反映されるまでに間があるため、反映を待っている旨を状態の文(支援技術へ伝える)で表示し、加入状態の照会だけを5秒ごとに最大12回取り直す。反映が済んだかどうかは判定しない(Portalで何も変えずに戻った場合と区別できないため)。12回を終えたら、同じ状態の文を、反映に時間がかかっているためしばらくしてからこのページを開き直す案内に切り替える。「自動更新」のスイッチは置かない
- 読み込み中はスケルトン、取得の失敗は題名を残したまま再試行ボタンと問い合わせへの導線を表示する。再試行を押すと題名へフォーカスを移す

### 決済履歴(`/settings/billing`)

題名「決済履歴」の下に、ログイン中の利用者の決済履歴の一覧を置き、prod以外の環境では末尾に決済の疎通確認の区画を置く。検索エンジンに載せない。記録の規則は[決済実装方針の決済履歴の記録の規則](../features/004-payments.md#決済履歴の記録の規則)を正とする。

- 一覧は発生日時の新しい順に20件ずつ並べる(FR-PYMNT-005)。各記録は、購入種別の名前を見出しにし、日時(年を含む)・種類(都度決済・定期課金の請求・返金・チャージバック)・数量(数量のある記録だけ)・金額(税込)・状態を示す。金額は返金と引き落としを負、チャージバックで戻った額を正の符号付きで示す
- 続きがある間は一覧の下に「さらに表示」を置き、押すと古い記録を一覧の後ろに加え、加えた最初の記録へフォーカスを移す。読み込み中はボタンの文言を「読み込み中」にする。続きの取得の失敗はボタンの上に失敗の文言を示し、ボタンを残す
- 0件の時は決済履歴が無い旨を表示する
- 読み込み中はスケルトン、最初の取得の失敗は一覧の位置に再試行ボタンを表示する。再試行を押すと題名へフォーカスを移す
- 決済の疎通確認の区画(dev・stagingだけ)は、区画の見出し「決済の疎通確認」、1ドルの疎通確認用の購入を作って決済画面へ進む旨と権利は付与されない旨の説明、「疎通確認の決済を始める」ボタンを置く。押すと購入を作って決済画面(`/checkout/{購入ID}`)へ移り、失敗はボタンの下に失敗の文言を示す。prodでは区画を表示せず、APIサーバーも疎通確認の購入を拒否する

### 停止中の設定ページ

停止中のユーザーはログインできないが、停止の前からのセッションでは設定ページを開ける(FR-USER-026・FR-USER-027)。

- アカウントの設定ページでは退会だけを操作でき、メールアドレスの変更とパスワードの変更の入力と送信を無効にする
- セキュリティの設定ページでは、他の端末のログアウトだけを操作でき、多要素認証の設定とリカバリコードの再発行を無効にする
- どちらのページも題名の直下に停止中である旨の案内を表示し、行えない操作と行える操作に続けて、ログアウトした後やセッションが切れた後は問い合わせから退会を依頼できる旨と問い合わせへのリンクを示す(文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言))
- プロフィール編集では、全欄と保存を無効にする(表示する文言は[プロフィール編集](#プロフィール編集settingsprofile))
- フォロー一覧は閲覧だけの画面のため、停止中でも一覧を表示する

## 自分のプロダクト(`/my/products`)

ログイン中の利用者が、自分のプロダクトの直近のローンチの状態と次にできることを確かめるページ。共通ヘッダーの「ローンチする」は登録画面へ、ユーザーメニューの「自身のプロダクト」はこのページへ移す。未ログインで開くと、このページを戻り先にしてログインページへ移す。文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)と[操作とナビゲーションの名前](003-text-and-copy-rules.md#操作とナビゲーションの名前)を参照。

上から順に以下を配置する。

1. 見出し: ページの`h1`「自分のプロダクト」と1行の説明文。右上に主要ボタン「新しいプロダクトを登録」(`/my/products/new`)
2. 停止中の案内(停止中の利用者のみ): 停止中のため登録・変更できない旨と問い合わせへの導線
3. 一覧: 論理削除していない自分のプロダクトを、直近のローンチ日が新しい順に20件ずつカードで並べ、「さらに読み込む」で続きを後ろに加える。非公開化中のプロダクトも含める

### 一覧のカード

- 左にロゴ(`square-sm`。未設定・隔離中・読み込みの失敗では名称の頭文字のプレースホルダー)、右に名称・ハンドル(`@`なし)・カテゴリのバッジを置く。非公開化中は「公開停止中」のバッジを付ける
- 直近のローンチ(取消を除いてローンチ日が最も新しいもの)の状態と、次回のローンチの予約の可否を並べる(次の2つの表)。日時は`<time datetime>`で出力し、閲覧者のタイムゾーンで表示する
- 操作は「編集」(編集画面へ)と「詳細を見る」(プロダクト詳細へ。本人には未掲載でも開ける)を置く。非公開化中はプロダクト詳細が本人にも404となるため「詳細を見る」を出さない
- カードの下に、後続の機能が登録した区画([自分のプロダクトの区画の登録](#自分のプロダクトの区画の登録))を登録の順に並べる
- 幅640px以上はロゴ・情報・操作を横に並べ、640px未満は縦に積む

| 直近のローンチの状態                     | 表示                                                                                                 |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 予定・ペアリング済み                     | 「キックオフ予定」と、キックオフ(ローンチ日の0:00)の日時と相対表現(「あと2日」)                      |
| マッチ中                                 | 「予選マッチ中」と、トップページへの「トップページで見る」                                           |
| 終了                                     | 予選の結果の「ディレクトリ掲載」(勝利、不戦勝を含む)または「予選敗北」(両者敗北を含む)と、ローンチ日 |
| ローンチが無い(取消のローンチだけを含む) | ローンチの状態は出さない(次回のローンチの予約の案内だけを出す)                                       |

| 次回のローンチの予約                                      | 表示                                                                                                                              |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 予約できる(直近のローンチが終了、またはローンチが無い)    | 選べる最も早い日の案内と、編集画面への「次回のローンチを予約」                                                                    |
| 予定のローンチのローンチ日を変更できる                    | ローンチ日は編集画面で変更できる旨                                                                                                |
| 予約できない(FR-RELCH-004・006、非公開化中(FR-PRDCT-026)) | 理由の文言と、解除の日時が決まっていればその日時([エラーメッセージ](003-text-and-copy-rules.md#エラーメッセージ)の再ローンチ不可) |
| 判定に失敗した                                            | ローンチの状態を確認できなかった旨                                                                                                |
| マッチ直前・マッチ中の固定の期間(FR-PRDCT-014)            | ローンチ日・カテゴリの変更と削除ができない旨(予約の可否の案内に加えて示す)                                                        |

- 表示中にキックオフ(ローンチ日の0:00)を迎えたカードは、その時刻に状態を取り直して「予選マッチ中」に切り替える。自動更新のスイッチは置かない
- 0件は「まだプロダクトはありません。」と、ローンチ日に予選マッチで1対1の対戦が始まり勝利するとディレクトリに掲載される旨、登録への導線を示す
- 初回ローディングはカードの形を保ったスケルトンにする。最初の取得の失敗は見出しを残したまま一覧の位置に失敗の文言・再試行ボタン・問い合わせへの導線を、続きの取得の失敗は読み込んだカードと「さらに読み込む」を残したままボタンの上に失敗の文言を示し、同じボタンで読み込み直す
- 停止中の利用者には、一覧を表示したまま「新しいプロダクトを登録」と各カードの「編集」を無効にし、編集画面へ移す「次回のローンチを予約」を出さない(FR-USER-026)

### 自分のプロダクトの区画の登録

後続の機能は次の箇所に区画を登録する。区画はそれぞれ自分でデータを取得し、該当しなければ何も表示しない。1つの区画の取得や描画の失敗はその区画の位置だけに示し、他の区画とカードの表示を止めない。登録が無い間は何も表示しない。

| 登録箇所               | 表示の位置                                     | 区画に渡す情報                                                         | 登録する機能の例                                                              |
| ---------------------- | ---------------------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 自分のプロダクトの区画 | 一覧の各カードの下と、編集画面の状態の区画の中 | プロダクトのハンドル・名称・非公開化中かどうか・表示の位置(一覧・編集) | Week・Yearトーナメント([トーナメント参加費の導線](#トーナメント参加費の導線)) |
| 削除の確認の注意書き   | 削除の確認のダイアログの本文の下               | プロダクトのハンドル                                                   | Week・Yearトーナメント(参加資格の喪失と返金)・スポンサー広告                  |

| ---------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/my/products/new`           | 登録画面 | ページのタイトル「プロダクトを登録」                                                                                                                                                    |
| `/my/products/{handle}/edit` | 編集画面 | ページのタイトル「<名称>を編集」。他の利用者のもの・論理削除済み・存在しないハンドルは存在しないページと同じ404。自分のプロダクトの旧ハンドルは現在のハンドルの編集画面のURLへ302で移す |

どちらも未ログインで開くと、開こうとしたページを戻り先にしてログインページへ移す。

### フォームの区画の並び

1カラム(最大幅768px)で、見出し付きの区画を上から次の順に置き、末尾に送信ボタン(登録は「ローンチを予約🚀」、編集は「変更を保存」)を置く。

1. 基本情報: ロゴ・名称・タグライン・カテゴリ・ハンドル・外部WebサイトURL
2. 説明文: 書式のツールバー・「書く」と「プレビュー」の切り替え・文字数のカウンターを持つマークダウンの入力欄(FR-MDOWN-001〜003)。プレビューはプロダクト詳細と同じ描画とする
3. スクリーンショット(任意)
4. ローンチ日: カレンダー([ローンチ日の欄](#ローンチ日の欄))

- 各欄はフォーカスアウト時(UI-005)に検証し、違反の文言をその欄の近くに示す([エラーメッセージ](003-text-and-copy-rules.md#エラーメッセージ))。サーバーが返した欄ごとの違反も同じ位置に示し、欄に対応しない失敗はフォーム全体の失敗として送信ボタンの近くに示す
- ハンドル: `/p/`の接頭辞付きの欄。フォーカスを外すと形式と使用可否を確かめ、使えない場合はその場で理由を示す。編集中のプロダクトの現在のハンドルと保持中の旧ハンドルは使えるものとして扱う。保持中の旧ハンドルがあれば、欄の下に、次にハンドルを変更するか他のプロダクトが同じハンドルを設定するまで以前のURLが新しいURLへ転送される旨を示す
- カテゴリ: プロダクトカテゴリのマスタの追加の順に並べ、標準カテゴリ「その他」を末尾に置いたセレクト
- 画像は選択後に編集ダイアログ(FR-FILEU-003)を経てアップロードする。SVGは編集ダイアログを省略する。ロゴは正方形に切り取り、現在のロゴと「ロゴを差し替え」を示す。スクリーンショットは自由な比率で切り取り、選んだ順に並べて各画像に「取り除く」を置き、枚数と合計の容量(「3/20枚・2.1MB/10MB」)を示す。形式・1枚・枚数・合計の上限の違反は送信の前にその欄に示す
- 送信は、画面に表示しないbot判定の結果を添えて送る(FR-PRDCT-016)。bot判定の枠と場所は設けず、判定の失敗の文言だけを示す

### ローンチ日の欄

- 月ごとのカレンダーで選ぶ。フォームの中に直接描き、ポップオーバーでは開かない。選べる範囲(最も早い日と最も遅い日)と選べない日はサーバーから受け取る
- 選べない日はグレーアウトし、選べないがフォーカスはできる日として、理由をツールチップと読み上げ用の文言で示す。理由はペアリングの締め切り(FR-PRDCT-002)・敗北後の間隔(FR-RELCH-002・003)・選べる期間の外(今日から90日後より後、FR-PRDCT-003)の3つとする
- 日を選ぶと、キックオフ(ローンチ日の0:00)の日時を閲覧者のタイムゾーンで`<time datetime>`により示し、相対表現(「あと2日」)を添える。ローンチ日そのものは基準時刻の暦日のまま表示し、閲覧者のタイムゾーンで日をずらさない
- 敗北後の間隔が掛かっていてUltrasの特典を受けていない投稿者には、カレンダーの下にUltrasなら敗北後2日で再ローンチできる旨と料金ページへのリンクを添える。表示は機能フラグ(FR-ADMCF-022)に従う
- 表示中に23:40を過ぎると、その時刻に選べる日を取り直す。自動更新のスイッチは置かない
- 登録ではローンチ日を必須とし、登録と同時に最初のローンチを予約する

### 登録画面(`/my/products/new`)

- メールアドレスの確認が済んでいない利用者には、題名の下に確認が必要な旨と確認メールの再送の導線を示し、全欄と送信ボタンを無効にする(FR-USER-006)
- 停止中の利用者には、題名の下に[自分のプロダクト](#自分のプロダクトmyproducts)と同じ停止中の案内(問い合わせへの導線)を示し、全欄と送信ボタンを無効にする(FR-USER-026)。停止中でメールアドレスの確認も済んでいない利用者には停止中の案内だけを示す
- 登録に成功すると、登録した旨とキックオフの日時をトーストで示し、[自分のプロダクト](#自分のプロダクトmyproducts)へ移す

### 編集画面(`/my/products/{handle}/edit`)

上から状態の区画、フォーム、「危険な操作」の区画の順に置く。

- 状態の区画: 直近のローンチの状態と次回のローンチの予約の可否([一覧のカード](#一覧のカード)と同じ表示。ただし予定のローンチのローンチ日を変更できる旨はローンチ日の欄で変更するため示さない)、マッチ直前・マッチ中の固定の案内、非公開化中の案内と問い合わせへの導線、[自分のプロダクトの区画](#自分のプロダクトの区画の登録)
- ローンチ日の欄は次回のローンチの予約の可否で変える
  - 予定のローンチのローンチ日を変更できる: 現在のローンチ日を選んだ状態のカレンダーを示し、別の日へ変更できる
  - 予約できる: 「次回のローンチを予約」の欄としてカレンダーを示す。日を選ばずに保存すると予約しない
  - 予約できない・判定に失敗した・マッチ直前・マッチ中の固定の期間: カレンダーを出さず、状態の区画と同じ案内を示す
- 予約済みのローンチの取りやめ(ローンチ日を空に戻す操作)は設けない。投稿者が行えるのはローンチ日の変更とプロダクトの削除だけである
- 保存に成功すると、保存した旨(次回のローンチを予約した場合はその旨)をトーストで示す。ハンドルを変えた場合は、新しいハンドルの編集画面のURLへ履歴を置き換えて移す
- 画面を開いた後に別の画面でプロダクトが変更されていた場合は保存せず、最新の内容を読み込んでから操作するよう示し、送信ボタンの近くに「最新の内容を読み込む」を置く。押すと最新の内容でフォームを作り直し、入力中の内容は捨てる。状態の区画は失敗の時点で最新に取り直す。選んだローンチ日が選べなくなっていた場合は、選べる最も早い日をローンチ日の欄に示し、選べる日を取り直す
- 表示中の取り直しで、別の画面でハンドルが変わっていれば新しいハンドルの編集画面へ、削除されていれば[自分のプロダクト](#自分のプロダクトmyproducts)へ移す
- メールアドレスの確認が済んでいない利用者も、既存のプロダクトの編集と削除はできる。停止中の利用者は保存と削除を拒否される(FR-USER-026)

#### 非公開化中の編集

管理者が非公開化(FR-ADMUG-009)している間も、投稿者は内容の編集と削除を行える(FR-PRDCT-025)。投稿者が問題を直して運営へ復元を依頼できるようにするためである。

- 状態の区画に、公開が停止されている旨と、内容を直したら問い合わせから確認を依頼する旨、問い合わせへの導線を示す
- 次回のローンチは予約できない(FR-PRDCT-026)。ローンチ日の欄はカレンダーを出さず、予約できない理由を示す。非公開化の時点で未開始だったローンチは取り消されている(FR-ADMUG-010)
- 一覧のカードには「公開停止中」のバッジを付け、「詳細を見る」を出さない

#### マッチ直前・マッチ中の固定

- マッチ直前・マッチ中は、ローンチ日・カテゴリの編集欄と削除ボタンを無効化し、理由を表示する(FR-PRDCT-014)。予選ではペアリング後から、トーナメントでは組み合わせ決定後または前ラウンド勝利後から、マッチ終了までが該当する
- 固定の期間もローンチ日・カテゴリ以外の欄は編集して保存できる。カテゴリの欄は入力要素ごと無効にし、理由を欄に結び付ける
- 表示中にペアリング(ローンチ日の前日23:45)を迎えると、その時刻に状態を取り直して固定の表示に切り替える。削除ボタンにフォーカスがある間は押せない状態だけを示してフォーカスを保ち、フォーカスが離れてから無効にする
- 予選勝利後〜Weekトーナメントの組み合わせ決定前、及びWeek優勝後〜Yearトーナメントの組み合わせ決定前は削除できる。削除、または退会によるプロダクトの論理削除(FR-PRDCT-015)の時点で参加資格を得ていた場合は、参加資格を失い(FR-TOURW-027・FR-TOURY-030)、決済した参加費は自動で全額返金される(FR-PYMNT-010)

#### 削除

- 「危険な操作」の区画の「プロダクトを削除」から、プロダクト名と削除の結果(ローンチ予定と過去のローンチの記録が削除され、元に戻せない旨)を明記した確認のダイアログを開き、確定のボタン「削除」で論理削除する(FR-PRDCT-013)。削除は画面に表示しないbot判定の結果を添えて送る
- 確認のダイアログの本文の下に、後続の機能が登録した注意書き([自分のプロダクトの区画の登録](#自分のプロダクトの区画の登録))を、そのプロダクトに該当する場合に示す
  - 掲載中・掲載予定のスポンサー広告があるプロダクトの削除確認には、広告が終了して返金されない旨を表示する(FR-SPONS-020)
  - トーナメントの参加資格を得ているプロダクトの削除確認には、参加資格を失い参加費が全額返金される旨を表示する
- 削除に成功すると、削除した旨をトーストで示し、[自分のプロダクト](#自分のプロダクトmyproducts)へ移す

### プロダクトのハンドルの扱い

ハンドルの規則は[旧ハンドルの保持とリダイレクト](#旧ハンドルの保持とリダイレクト)に従う。プロダクトに固有の扱いは次のとおりである。

- 論理削除したプロダクトの現在のハンドルは、物理削除(論理削除から14日以内、FR-PRDCT-024)まで使用中として扱い、他のプロダクトは設定できない(FR-PRDCT-010)。削除の直後にハンドルを他人が取り、共有済みのリンクを乗っ取ることを防ぐためである
- 論理削除したプロダクトの旧ハンドルからの転送は、論理削除の時点で止める(FR-PRDCT-022)
- 旧ハンドル(論理削除したプロダクトのものを含む)は、他のプロダクトが新しいハンドルとして設定できる(FR-PRDCT-011)。設定を確定した時点で元の保持者からその旧ハンドルを取り除き、元の転送を終える。以後そのURLは新しく設定したプロダクトのものになる(FR-PRDCT-020・022)

## 料金ページ(`/pricing`)

スポンサー広告の申し込みとUltrasプランの加入を1ページにまとめる。各機能が登録する区画を次の表の順に並べ、末尾に法的通知(返金ポリシー・特定商取引法に基づく表記)へのリンク(`/legal`、アンカー無し)を置く。未ログインでも閲覧でき、検索エンジン向けのページのタイトル「料金」と説明を持つ(文言は[Ultrasの画面の文言](003-text-and-copy-rules.md#ultrasの画面の文言))。

| 順序 | 区画           | 担当する機能        | 対応要件                        |
| ---- | -------------- | ------------------- | ------------------------------- |
| 10   | Ultras         | ultras-subscription | FR-PPLAN-001、FR-ADMCF-022・023 |
| 20   | スポンサー広告 | sponsorship         | FR-SPONS-002・004・007          |

- 区画はそれぞれ自分でデータを取得し、1つの区画の取得や描画の失敗はその区画の位置に見出しと再試行の導線を示して、他の区画と法的通知へのリンクの表示を続ける。読み込み中と失敗の間も区画の見出しを出す。区画が1つも表示されない時も法的通知へのリンクは出す
- Ultrasの区画: 見出し「Ultras」、月額の価格(税込のUSD)、特典(トーナメント参加費の免除・予選敗北後の再ローンチを2日後から可能・公開プロフィールの加入表示(FR-UPROF-014))、自動更新と解約の条件、支払い済みのトーナメント参加費は返金されない旨(FR-PPLAN-009)、「Ultrasに加入」ボタン
  - 機能フラグ(FR-ADMCF-022)がオフの間は、未加入者(特典の継続期間内にない閲覧者)にはこの区画を表示せず、ページは他の区画のために表示を続ける(FR-ADMCF-023)。特典の継続期間内の閲覧者には、フラグの値によらず区画を表示する
  - 特典の継続期間内の閲覧者には、「Ultrasに加入」ボタンの代わりに現在の加入状態と、プラン管理画面(`/settings/plan`)への導線「プランを見る」を表示する
  - 未ログインの閲覧者には価格と説明を表示し、「Ultrasに加入」ボタンはログインへ誘導する(ログインの後に料金ページへ戻る)。メールアドレス未確認の利用者にはボタンを無効にし、理由を示す(FR-USER-006)
  - 価格を照会できない時は、価格の位置に現在表示できない旨を示し、ボタンを無効にする
  - 「Ultrasに加入」ボタンを押すとUltrasの購入を作り、決済画面(`/checkout/{購入ID}`)へ移る。加入できない理由(機能フラグがオフ・加入中・解約済みで特典の継続期間内など)はボタンの近くに示す
- スポンサー広告の区画: Legend/Gold/Silverの1日単価と表示位置の説明、申し込みフォーム(自身のローンチ済みプロダクトの選択、ティア、掲載開始日・終了日)、日数×単価の合計金額、「申し込む」ボタン。未ログイン時は価格と説明のみ表示し、ボタンはログインページへ誘導する。押下でFR-PYMNT-001の決済画面へ遷移する
- トーナメント参加費の決済はこのページには置かず、対象ローンチのプロダクト管理ページから行う(後述)

### 決済前の最終確認画面

決済画面(Stripe Payment Element)の入力欄より上に、特定商取引法12条の6に基づき次の事項を表示する。

- 分量・販売価格(税込)・支払方法(FR-PYMNT-001の決済手段)及び時期・役務の提供時期
- 申込みの期間に定めがある場合は、その旨と期間
- 申込みの撤回及び解除に関する事項([返金ポリシー](../legal/004-legal-notice-outline.md#返金ポリシー)の要旨)と、法的通知のページへのリンク。リンク先は見出しのアンカーを付けない`/legal`とする。アンカーは見出しの文字列から作られ、法的通知の見出しの改訂でリンクが切れるためである
- 役務の即時提供への同意と、提供開始により撤回権(EU・英国の消費者の14日間)を失う旨の了知を求めるチェックボックス。居住地を問わず表示し、未チェックの間は決済を確定できない

Ultrasプラン加入の決済画面ではこれに加えて、毎月自動で更新される旨と毎月の請求額・プラン管理画面からいつでも解約でき課金期間の末日まで特典が続く旨・日割りの返金が無い旨・支払い済みのトーナメント参加費は返金されない旨(FR-PPLAN-009)を表示する(文言は[決済の画面の文言](003-text-and-copy-rules.md#決済の画面の文言)の「Ultrasの最終確認画面の表示事項」)。配置と状態ごとの表示は[決済画面](#決済画面checkout購入id)を参照する。

## トーナメント参加費の導線

決済画面には[決済前の最終確認画面](#決済前の最終確認画面)と同様の事項を表示し、申込みの期間は下記の決済期限とする。

### Weekトーナメント

- 予選勝利の結果通知メールと、自身のプロダクト管理ページ・プロダクト詳細ページ(本人のみ)に「Weekトーナメントに参加」ボタンと決済期限を表示する
- 決済期限はユーザーのタイムゾーンでの日時と相対表現を併記する。UIに表示する時刻はFR-TOURW-002の決済セッション作成期限とする([理由](../overview/002-pricing-and-plans.md#ui表示において決済期限を35分早める理由))。日曜日ローンチは猶予が短い([Weekトーナメント規則](../overview/004-week-tournament-rules.md#参加資格と日程))ため、結果通知メール内でも期限を強調する。期限まで残り48時間未満では、ページ上の期限表示を注意色で強調し「時:分:秒」の秒読みを添える
- Ultras加入中はFR-TOURW-003により自動的に参加資格を得るため、ボタンの代わりに「参加費免除」の状態表示を行い、参加のための操作は不要とする(免除条件は[トーナメント参加費の免除条件](../overview/002-pricing-and-plans.md#トーナメント参加費の免除条件)を参照)
- Ultras未加入者には決済ボタンの下に、Ultrasなら参加費が免除され敗北後は2日で再ローンチできる旨と料金ページへのリンクを添える。表示は機能フラグ(FR-ADMCF-022)に従う
- 決済サービスの障害時(縮退運転)は決済ボタンを無効化し、ボタンの近くに「現在ご利用いただけません」と閲覧やその他の操作は利用できる旨を表示する

### Yearトーナメント

- Week優勝(決勝勝利)の結果通知メール(FR-NOTIF-004)と、自身のプロダクト管理ページ・プロダクト詳細ページ(本人のみ)に「Yearトーナメントに参加」ボタンと決済期限を表示する
- 決済期限はユーザーのタイムゾーンでの日時と相対表現を併記する。UIに表示する時刻はFR-TOURY-004の決済セッション作成期限とする([理由](../overview/002-pricing-and-plans.md#ui表示において決済期限を35分早める理由))。Week優勝から決済期限までは次回Yearトーナメント決勝日の設定次第で最長63週空く([Yearトーナメント規則](../overview/005-year-tournament-rules.md#決勝日と日程))ため、ボタンと期限表示はWeek優勝直後から決済完了または期限到来まで表示し続ける
- Ultras加入中はFR-TOURY-005により自動的に参加資格を得るため、ボタンの代わりに「参加費免除」の状態表示を行い、参加のための操作は不要とする(免除条件は[トーナメント参加費の免除条件](../overview/002-pricing-and-plans.md#トーナメント参加費の免除条件)を参照)

## 決済(`/checkout/*`)

決済画面と決済後のランディングはログインを求め、未ログインならログインの画面を経て開く。どちらも題名(`h1`)の下に内容を置き、検索エンジンに載せない。決済のためのスクリプト(Stripe.js)はこの2つのページでだけ読み込み、他のページでは読み込まない。購入の状態と反映の規則は[決済実装方針](../features/004-payments.md)を、文言は[決済の画面の文言](003-text-and-copy-rules.md#決済の画面の文言)を正とする。

### 決済画面(`/checkout/{購入ID}`)

各申込の画面のボタンが購入を作ってからこのページへ移す。題名は「お支払い」とする。購入が支払える状態(未完了で有効期限の前)なら、上から順に次を置く。

1. 購入の内容: 購入・分量・販売価格(税込)・支払方法・支払時期・役務の提供時期。最終確認画面の追加事項(Ultrasの自動更新である旨・毎月の請求額・解約方法など)があれば、見出し「購入の条件」の箇条を続ける
2. 受付期限(申込みの期間に定めがある購入だけ): 閲覧者のタイムゾーンでの日時と残り時間の相対表現、期限を過ぎると支払いを受け付けない旨
3. 返金ポリシー: 返金ポリシーの要旨と、法的通知(`/legal`、アンカー無し)へのリンク
4. お支払い情報: 同意のチェックボックス、決済情報の入力欄(Stripe Payment Element)、請求先住所の入力欄、「支払いを確定する」ボタン

- 決済手段は決済セッションの側で絞り、画面では選ばせない。入力欄にはカード(Apple Pay・Google Payを含む)とLinkだけが出る
- 請求先住所は、購入者の居住地に応じた税額をStripe Taxで算出するために集める(LR-009)
- 「支払いを確定する」ボタンは、同意のチェックボックスが未チェックの間と、入力欄が確定できる状態でない間は無効にする。押すと、先に同意した日時と同意の文言の版を購入に記録し、記録に成功したときだけ支払いを確定する。記録の失敗と、カードの拒否など確定の失敗は、ボタンの上に理由を示し、別の決済手段でやり直せるようにする。送信中はボタンの文言を「送信中」にする
- 金額は税込のUSDを、閲覧者のロケールに応じた数値の表示形式で示す(I18N-003・I18N-004)

購入の状態ごとに、入力欄の代わりに次を表示する。

| 状態                                                     | 表示                                                                                                                                               |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 支払いの確認中(決済セッションの完了の後、反映の前)       | 確認が済むと決済履歴に記録される旨と、「決済履歴を見る」                                                                                           |
| 完了                                                     | 支払いが完了している旨と、「決済履歴を見る」                                                                                                       |
| 権利を付与できず全額を返金する                           | 全額を返金する旨と返金の理由と、「決済履歴を見る」                                                                                                 |
| 失効(有効期限切れ・支払いの失敗・新しい購入への置き換え) | 有効期限が切れたため購入が完了していない旨。受付期限の前なら「決済をやり直す」(購入種別ごとの申込の画面へのリンク)、受付期限の後ならやり直せない旨 |
| 決済を利用できない(Stripeに到達できない、公開キーが無い) | [縮退の表示](#決済の縮退の表示)                                                                                                                    |
| 他人の購入・存在しない購入                               | 状態を明かさずに、決済が見つからない旨とURLの確認の案内、「決済履歴を見る」                                                                        |

- 「決済をやり直す」の行き先は、トーナメント参加費が自身のプロダクト管理(`/my/products`)、スポンサー広告とUltrasプランが料金ページ(`/pricing`)、決済の疎通確認が決済履歴(`/settings/billing`)の開始のボタンとする
- 読み込み中はスケルトン、取得の失敗は題名を残したまま再試行ボタンと問い合わせへの導線を表示する。再試行を押すと題名へフォーカスを移す

### 決済後のランディング(`/checkout/return`)

Stripeが支払いの後に移すページで、題名は「お支払いの結果」とする。開くと、クエリの`session_id`の決済セッションの状態をStripeから取り直し、Webhookと同じ反映の処理を呼ぶ(FR-PYMNT-009)。同じ決済セッションを何度開いても、反映は1回しか行わない。

題名の下に、状態の文(状態が変わるたびに支援技術へ伝える)・導線・内容を順に置く。

| 状態                                           | 状態の文と導線                                                                                                                                       | 内容                                                       |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 確認中(反映の結果を待つ間)                     | 結果を確認している旨                                                                                                                                 | —                                                          |
| 完了                                           | 購入が確定した旨。購入した対象の画面(トーナメント参加費はプロダクト管理、スポンサー広告は広告の一覧、Ultrasプランはプランの管理)と「決済履歴を見る」 | 購入の内容(購入・分量・お支払い金額(税込)・役務の提供時期) |
| 処理中(支払いが未確定、または反映が未完了)     | 確認が済むとこの画面の表示が切り替わる旨と、「決済履歴を見る」                                                                                       | —                                                          |
| 処理中のまま確かめ直しの上限に達した           | 確認に時間がかかっているため、しばらくしてから決済履歴で確かめるよう案内する旨と、「決済履歴を見る」                                                 | —                                                          |
| 権利を付与できず全額を返金する                 | 全額を返金する旨と返金の理由と、「決済履歴を見る」                                                                                                   | —                                                          |
| 支払いが完了していない(決済セッションは有効)   | 購入が完了していない旨と、決済画面へ戻る「決済をやり直す」                                                                                           | —                                                          |
| 失効                                           | 決済画面の失効と同じ                                                                                                                                 | —                                                          |
| 決済を利用できない                             | 「決済履歴を見る」                                                                                                                                   | [縮退の表示](#決済の縮退の表示)                            |
| 他人の決済セッション・存在しない決済セッション | 状態を明かさずに、決済が見つからない旨とURLの確認の案内、「決済履歴を見る」                                                                          | —                                                          |
| `session_id`が無い・形式に合わない             | 決済の確認に必要な情報が正しくない旨とURLの確認の案内、「決済履歴を見る」                                                                            | —                                                          |

- 処理中の間は3秒ごとに最大20回まで確かめ直す。上限に達したら確かめ直しを止める
- 確認の失敗(上の表に無い失敗)は、題名を残したまま再試行ボタンと問い合わせへの導線を表示する。再試行を押すと題名へフォーカスを移し、確かめ直しの回数を数え直す
- 決済の疎通確認の購入は対象の画面を持たないため、完了の導線は「決済履歴を見る」だけとする

### 決済の縮退の表示

決済サービスの障害でStripeに到達できない間(公開キーやStripeのキーを置いていない環境を含む)は、決済画面の入力欄と決済後のランディングの内容の代わりに、題名「現在ご利用いただけません。」と、決済サービスで障害が発生している旨・閲覧やその他の操作は引き続き利用できる旨の注記の枠を表示する(NFR-AVAIL-002)。Stripe.jsの読み込みや支払いの確定が想定外の理由で失敗した時も同じ表示にし、エラートラッキングへ送る。

## ヘルプ

表示項目はFR-HELP-001〜003・FR-HELP-008〜010を正とする。目次はPCでは右側に固定、モバイルでは本文冒頭に折りたたみで表示する。

## 問い合わせ

表示項目はFR-INQRY-001・FR-INQRY-005・007・FR-INQRY-013〜016を正とする。添付ファイルはダウンロードリンクとして表示し、インライン表示しない(FR-FILEU-019)。文言は[状態・案内の文言](003-text-and-copy-rules.md#状態案内の文言)と[操作とナビゲーションの名前](003-text-and-copy-rules.md#操作とナビゲーションの名前)を参照。

### 問い合わせフォーム(`/contact`)

題名「お問い合わせ」と導入文の下に、閲覧者の状態に合わせたフォームを1つ置く。ログイン中(停止中を含む)の閲覧者には、フォームの下に自分の問い合わせの一覧を置く。

| 閲覧者                       | フォーム                                                                                                                                     | 送信の後                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 未ログイン                   | カテゴリ・ニックネーム・連絡先メールアドレス・メッセージ(FR-INQRY-001)                                                                       | フォームを送信完了の表示に置き換え、その見出しへフォーカスを移す(FR-INQRY-012) |
| 停止中のログインユーザー     | 停止中である旨と、回答は入力した連絡先メールアドレスへ届く旨の案内(FR-INQRY-006)に続けて、未ログインと同じフォーム                           | 未ログインと同じ                                                               |
| 停止中でないログインユーザー | 送信者(プロフィール画像とニックネーム。FR-INQRY-005)の表示・カテゴリ・メッセージ・添付ファイル(任意。FR-INQRY-007)。連絡先の入力欄は置かない | 作成した問い合わせのチャット(`/inquiries/{id}`)へ移す(FR-INQRY-011)            |

- カテゴリは標準カテゴリ「その他」を末尾にした選択肢から選ぶ。どのフォームも、画面に表示しないbot判定の結果を添えて送る(FR-INQRY-008)
- 添付ファイルは選ぶたびにアップロードし、アップロード済みのファイルを削除のボタン付きで一覧にする。APIサーバーが添付できないと返したファイルは、一覧の項目にその旨を示す
- 未ログイン(停止中を含む)の送信の回数の上限(FR-RLMIT-003)を超えた時は、エラーの文言に再度送信できる日時を添える
- 自分の問い合わせの一覧(見出し「送信した問い合わせ」)は停止中でないログインユーザーと停止中のログインユーザーの両方に表示し、送信日時の新しい順に20件ずつ並べる。各行は対応ステータス・カテゴリ名(チャットへのリンク)・送信日時・最後のメッセージの日時を示す。21件目以降は一覧の下の「前へ」「次へ」で移り、ページの位置はURLクエリ`after`に置く(不正な値は1ページ目として扱う)。1ページ目で続きが無い時は「前へ」「次へ」を表示しない
- ログイン中の利用者の送信の後と、チャットでの追加メッセージの後は、一覧を取り直す

### 問い合わせチャット(`/inquiries/{id}`)

題名「問い合わせチャット」の下に、カテゴリ・対応ステータス・送信日時の一覧、見出し「メッセージ」の区画、送信のフォームを順に置く。

- メッセージは送信日時の古い順に並べ(FR-INQRY-013)、利用者のメッセージは既定のアイコン、管理者の返信は返信した管理者のプロフィール画像とニックネーム(削除済みなら「削除済みの管理者」。FR-INQRY-014・015)を示す。新しく届いたメッセージは支援技術に読み上げる
- 表示している間は30秒ごとと、他のタブや他のアプリから画面へ戻った時に取り直し、新しいメッセージと対応ステータスを反映する。タブが表示されていない間は取り直さない。メッセージの見出しの横に「自動更新」のスイッチ(既定はオン)を置き、オフにすると30秒ごとの取り直しだけを止める
- 停止中でないログインユーザーには、メッセージ(1,000文字以内)と添付ファイル(任意。FR-INQRY-019)の送信のフォームを置く。送信に成功したら本文の欄を空にしてフォーカスを戻す
- 停止中のログインユーザーにはフォームの代わりに、送信できない旨と問い合わせフォームへのリンクを表示する(FR-INQRY-018)
- 本人以外の問い合わせ・存在しない問い合わせ・形式に合わないIDは、どれも同じ表示の404にし、題名の下に問い合わせが見つからない旨と、送信した問い合わせはお問い合わせのページの一覧から開ける旨、「お問い合わせのページへ」の導線を示す。チャットは検索エンジンに載せない

## 法務文書(`/terms`・`/privacy`・`/legal`)

利用規約・プライバシーポリシー・法的通知は、管理者が[管理画面](#法務文書legal-documents)で公開した版だけを表示し、下書きは表示しない。共通フッターのリンク(LR-001)から到達する。表示項目はFR-ADMAG-010を正とする。本文はマークダウンを描画し、本文中の外部リンクは[外部Webサイトへのリンク](#外部webサイトへのリンク)のとおり別タブで開く。アニメーション演出は使わず、読み物として静止させる。

公開ページには上から順に以下を配置する。

1. 見出し: ページの`h1`に文書の名前
2. 最終改訂日: 最新版の公開日(曜日を含まない年月日)
3. 本文
4. 改訂履歴: 見出し(`h2`)「改訂履歴」の下に、公開した版を新しい順に並べる。各版は「第N版」(過去の各版のページへのリンク)・公開日・変更概要を示し、公開した管理者は示さない。版の数は年に数件の想定のため、ページ送りは置かない

まだ1つも版を公開していない文書は、見出しの下に「この文書は準備中です。」だけを表示し、検索エンジンに載せず正規のURLを出さない。公開済みの文書はパス(`/terms`など)を正規のURLとする。

過去の各版のページ(`/{文書のパス}/revisions/{版番号}`)には上から順に以下を配置する。

1. 見出し: ページの`h1`に「<文書の名前>(第N版)」
2. 版の案内: 本文より前に、過去の版なら「これは第N版です。最新版ではありません。」と公開ページへの「最新版を見る」、最新版なら「これは最新版です。」と公開ページへの「公開ページを見る」を、注記の枠で示す
3. 公開日(曜日を含まない年月日)・変更概要
4. 本文

- 版番号は先頭が0でない1〜9桁の整数とし、形式に合わない版番号と存在しない版は[存在しないページ](#共通レイアウト利用者側)(404)にする
- 過去の各版のページは、最新版の版番号のものを含め検索エンジンに載せない
- 読み込み中はスケルトン、取得の失敗は見出しを残したまま本文の位置に再試行ボタンと問い合わせへの導線を表示する。再試行を押すと見出しへフォーカスを移す

## 疎通確認(`/system/status`)

フロントエンドサーバーからAPIサーバーとデータベースへ到達できるかを開発者が確かめるページで、利用者側・管理者側の両方に同じ構成で置く。ローカルとstagingの環境だけで表示し、prodでは存在しないページ(404)とする。検索エンジンの索引には載せない。

- 見出し「疎通確認」の下に、画面を表示した時の結果の区画と「ブラウザからの再確認の結果」の区画の2つを並べ、それぞれにAPIサーバーの時刻とデータベースの到達可否を表示する
- 画面を表示した時の結果の区画の見出しは、取得を実行した場所に合わせる。このページを直接開いた(読み込み直した)時はサーバー側で取得するため「サーバー側の描画時の結果」とし、ブラウザ内の画面遷移やエラーの画面の「再試行」でこのページを表示した時はブラウザで取得するため「画面の読み込み時の結果」とする。区画の中身(時刻・到達可否・失敗の文言)は実行した場所によらず同じである
- 「再確認」ボタンでブラウザから取得し直し、結果を「ブラウザからの再確認の結果」の区画に出す。押す前の区画には操作の案内を出す
- APIサーバーへ到達できない場合は、結果の区画に「APIサーバーへ到達できません。」を表示し、エラーの画面にはしない
- 文言は開発者向けの画面のため、[文言・文字数規則](003-text-and-copy-rules.md#疎通確認の画面の文言)のとおり技術用語(APIサーバー・データベース)を使う

## 基本レイアウト(管理者側)

管理者側の全ページに共通する基本レイアウトは、ヘッダー・メニュー・本文で構成し、フッターは持たない。

- ヘッダーには左端にサービス名と管理画面であることを示すロゴ(「⚽️ Launch Stadium管理」、管理者側のトップページへ遷移)を、右端にダークモードの切替ボタンとログイン中の表示を置く。切替ボタンは[利用者側](#ダークモードの切替ボタン)と同じものとする。幅が足りない時は、切替ボタンとログイン中の表示を次の行の右端へ折り返す
- メニューは、幅768px以上では本文の左の列、768px未満では本文の上に置く
- メニューは登録された項目だけを[管理者側ページ一覧](#管理者側ページ一覧)の順に並べ、現在のページの項目を示す。768px未満では「メニュー」のボタンで開くシートに並べる。全ロールが全メニューを参照できるため、項目をロールで隠さない
- ログイン中の表示は、管理者のアバター・ニックネーム・ロールの表示名のボタンで、開くと「自分のアカウント」と「ログアウト」を選べる。幅640px未満ではアバターだけを見せ、640px以上ではニックネームとロールの表示名を並べる(長いニックネームは折り返す)
- 未ログイン(取得の前・取得の失敗を含む)では、ログイン画面などの認証の画面・存在しないページ・想定外のエラーのページで、メニューもログイン中の表示も表示しない。管理者側には新規登録が無いため、ログインへの導線も置かない
- ダッシュボード(`/`)は各機能が登録したカード([ダッシュボードのカード](#ダッシュボードのカード))を登録の順に並べ、カードが無い時は「表示できる項目はまだありません。」を表示する。1つのカードの失敗はそのカードの位置だけに再試行の導線とともに示し、問い合わせへの導線と問い合わせを促す文は出さない
- 存在しないページの表示はトップページへの導線だけを添える。想定外のエラーの表示は再試行の導線だけを添え、問い合わせへの導線と問い合わせを促す文は出さない(管理者側に問い合わせの画面が無いため。文言は[想定外のエラーの画面](003-text-and-copy-rules.md#状態案内の文言))
- 管理者側のページは検索エンジンの索引の対象外(`noindex`)のため、正規のURL(`<link rel="canonical">`)を出さない

### メニューごとの必要なロール

ロールは「閲覧のみ」「モデレーター」「最上位管理者」の順に強い。閲覧のみは全メニューの参照と自分のアカウントの編集だけを行える。モデレーターは、要件が最上位管理者に限っていない更新操作をすべて行え、加えて管理者の招待と、最上位管理者以外のアカウントの削除を行える。最上位管理者はすべての操作を行える。要件定義書にロールごとの権限の一覧が無いため、各機能は次の表を基準に、操作ごとに必要なロールを宣言する。

| プロダクト         | 一覧・検索・詳細                                                                           | 非公開化・復元                                                       | —                                                                                    |
| コメント           | 一覧・検索                                                                                 | 非公開化・復元                                                       | —                                                                                    |

### ダッシュボードのカード

ダッシュボードの内容は、それぞれのカードを担当する機能が登録する。登録の順序は次の表の値とし、小さいものから並べる。カードは全ロールに表示する。

| 順序 | カード                   | 担当する機能                | 対応要件                   |
| ---- | ------------------------ | --------------------------- | -------------------------- |
| 10   | 週毎の統計グラフ         | UGC管理(ugc-moderation)     | FR-ADMAC-001、FR-ADMUG-001 |
| 20   | 未対応の問い合わせの件数 | 問い合わせ(inquiry-chat)    | FR-ADMAC-001               |
| 30   | 未対応の通報の件数       | 通報管理(content-reporting) | FR-ADMAC-001               |

- 各カードは自分でデータを取得し、読み込み中・エラー・本文を切り替える共通の枠に表示する。カードの題名から各メニューのページへの導線を置ける
- 未対応の問い合わせの件数のカードは、退会済みの利用者の問い合わせを除く「未対応」のログイン・未ログインの問い合わせの合計を示し、題名から「未対応」で絞り込んだ[問い合わせの一覧](#問い合わせinquiries)(`/inquiries?status=OPEN`)へ移す。取り直しに失敗した時は前の件数を残す

## 管理者側の認証(`/auth/*`)

| パス                           | ページ                     | 備考                                                                                                                                                                                                                                                 |
| ------------------------------ | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/auth/login`                  | ログイン                   | メールアドレス・パスワードの後、同じページで認証コード(またはリカバリコード)の入力を求める。クエリ`redirect`: ログインの後の戻り先(同じオリジンのパスだけを受け付け、それ以外はダッシュボードへ戻る)。ログイン中の管理者が開くとダッシュボードへ移す |
| `/auth/password-reset`         | パスワードの再設定の要求   | メールアドレスが管理者として登録されているかによらず同じ案内を表示する                                                                                                                                                                               |
| `/auth/password-reset/confirm` | 新しいパスワードの設定     | メールのリンクから開く                                                                                                                                                                                                                               |
| `/auth/invitation`             | 招待の受け入れ             | 招待のメール、または開発者の招待の発行コマンドのリンクから開く。ニックネーム・パスワード→認証アプリのQRコードと手入力用の文字列→認証コード→リカバリコードの表示→ダッシュボードへ、の順に同じページで進む                                             |
| `/auth/email-change/confirm`   | メールアドレスの変更の確定 | メールのリンクから開く                                                                                                                                                                                                                               |

- 管理者側には新規登録が無い。管理者は、管理者アカウントのページからの招待と、開発者が実行する招待の発行コマンドでだけ増え、招待中の管理者は招待の受け入れを済ませるまでログインできない(FR-ADMAC-015)
- どのページも、本文の中央に、ページの題名と白い面(カード)に載せたフォームを幅を絞って置く。ログイン画面には、パスワードの再設定の画面への導線を置く
- メールのリンクから開くページは、[利用者側](#認証auth)と同じく、トークンをURLのフラグメント(`#token=`)で受け取り、読み取った直後にアドレスバーのURLから消す。開いただけでは確定せず、ボタンを押して確定する。リンクが無効か期限切れなら、その旨と次の操作(招待は招待した管理者への再送の依頼、パスワードの再設定は再設定の要求の画面、メールアドレスの変更は自分のアカウントのページ)を示す
- 招待の受け入れを完了した端末は、改めてのログインを求めずにログイン状態にする。リカバリコードはこの画面でだけ表示し、両方(認証アプリとリカバリコード)を失うと復旧できない旨を添える
- 招待の受け入れとメールアドレスの変更の確定のページは、ログイン中でもダッシュボードへ移さない。別の管理者がログイン中のブラウザで招待の受け入れを完了すると、そのブラウザのログインは招待を受け入れた管理者に替わる
- ログイン必須のページ(`/auth/*`と[疎通確認](#疎通確認systemstatus)以外の全ページ)を未ログインで開くと、開こうとしたページを戻り先にしてログインページへ移す
- ログインとパスワードの再設定の要求のフォームは、画面に表示しないbot判定の結果を添えて送る

## 問い合わせ(`/inquiries`)

ログイン・未ログインの問い合わせの一覧と詳細を表示し、返信と対応ステータスの変更を行う。操作と必要なロールは[メニューごとの必要なロール](#メニューごとの必要なロール)、文言は[文言・文字数規則](003-text-and-copy-rules.md#管理画面の状態案内の文言)を参照。返信と対応ステータスの変更は監査ログに記録するため、返信のフォームと対応ステータスの変更の確認のダイアログに、理由(任意)の欄と監査ログに記録される旨を出す。

| パス                          | ページ | 備考                                                                                         |
| ----------------------------- | ------ | -------------------------------------------------------------------------------------------- |
| `/inquiries`                  | 一覧   | 絞り込みの条件とページの位置はURLクエリ(`status`・`kind`・`category`・`from`・`to`・`after`) |
| `/inquiries/{問い合わせのID}` | 詳細   | 存在しない問い合わせは404                                                                    |

### 問い合わせの一覧

題名「問い合わせ」と説明の下に、絞り込みと一覧を置く。

- 絞り込みは対応ステータス・種別(ログイン・未ログイン)・カテゴリ・受付日の開始日と終了日(閲覧者の地域の暦の年月日)で、「適用」で一覧に反映する。不正なURLクエリはその条件を未指定として扱う
- 一覧はログインと未ログインの問い合わせを合わせて受付日時の新しい順に50件ずつ並べ、列は受付日時・種別・カテゴリ・対応ステータス・送信者・最後のメッセージの日時とする。送信者の名前から詳細へ移る。送信者はログインの問い合わせなら利用者のニックネーム(利用者を読めない時は「表示できない利用者」)、未ログインの問い合わせなら入力されたニックネームとし、退会済みの利用者の問い合わせには「退会済み」の印を付ける。続きは「前へ」「次へ」で移る

### 問い合わせの詳細

題名「問い合わせの詳細」の下に、問い合わせの内容、操作の区画、後続の機能が登録する詳細の操作を順に置く。

- ログインの問い合わせは、種別・送信者(ニックネームとハンドル、退会済みなら「退会済み」の印)・カテゴリ・対応ステータス・受付日時の一覧と、見出し「メッセージ」の区画を置く。メッセージは利用者側の[問い合わせチャット](#問い合わせチャットinquiriesid)と同じく送信日時の古い順に並べ、30秒ごとと画面へ戻った時に取り直し、「自動更新」のスイッチで30秒ごとの取り直しを止められる
- 未ログインの問い合わせは、回答は連絡先メールアドレスへシステム外のメールで行う旨の案内に続けて、種別・ニックネーム・連絡先メールアドレス・カテゴリ・対応ステータス・受付日時・メッセージを示す。取り直しはしない
- モデレーター以上の管理者には、ログインの問い合わせの返信のフォーム(見出し「返信」、1,000文字以内)と、対応ステータスの変更の区画(見出し「対応ステータスの変更」)を置く。未ログインの問い合わせは対応ステータスの変更だけを置き、退会済みの利用者の問い合わせはどちらも置かない
- 返信を送ると利用者へ返信があった旨の通知メール(返信の本文を含まない)を送る(FR-INQRY-021)。返信は対応ステータスを変えない。返信を保存して通知メールを送れなかった時は、その旨をトーストで知らせる。送信に成功したらフォームを空にして本文の欄へフォーカスを移す
- 対応ステータスの変更は変更後の値を選んで「対応ステータスを変更」を押し、確認のダイアログで確定する。現在と同じ値は選んでも変更できない
- 詳細の操作の区画は後続の機能(ユーザーの停止など)が登録し、登録が無い間は何も表示しない

## カテゴリ(`/categories`)

題名「カテゴリ」と説明の下に、各機能が登録するカテゴリの区画を次の表の順に並べる。区画はそれぞれ自分でデータを取得し、1つの区画の失敗はその区画の位置だけに再試行の導線とともに示す。区画は[カテゴリの編集部品](003-text-and-copy-rules.md#管理画面の操作とナビゲーションの名前)で一覧と追加・編集・削除を行う。

| 順序 | 区画               | 担当する機能                | 対応要件               |
| ---- | ------------------ | --------------------------- | ---------------------- |
| 10   | プロダクトカテゴリ | product-launch              | FR-ADMCF-008・010・011 |
| 20   | ヘルプ記事カテゴリ | help-center                 | FR-ADMCF-012〜015      |
| 30   | 問い合わせカテゴリ | 問い合わせ(inquiry-chat)    | FR-ADMCF-016〜018      |
| 40   | 通報カテゴリ       | 通報管理(content-reporting) | FR-ADMCF-019〜021      |

- プロダクトカテゴリは先頭の区画とし、カテゴリ名とハンドルの一覧を追加の順に並べ、標準カテゴリ「その他」(ハンドル`other`)を末尾に置く。この並びはプロダクトの登録・編集画面のカテゴリの選択肢と同じである
  - ハンドルは必須で、[プロダクトのハンドル](#旧ハンドルの保持とリダイレクト)と同じ形式・大文字小文字を区別しない一意とし、予約語の対象にしない。ハンドルを変更しても変更前のハンドルは保持しない
  - 「その他」は削除・名前の変更・ハンドルの変更ができない(FR-ADMCF-010)
  - プロダクトが紐付くカテゴリは削除できない(FR-ADMCF-011)。論理削除してから物理削除されるまで(14日以内)のプロダクトも紐付くものとして数えるため、削除の確認のダイアログにその旨を示す
  - 追加・変更・削除は監査ログに記録し、確認のダイアログに記録される旨を出す。カテゴリの編集部品に理由の欄が無いため、理由は記録しない
- 問い合わせカテゴリは追加の順に並べ、標準カテゴリ「その他」を末尾に置く。「その他」は名前の変更と削除ができない(FR-ADMCF-017)。削除の確認のダイアログには、紐付く問い合わせの件数と「その他」へ付け替える旨を示す(FR-ADMCF-018)。追加・名前の変更・削除は監査ログに記録する

## 法務文書(`/legal-documents`)

利用規約・プライバシーポリシー・法的通知の下書きの編集と公開、公開した版の閲覧を行う。操作と必要なロールは[メニューごとの必要なロール](#メニューごとの必要なロール)、文言は[文言・文字数規則](003-text-and-copy-rules.md#管理画面の状態案内の文言)を参照。法務文書の操作は監査ログに記録しないため、確認のダイアログに監査ログに記録される旨を出さない。

| パス                                         | ページ   | 備考                                                                                                                  |
| -------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------- |
| `/legal-documents`                           | 一覧     |                                                                                                                       |
| `/legal-documents/{種類}`                    | 編集     | 種類は`terms`(利用規約)・`privacy`(プライバシーポリシー)・`legal-notice`(法的通知)。それ以外は404                     |
| `/legal-documents/{種類}/revisions/{版番号}` | 版の表示 | 版番号は利用者側の[過去の各版のページ](#法務文書termsprivacylegal)と同じ形式。形式に合わない版番号と存在しない版は404 |

### 一覧

題名「法務文書」の下に、3文書を1行ずつ並べた表を置く。列は文書の名前・最新版(「第N版」、未公開なら「未公開」)・公開日時・下書きの有無・操作(「編集」と、利用者側の公開ページを同じタブで開く「公開ページを開く」)とする。

### 編集

上から順に以下を配置する。

1. 題名: 文書の名前と、利用者側の公開ページを同じタブで開く「公開ページを開く」
2. 下書きの状態: 下書きがあれば、その旨と最後に保存した日時・保存した管理者を、無ければ下書きが無い旨を示す
3. 本文の入力欄と操作: マークダウンの入力欄(上限は[文字数上限](003-text-and-copy-rules.md#入力欄の文字数上限)の法務文書の本文)。初期値は下書き、下書きが無ければ最新版の本文、どちらも無ければ空とする。操作は「下書きを保存」と、下書きがある時だけの「下書きを破棄」「公開する」
4. 改訂履歴: 公開した版を新しい順に並べた表。列は版・公開日時・変更概要・公開した管理者・操作(管理画面の版の表示の「表示」と、利用者側の過去の各版のページを同じタブで開く「公開ページで見る」)とする

- 保存していない変更がある間は「公開する」を無効にし、下書きの保存を促す案内を添える。公開するのは保存済みの下書きだけである
- 保存していない変更があるまま他のページへ移ろうとすると、確認のダイアログを出す。ブラウザのタブを閉じる・読み込み直す時も、ブラウザの確認を出す
- 「下書きを破棄」は確認のダイアログを経る。「公開する」は変更概要(必須。利用者側の改訂履歴と過去の各版のページに公開される)を入力するダイアログを開き、入力欄の下に入力中の文字数と上限を示す
- 最上位管理者でない管理者には、本文の入力欄を読み取り専用にし、3つの操作を表示しない
- 保存・破棄・公開の結果はトーストで知らせ、画面の内容を結果に置き換える。破棄・公開の後は押したボタンが消えるため、本文があれば「下書きを保存」へ、本文が空なら本文の入力欄へフォーカスを移す
- 他の管理者が同じ文書を先に更新していた場合(競合)は操作を拒否し、入力欄の内容を残したまま、その旨と「最新の内容を読み込む」を本文の入力欄の上に示す
- 公開した管理者・保存した管理者が削除済みなら「削除済みの管理者」と表示する

### 版の表示

題名「<文書の名前>(第N版)」の下に、版・公開日時・変更概要・公開した管理者の一覧と、利用者側の過去の各版のページを同じタブで開く「公開ページで見る」を置き、その下に本文を表示する。

## 管理者側の設定(`/settings`)

題名「設定」と説明の下に、各機能が登録する設定の区画を次の表の順に並べる。区画はそれぞれ自分でデータを取得し、1つの区画の取得や描画の失敗はその区画の位置に見出しと再試行の導線とともに示して、他の区画の表示を続ける(読み込み中と失敗の間も区画の見出しを出す)。全ロールが各区画を参照でき、変更に必要なロールは[メニューごとの必要なロール](#メニューごとの必要なロール)に従う。文言は[文言・文字数規則](003-text-and-copy-rules.md#管理画面の状態案内の文言)を参照。

| 順序 | 区画                         | 担当する機能        | 対応要件                        |
| ---- | ---------------------------- | ------------------- | ------------------------------- |
| 10   | Yearトーナメントの決勝実施日 | tournament-year     | FR-ADMCF-001〜007               |
| 20   | Ultras導線の機能フラグ       | ultras-subscription | FR-ADMCF-022・023、FR-ADMAC-007 |
| 30   | 通知メールの送信者情報       | notifications       | FR-ADMCF-024                    |

- Ultras導線の機能フラグの区画は、現在の値(オン・オフ)のスイッチ、最後に変更した日時と変更した管理者のニックネーム、オフにすると未加入者への導線と新規加入を止め加入中の利用者には影響しない旨の説明を表示する(FR-ADMCF-022・023)
- スイッチは最上位管理者にだけ有効にし、それ以外のロールには無効にして最上位管理者だけが変更できる旨を添える(参照だけ。FR-ADMAC-007)。切り替えは確認のダイアログで確定し、ダイアログに理由(任意)の欄と監査ログに記録される旨を出す
- 切り替えの失敗は、理由の入力を保ったままダイアログの中に文言を示す。区画を表示した後に他の管理者が変更していた場合(競合)は切り替えを拒否し、最新の値を読み込み直すよう案内する。確定した後は区画の表示を新しい値に置き換え、トーストで知らせる

## 自分のアカウント(`/account`)

自分のアカウントのページは、ページの題名と説明の下に、次の区画を順に並べる。どの区画も全ロールが操作できる。

| 区画                 | 内容                                                                                                                                                         | 対応要件                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| プロフィール         | ニックネーム(必須)・肩書き(任意)・プロフィール画像(任意。未登録の間はニックネームから作るアイコン)の編集                                                     | FR-ADMAC-010〜012               |
| メールアドレスの変更 | 現在のメールアドレスの表示と、新しいメールアドレスへの確認のリンクの送信。リンクの画面で確定すると変わる                                                     | FR-ADMAC-016、FR-ADMAC-020〜022 |
| パスワードの変更     | 新しいパスワードの設定。確認のリンクを経ずに、送信した時点で変わる                                                                                           | FR-ADMAC-017                    |
| 多要素認証           | 認証アプリの再設定(ダイアログで、QRコードと手入力用の文字列→認証コード→新しいリカバリコードの表示)。設定し直すまでは今の認証アプリを使える。無効にはできない | FR-ADMAC-019                    |
| リカバリコード       | 未使用のリカバリコードの残数と、再発行(新しいリカバリコードはダイアログでだけ表示する)。残りが3個以下なら再発行を促す警告を添える                            | FR-ADMAC-019                    |

- メールアドレスの変更・パスワードの変更・多要素認証の再設定の開始・リカバリコードの再発行は、送信の前に本人確認として現在のパスワードと、認証コードかリカバリコードの入力を求める。リカバリコードで本人確認をすると、そのコードは使用済みになり残数が減る
- メールアドレスの変更の確定・パスワードの変更・多要素認証の再設定・リカバリコードの再発行の後は、全ての端末をログアウトさせ、操作した端末がログイン中ならその端末だけをログインしたままにする(FR-ADMAC-021)
- 多要素認証の再設定のダイアログは、完了の処理中に閉じられない。完了の後は新しいリカバリコードを示し、以前のリカバリコードは使えなくなる
