# ページ構成とレイアウト

利用者側・管理者側それぞれのページ一覧と、主要ページの情報配置を定める。各ページに表示する項目や操作の規則は対応要件を正とし、本書は要件定義書に無いURL・配置・並び順・UI上の振る舞いを定める。共通コンポーネントの実装規則は`docs/GUIDES/tech/frontend`を正とする。

## URL構造(利用者側)

| パス                                                             | ページ                                                   | 備考                                                           |
| ---------------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------- |
| `/`                                                              | トップページ                                             |                                                                |
| `/directory`                                                     | ディレクトリ                                             | クエリ: `q`・`category`・`from`・`to`・`sort`・`page`          |
| `/p/{handle}`                                                    | プロダクト詳細                                           | FR-PRDCT-010。ハンドル文字列は大文字小文字を区別しない         |
| `/@{handle}`                                                     | ユーザー公開プロフィール                                 | FR-UPROF-007。同上                                             |
| `/help`                                                          | ヘルプトップ                                             | クエリ: `q`                                                    |
| `/help/{handle}`                                                 | ヘルプ記事詳細                                           | FR-HELP-007                                                    |
| `/contact`                                                       | 問い合わせフォーム                                       |                                                                |
| `/inquiries/{id}`                                                | 問い合わせチャット                                       | FR-INQRY-007により本人のみ                                     |
| `/terms`・`/privacy`・`/legal`                                   | 利用規約・プライバシーポリシー・法的通知                 | 末尾に改訂履歴(FR-ADMAG-008)                                   |
| `/pricing`                                                       | 料金ページ(スポンサー広告の申し込みとUltrasプランの加入) | 決済導線はログイン必須。Ultrasの区画は機能フラグで表示を制御   |
| `/checkout/return`                                               | 決済後ランディング(FR-PYMNT-008)                         | `elements`モードのStripe Checkoutで`return_url`に設定する      |
| `/settings/*`                                                    | 各種設定(後述)                                           | ログイン必須                                                   |
| `/my/products`・`/my/products/new`・`/my/products/{handle}/edit` | 自身のプロダクト管理                                     | ログイン必須                                                   |
| `/auth/*`                                                        | 登録・ログイン・パスワードリセット等                     |                                                                |
| `/unsubscribe/{token}`                                           | 配信停止(FR-NOTIF-009)                                   | ログイン不要。RFC 8058のPOST先(FR-NOTIF-008)はイベントサーバー |
| `/api-docs`                                                      | 公開APIのSwagger UI(NFR-MAINT-007)                       |                                                                |

URL内のハンドル文字列は大文字小文字を区別せずに解決し、正規化した表記へリダイレクトはしない。検索エンジンによる重複コンテンツ判定を避けるため、各ページは`<link rel="canonical">`により登録時の表記のURLを正として出力する。

## 共通レイアウト(利用者側)

- ヘッダーにはロゴ(トップページへ遷移)・ディレクトリ・ヘルプ・「ローンチする」・ログイン/ユーザーメニューを表示する
- ヘッダーの「ローンチする」は未ログイン時はログインページへ、ログイン済みならプロダクト登録ページへ遷移する
- ユーザーメニュー: プロフィール、自身のプロダクト、設定、ログアウト(FR-USER-011)
- フッターにはFR-HELP-006・LR-001で定めるリンクを常に表示する
- 検索欄は共通ヘッダーに置かず、ディレクトリとヘルプの各ページ内に置く

### スポンサー広告スペース

FR-SPONS-006の広告スペースを以下の配置とする。申し込まれた広告は枚数上限を設けず全て表示する。

| ティア | 位置                         | 表示内容                            | サイズ感                                                 |
| ------ | ---------------------------- | ----------------------------------- | -------------------------------------------------------- |
| Legend | ヘッダー直下の全幅バナー     | ロゴ(`square-md`)・名称・タグライン | 高さ約120px。複数枚は横スクロールカルーセル              |
| Gold   | メインコンテンツ横のカード列 | ロゴ(`square-md`)・名称・タグライン | PCは幅280pxのサイドバー、モバイルは一覧の10件毎に1枚挿入 |
| Silver | Silverリスト(フッター直上)   | ロゴ(`square-sm`)・名称             | 1行に複数枚を折り返し表示                                |

- 広告ラベル(FR-SPONS-010)の文言は「スポンサー」とし、ティアの色で表示する
- 広告が0件のティアはスペースごと非表示にする

## トップページ

上から順に以下のセクションを表示する。該当マッチが無いセクションは非表示。

1. Yearトーナメントのマッチ(開催中の場合)。ラウンド名(1回戦/準々決勝/準決勝/決勝)と決勝日を見出しに表示
2. Weekトーナメントのマッチ(開催中の場合)。複数の週のトーナメントが重なる場合はFR-TOURW-009の順。第◯週とラウンド名を見出しに表示
3. 予選マッチ(FR-GAME-005)。全件をページネーションなしで表示

### 予選マッチの並び順

合計Upvote数(両プロダクトの和)が最も多いマッチを先頭に置き、それ以外は合計Upvote数が少ない順に並べる。注目のマッチを見せつつ、注目されていないマッチにも露出を回す意図である。同数の場合はマッチID順。並び替えはページ読み込み時に行い、閲覧中はリアルタイムに動かさない。

### マッチの不戦勝表示

不戦勝(対戦相手なし、FR-GAME-003・014、FR-TOURW-015・017、FR-TOURY-015・017)はUpvoteを受け付けないため対戦カードを出さず、該当の一覧末尾「不戦勝」セクション([表記規則](003-text-and-copy-rules.md#表記規則))に当該プロダクト情報のみを表示する。予選のペアリングの余り(FR-GAME-003)は1日のローンチ数が奇数の場合に最大1件のみ生じるが、マッチ直前の対戦相手の退会等及びブラケット内の不戦勝連鎖(FR-GAME-014、FR-TOURW-015・017、FR-TOURY-015・017)は件数に上限が無い。

### マッチの早期勝利表示

マッチ中に対戦相手側で投稿者の退会・停止またはプロダクトの非公開化が発生した場合(FR-GAME-013)、Upvote受付が打ち切られてマッチが終了し、勝者となったプロダクトは進行中の対戦カードから外れる。不戦勝表示と同じく予選一覧の末尾「不戦勝」セクション([表記規則](003-text-and-copy-rules.md#表記規則))に当該プロダクト情報のみを表示する。Week・Yearトーナメントのマッチ中の早期勝利(FR-TOURW-014・FR-TOURY-014)も、該当トーナメントの一覧末尾に同様に表示する。

### マッチカード

表示項目と導線はFR-GAME-006・FR-GAME-007、Upvoteボタンの活性条件はFR-VOTE-003・FR-VOTE-005を正とする。

- カードにはカテゴリと、予選終了までの残り時間(「フルタイムまであと◯時間」)及び終了時刻を表示する
- 「サイトを開く」は外部Webサイトを別タブで開く(当該WebサイトのSEO向上を支援するため、意図的に`rel`属性は付けない)
- Upvoteボタンは押下でトグル(Upvote/取り消し)。無効化時は理由をツールチップで示す
- 中央のバーは両者のUpvote数の比率。0対0のときは空のバー
- カテゴリ横断マッチはカテゴリを両プロダクト分表示する
- モバイルでは2つのプロダクトを縦に積み、VSとバーをその間に置く

## ディレクトリ

表示項目・絞り込み・検索・ソート・ページネーションはFR-DIR-002・FR-DIR-005〜009を正とする。

- カテゴリフィルタの既定値は「全て」
- 期間のプリセットは「昨日/今週/今月/今年/全期間」。週・月・年は基準時刻(UTC-08:00)で区切り、URLクエリには`from`・`to`(YYYY-MM-DD)へ展開して持つ
- 並び順の「関連度」は検索語がある場合のみ選択でき、検索時の既定値とする。検索語が無い場合の既定値はローンチ日の新しい順
- Product of the Week/Year受賞プロダクトにはゴールドのバッジを付ける
- 項目ごとに勝利した予選マッチ情報も表示する。複数回勝利したプロダクトは基準勝利マッチ1件の情報を表示する
  - 基準勝利は、ローンチ期間で絞り込む場合は期間内の最新の勝利、それ以外は直近の勝利とする
  - ソートキーの「ローンチ日」「Upvote数」も基準勝利の値を用いる
- `page`クエリの範囲外は空状態を表示する

## プロダクト詳細(`/p/{handle}`)

表示項目はFR-DIR-003・FR-DIR-004・FR-COMNT-003〜004・FR-RATNG-001・FR-REPOT-001を正とし、上から順に以下を配置する。

1. ヘッダー: ロゴ(`square-lg`)、名称、タグライン、カテゴリ、投稿者(アバター・ニックネーム)、「サイトを開く」、受賞バッジ、5段階評価の平均値と評価数、自身の評価入力
2. スクリーンショット(`screenshot-thumb`の横スクロール、クリックで`screenshot-full`をライトボックス表示)
3. 説明文(マークダウン描画)
4. マッチ履歴: 終了済みマッチ毎にUpvote数・勝敗・対戦相手を新しい順に表示。各マッチはUpvoteしたユーザー一覧を開閉できる。対戦相手が[公開範囲仕様](#プロダクト詳細の公開範囲)により404となる場合は、名称のみ表示しリンクさせない
5. ローンチ毎のコメント: 最新ローンチを既定で展開。返信は3階層までインデント
6. 通報リンク(ページ末尾、控えめだが見つけやすい位置)

投稿者本人には編集ボタンと再ローンチ予約ボタンを表示し、制限中は理由を示す。FR-RELCH-002・003のように解禁日が確定している場合はその日付も併記し、FR-RELCH-004のようにWeek/Yearトーナメントの結果確定を待つ場合は解禁日を示さず状況(参加中のトーナメント名)のみ示す([再ローンチ規則](../overview/006-relaunch-rules.md))。

### プロダクト詳細の公開範囲

投稿者本人が閲覧する場合を除き、ディレクトリに掲載されている(FR-DIR-001)プロダクト以外には404を返す。

上記を満たす場合でも、次のいずれかに該当するプロダクトには投稿者本人による閲覧を含め常に404を返す。

- 管理者が非公開化した(FR-ADMUG-007)
- 投稿者が退会済みまたは停止中である(FR-DIR-010と同じ判定)
- 投稿者が自分で論理削除した(FR-PRDCT-011)

## ユーザー公開プロフィール(`/@{handle}`)

表示項目はFR-UPROF-001・FR-FOLOW-005・FR-VOTE-010を正とし、上から順に以下を配置する。

1. ヘッダー: アバター(`square-lg`)、ニックネーム、ハンドル、ヘッドライン、フォロワー数、フォローボタン(本人には表示しない)、外部Webサイトリンク
2. 自己紹介(マークダウン描画)
3. タブ: ローンチしたプロダクト(FR-PRDCT-016) / Upvote履歴(FR-VOTE-010)
4. 通報リンク(ページ末尾)

フォロー中・フォロワーの一覧は本人の設定ページ内でのみ閲覧できる。

### ユーザー公開プロフィールの公開範囲

管理者により停止されたユーザーの公開プロフィールは、ログインユーザー自身のプロフィールである場合を除き404を返す。

## プロダクト登録・編集

入力項目と制約はFR-PRDCT-001〜009、外部WebサイトURLの制約はNFR-SECUR-044(プロフィール設定も同じ)を正とする。

- ローンチ日はカレンダーで選び、選択不可の日(FR-PRDCT-002、再ローンチ制限)はグレーアウトし理由をツールチップで示す
- ハンドルと外部WebサイトURLはフォーカスアウト時(UI-004)に検証し、その場でエラーを表示する
- 画像は選択後に編集ダイアログ(FR-FILEU-003)を経てアップロードする。SVGは編集ダイアログを省略する
- ペアリング後〜マッチ終了まで(FR-PRDCT-012)は、ローンチ日・カテゴリの編集欄と削除ボタンを無効化し、理由を表示する

## 料金ページ(`/pricing`)

スポンサー広告の申し込みとUltrasプランの加入を1ページにまとめ、上から順に以下を表示する。

1. Ultrasプラン: 月額価格、特典、自動更新と解約条件、「Ultrasに加入」ボタン。加入中は現在の状態と解約導線を表示。未加入ユーザーへのこの区画の表示は機能フラグで制御する(FR-ADMCF-018)
2. スポンサー広告: Legend/Gold/Silverの1日単価と表示位置の説明、申し込みフォーム(自身のローンチ済みプロダクトの選択、ティア、掲載開始日・終了日)、日数×単価の合計金額、「申し込む」ボタン
3. 法的通知(返金ポリシー・特定商取引法に基づく表記)へのリンク

- 未ログイン時は価格と説明のみ表示し、各ボタンはログインページへ誘導する
- 各ボタンは押下でFR-PYMNT-001の決済画面へ遷移する
- トーナメント参加費の決済はこのページには置かず、対象ローンチのプロダクト管理ページから行う(後述)

### 決済前の最終確認画面

決済画面(Stripe Payment Element)の入力欄より上に、特定商取引法12条の6に基づき次の事項を表示する。

- 分量・販売価格(税込)・支払方法及び時期・役務の提供時期
- 申込みの期間の定めが無い旨
- 申込みの撤回及び解除に関する事項([返金ポリシー](../legal/004-legal-notice-outline.md#返金ポリシー)の要旨)

Ultrasプラン加入の決済画面ではこれに加えて、自動更新である旨・毎月の請求額・解約方法を表示する。

## トーナメント参加費の導線

決済画面には[決済前の最終確認画面](#決済前の最終確認画面)と同様の事項に加え、申込みの期間として下記の決済期限を表示する。

### Weekトーナメント

- 予選勝利の結果通知メールと、自身のプロダクト管理ページ・プロダクト詳細ページ(本人のみ)に「Weekトーナメントに参加」ボタンと決済期限を表示する
- 決済期限はユーザーのタイムゾーンでの日時と相対表現を併記する。UIに表示する時刻はFR-TOURW-002の決済セッション作成期限とする([理由](../overview/002-pricing-and-plans.md#UI表示において決済期限を35分早める理由))。日曜日ローンチは猶予が短い([Weekトーナメント規則](../overview/004-week-tournament-rules.md#参加資格と日程))ため、結果通知メール内でも期限を強調する
- Ultras加入中はFR-TOURW-003により自動的に参加資格を得るため、ボタンの代わりに「参加費免除」の状態表示を行い、参加のための操作は不要とする(免除条件は[トーナメント参加費の免除条件](../overview/002-pricing-and-plans.md#トーナメント参加費の免除条件)を参照)

### Yearトーナメント

- Week優勝(決勝勝利)の結果通知メール(FR-NOTIF-002)と、自身のプロダクト管理ページ・プロダクト詳細ページ(本人のみ)に「Yearトーナメントに参加」ボタンと決済期限を表示する
- 決済期限はユーザーのタイムゾーンでの日時と相対表現を併記する。UIに表示する時刻はFR-TOURY-002の決済セッション作成期限とする([理由](../overview/002-pricing-and-plans.md#UI表示において決済期限を35分早める理由))。Week優勝から決済期限までは次回Yearトーナメント決勝日の設定次第で最長63週空く([Yearトーナメント規則](../overview/005-year-tournament-rules.md#決勝日と日程))ため、ボタンと期限表示はWeek優勝直後から決済完了または期限到来まで表示し続ける
- Ultras加入中はFR-TOURY-003により自動的に参加資格を得るため、ボタンの代わりに「参加費免除」の状態表示を行い、参加のための操作は不要とする(免除条件は[トーナメント参加費の免除条件](../overview/002-pricing-and-plans.md#トーナメント参加費の免除条件)を参照)
