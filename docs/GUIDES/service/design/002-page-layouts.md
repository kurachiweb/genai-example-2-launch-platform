# ページ構成とレイアウト

利用者側・管理者側それぞれのページ一覧と、主要ページの情報配置を定める。共通コンポーネントの実装規則は`docs/GUIDES/tech/frontend`を正とする。

## URL構造(利用者側)

| パス                           | ページ                                   | 備考                                          |
| ------------------------------ | ---------------------------------------- | --------------------------------------------- |
| `/`                            | トップページ(ピッチ)                     |                                               |
| `/directory`                   | ディレクトリ                             | クエリ: `q`・`category`・`from`・`to`・`sort`・`page` |
| `/p/{handle}`                  | プロダクト詳細                           | ハンドル文字列は大文字小文字を区別しない       |
| `/@{handle}`                   | ユーザー公開プロフィール                 | 同上                                          |
| `/help`                        | ヘルプトップ                             | クエリ: `q`                                   |
| `/help/{handle}`               | ヘルプ記事詳細                           |                                               |
| `/contact`                     | 問い合わせフォーム                       |                                               |
| `/inquiries/{id}`              | 問い合わせチャット                       | 本人のみ                                      |
| `/terms`・`/privacy`・`/legal` | 利用規約・プライバシーポリシー・法的通知 | 末尾に改訂履歴                                |
| `/pricing`                     | 料金ページ(スポンサー広告の申し込みとUltrasプランの加入) | 決済導線はログイン必須。Ultrasの区画は機能フラグで表示を制御 |
| `/settings/*`                  | 各種設定(後述)                           | ログイン必須                                  |
| `/my/products`・`/my/products/new`・`/my/products/{handle}/edit` | 自身のプロダクト管理 | ログイン必須                      |
| `/auth/*`                      | 登録・ログイン・パスワードリセット等     |                                               |
| `/unsubscribe/{token}`         | 配信停止(リンク先表示と確認操作のみ)     | ログイン不要。RFC 8058のPOST先はイベントサーバー |
| `/api-docs`                    | 公開APIのSwagger UI                      |                                               |

`/p/`・`/@`・`/help/`のハンドル文字列は大文字小文字を区別せずに解決し、正規化した表記へリダイレクトはしない。

## 共通レイアウト(利用者側)

```
┌──────────────────────────────────────────────────────────┐
│ ヘッダー: ロゴ(ピッチへ) | ディレクトリ | ヘルプ | [ローンチする] | ログイン/ユーザーメニュー │
├──────────────────────────────────────────────────────────┤
│ Legendスポンサー広告バナー(トップ・ディレクトリ・プロダクト詳細のみ) │
├────────────────────────────────┬─────────────────────────┤
│ メインコンテンツ               │ Goldスポンサー広告カード列 │
│                                │ (PCはサイドバー、        │
│                                │  モバイルは一覧の間)     │
├────────────────────────────────┴─────────────────────────┤
│ Silverスポンサー広告リスト(ロゴ小+名称)                    │
├──────────────────────────────────────────────────────────┤
│ フッター: ヘルプトップ | ピン留めヘルプ記事... | 利用規約 | プライバシーポリシー | 法的通知 │
└──────────────────────────────────────────────────────────┘
```

- ヘッダーの「ローンチする」は未ログイン時はログインページへ、ログイン済みならプロダクト登録ページへ遷移する
- ユーザーメニュー: プロフィール、自身のプロダクト、設定、ログアウト。全ページでログアウトできる(FR-USER-010)
- フッターにはヘルプトップと全てのピン留めヘルプ記事、利用規約・プライバシーポリシー・法的通知へのリンクを常に表示する(FR-HELP-006、LR-001)
- 検索欄は共通ヘッダーに置かず、ディレクトリとヘルプの各ページ内に置く

### スポンサー広告スペース

広告スペースはトップページ・ディレクトリ・プロダクト詳細の3ページに設ける。申し込まれた広告は枚数上限を設けず全て表示し、同一ティア内の順序は表示毎にランダムとする。

| ティア | 位置                                   | 表示内容                          | サイズ感                                   |
| ------ | -------------------------------------- | --------------------------------- | ------------------------------------------ |
| Legend | ヘッダー直下の全幅バナー               | ロゴ(`square-lg`)・名称・タグライン | 高さ約120px。複数枚は横スクロールカルーセル |
| Gold   | メインコンテンツ横のカード列           | ロゴ(`square-md`)・名称・タグライン | PCは幅280pxのサイドバー、モバイルは一覧の10件毎に1枚挿入 |
| Silver | Silverリスト(フッター直上)             | ロゴ(`square-sm`)・名称           | 1行に複数枚を折り返し表示                  |

- 各広告に「スポンサー」ラベルをティアの色で表示する(LR-008、FR-SPONS-010)
- リンクは`rel="sponsored"`を付け、対象プロダクトの外部Webサイトを別タブで開く。プロダクト詳細ページへは遷移しない
- 広告が0件のティアはスペースごと非表示にする

## トップページ(ピッチ)

上から順に以下のセクションを表示する。該当マッチが無いセクションは非表示。

1. Yearトーナメントのマッチ(開催中の場合)。ラウンド名(1回戦/準決勝/決勝)と決勝日を見出しに表示
2. Weekトーナメントのマッチ(開催中の場合)。複数の週のトーナメントが重なる場合は開始が早い順。見出しは「Product of the Week(2026年第37週)準決勝」のように週とラウンド名
3. スタメン(本日の予選マッチ)。全件をページネーションなしで表示

### 予選マッチの並び順

合計Upvote数(両プロダクトの和)が最も多いマッチを先頭に置き、それ以外は合計Upvote数が少ない順に並べる。注目のマッチを見せつつ、注目されていないマッチにも露出を回す意図である。同数の場合はマッチID順。並び替えはページ読み込み時に行い、閲覧中はリアルタイムに動かさない。

### マッチカード

```
┌────────────────────────────────────────────────────┐
│ [カテゴリ] キックオフ0:00→フルタイム23:40(あと5時間)      │
│ ┌────────────────┐        VS        ┌────────────────┐ │
│ │ ロゴ  名称      │                  │ ロゴ  名称      │ │
│ │ タグライン      │                  │ タグライン      │ │
│ │ [サイトを開く]  │                  │ [サイトを開く]  │ │
│ │ [▲ Upvote 12]   │ ■■■■■■■■□□□□□   │ [▲ Upvote 9]    │ │
│ └────────────────┘                  └────────────────┘ │
└────────────────────────────────────────────────────┘
```

- 各プロダクトのロゴ・名称・タグラインはプロダクト詳細ページへの導線(FR-GAME-007)
- 「サイトを開く」は外部Webサイトを別タブで開く
- Upvoteボタンは押下でトグル(Upvote/取り消し)。自身のプロダクトとその対戦相手では無効化し、理由をツールチップで示す
- 中央のバーは両者のUpvote数の比率。0対0のときは空のバー
- カテゴリ横断マッチはカテゴリを両プロダクト分表示する
- 不戦勝(対戦相手なし)は片側を「対戦相手なし(不戦勝)」の表示に置き換え、Upvoteボタンを出さない
- モバイルでは2つのプロダクトを縦に積み、VSとバーをその間に置く

## ディレクトリ

```
┌────────────────────────────────────────────────────┐
│ [検索欄(50文字以内)] [検索]                          │
│ カテゴリ: [全て▼]  期間: [全期間▼] [開始日]〜[終了日] │
│ 並び順: [関連度 | ローンチ日 | Upvote数]              │
├────────────────────────────────────────────────────┤
│ プロダクト行 × 20                                    │
│  ロゴ 名称 タグライン [カテゴリ] [サイトを開く]        │
│  勝利したマッチ: 2026-09-07の予選、12対9 / 受賞バッジ  │
├────────────────────────────────────────────────────┤
│ ページネーション(オフセット、?page=N)                 │
└────────────────────────────────────────────────────┘
```

- 期間のプリセットは「今日/今週/今月/今年/全期間」。週・月・年は基準時刻(UTC-08:00)で区切り、URLクエリには`from`・`to`(YYYY-MM-DD)へ展開して持つ
- 並び順の「関連度」は検索語がある場合のみ選択でき、検索時の既定値とする。検索語が無い場合の既定値はローンチ日の新しい順
- 1行に表示する「勝利したマッチ情報」は直近の勝利マッチ。Product of the Week/Year受賞プロダクトにはゴールドのバッジを付ける
- 20件毎のオフセットページネーション。`page`クエリの範囲外は空状態を表示する

## プロダクト詳細(`/p/{handle}`)

上から順に以下を表示する。

1. ヘッダー: ロゴ(`square-lg`)、名称、タグライン、カテゴリ、投稿者(アバター・ニックネーム)、「サイトを開く」、受賞バッジ、5段階評価の平均値と評価数、自身の評価入力
2. スクリーンショット(`screenshot-thumb`の横スクロール、クリックで`screenshot-full`をライトボックス表示)
3. 説明文(マークダウン描画)
4. マッチ履歴: 終了済みマッチ毎にUpvote数・勝敗・対戦相手を新しい順に表示。各マッチはUpvoteしたユーザー一覧(アバター・ニックネーム、早い順、20件毎の無限スクロール)を開閉できる
5. ローンチ毎のコメント: 最新ローンチを既定で展開。トップレベル10件毎のカーソルページネーション、返信は3階層までインデント
6. 通報リンク(ページ末尾、目立たせない)

投稿者本人には編集ボタンと再ローンチ予約ボタンを表示し、制限中(21日制限・トーナメント参加中など)は理由と解禁日を示す。

## ユーザー公開プロフィール(`/@{handle}`)

1. ヘッダー: アバター(`square-lg`)、ニックネーム、ハンドル、ヘッドライン、フォロワー数、フォローボタン(本人には表示しない)、外部Webサイトリンク
2. 自己紹介(マークダウン描画)
3. タブ: ローンチしたプロダクト / Upvote履歴
4. 通報リンク(ページ末尾)

フォロー中・フォロワーの一覧は本人の設定ページ内でのみ閲覧できる。

## 設定(`/settings/*`)

| パス                       | 内容                                                               |
| -------------------------- | ------------------------------------------------------------------ |
| `/settings/profile`        | ニックネーム・ハンドル・アバター・ヘッドライン・自己紹介・外部Webサイト |
| `/settings/account`        | メールアドレス変更、パスワード変更、退会                           |
| `/settings/security`       | ログイン中セッション一覧と失効、TOTP多要素認証、リカバリコード     |
| `/settings/notifications`  | 4種類の通知メールの受信可否。バウンス等による配信停止中の表示      |
| `/settings/follows`        | フォロー中・フォロワー一覧(20件毎のカーソルページネーション)       |
| `/settings/plan`           | Ultrasの状態・加入・解約、決済履歴                                 |
| `/settings/sponsorships`   | 申し込んだスポンサー広告の一覧と掲載状況                           |
| `/settings/api-keys`       | APIキーの発行・スコープ設定・引き継ぎ再発行・削除                  |
| `/settings/export`         | データエクスポートの要求とダウンロード                             |

## プロダクト登録・編集

- 必須: ロゴ、名称、タグライン、カテゴリ、ハンドル、外部WebサイトURL、説明文。任意: スクリーンショット
- ローンチ日はカレンダーで選び、選択不可の日(翌日より前、再ローンチ制限、トーナメント参加中)はグレーアウトし理由をツールチップで示す
- ハンドルはフォーカスアウト時に重複判定し、その場でエラーを表示する
- 画像は選択後に編集ダイアログ(リサイズ・トリミング)を経てアップロードする。SVGは編集ダイアログを省略する
- ペアリング後〜マッチ終了までは、ローンチ日・カテゴリの編集欄と削除ボタンを無効化し、理由を表示する

## 料金ページ(`/pricing`)

スポンサー広告の申し込みとUltrasプランの加入を1ページにまとめ、上から順に以下を表示する。

1. Ultrasプラン: 月額価格、特典(再ローンチ間隔の短縮・トーナメント参加費の免除)、自動更新と解約条件、「Ultrasに加入」ボタン。加入中は現在の状態と解約導線を表示。未加入ユーザーへのこの区画の表示は機能フラグで制御する(FR-ADMCF-018)
2. スポンサー広告: Silver/Gold/Legendの1日単価と表示位置の説明、申し込みフォーム(自身のローンチ済みプロダクトの選択、ティア、掲載開始日・終了日)、日数×単価の合計金額、「申し込む」ボタン
3. 法的通知(返金ポリシー・特定商取引法に基づく表記)へのリンク

- 未ログイン時は価格と説明のみ表示し、各ボタンはログインページへ誘導する
- 各ボタンは押下でStripe Checkout Sessionを作成し、Payment Elementの決済画面へ遷移する
- トーナメント参加費の決済はこのページには置かず、対象ローンチのプロダクト管理ページから行う(後述)

## Weekトーナメント参加費の導線

- 予選勝利の結果通知メールと、自身のプロダクト管理ページ・プロダクト詳細ページ(本人のみ)に「Weekトーナメントに参加」ボタンと決済期限を表示する
- 決済期限はユーザーのタイムゾーンでの日時と相対表現を併記する。日曜日ローンチは猶予が24時間しかないため、結果通知メール内でも期限を強調する
- Ultras加入中は「参加費免除」を表示し、ボタン押下で決済なしに参加資格を得る

## ヘルプ

- トップ: 検索欄、カテゴリ別の記事一覧(各カテゴリ内はピン留めが先頭)。各項目はタイトルとサブタイトル
- 記事詳細: カテゴリ、作成した管理者(アバター・ニックネーム、削除済みなら「削除済み」)、更新日時、目次(見出しから自動生成、PCは右側に固定、モバイルは本文冒頭に折りたたみ)、本文、同カテゴリの他記事リンク

## 問い合わせ

- フォーム: カテゴリ、メッセージ。未ログイン時はニックネームと連絡先メールアドレスも必須。ログイン時はアバターとニックネームを表示し、添付ファイル欄(合計20MB)を出す
- チャット: メッセージを時系列に表示。管理者の返信にはアバター・ニックネーム(削除済みなら「削除済み」)。添付ファイルはダウンロードリンク(インライン表示しない)

## 管理者側ページ一覧

管理者側サイトは別ドメインで、ログインにはTOTP多要素認証が必須。権限ロール(閲覧のみ/モデレーター/最上位管理者)によるメニュー・操作の制御は要件定義書の各要件を正とする。

| メニュー           | 内容                                                                     |
| ------------------ | ------------------------------------------------------------------------ |
| ダッシュボード     | 週毎の収益・ユーザー数・プロダクト数・予選実施数・Upvote数のグラフ       |
| ユーザー           | 一覧・検索(ハンドル/ニックネーム/メールアドレス/停止状態)、停止・解除    |
| プロダクト         | 一覧・検索、詳細(評価・ローンチ履歴・マッチ結果・通報件数)、非公開化・復元 |
| コメント           | 一覧・検索、非公開化・復元                                               |
| 評価               | 個別の無効化・取り消し                                                   |
| 画像モデレーション | 隔離画像の一覧、公開承認・拒否                                           |
| 通報               | 一覧・絞り込み、集約表示、対応ステータス、対象の非公開化・却下           |
| 問い合わせ         | 一覧、チャット返信、対応ステータス                                       |
| スポンサー広告     | 申し込み状況の一覧、強制終了                                             |
| ヘルプ記事         | 一覧(全件)・作成・編集・削除、ピン留め、公開状態                         |
| カテゴリ           | プロダクト・ヘルプ記事・問い合わせ・通報の各カテゴリ管理                 |
| 法務文書           | 利用規約・プライバシーポリシー・法的通知の編集と改訂履歴                 |
| 設定               | Yearトーナメント決勝日、Ultras導線の機能フラグ                           |
| 管理者アカウント   | 一覧、招待、ロール変更、削除                                             |
| 監査ログ           | 閲覧・検索                                                               |
| 自分のアカウント   | プロフィール画像・ニックネーム・肩書き、メールアドレス・パスワード変更、TOTP再設定 |

ユーザーのメールアドレス検索は監査ログに記録される旨を検索欄の近くに表示する。
