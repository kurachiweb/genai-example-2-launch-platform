# ページ構成とレイアウト

利用者側・管理者側それぞれのページ一覧と、主要ページの情報配置を定める。各ページに表示する項目や操作の規則は対応要件を正とし、本書は要件定義書に無いURL・配置・並び順・UI上の振る舞いを定める。共通コンポーネントの実装規則は`docs/GUIDES/tech/frontend`を正とする。

## URL構造(利用者側)

| パス                                                             | ページ                                                   | 備考                                                           |
| ---------------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------- |
| `/`                                                              | トップページ                                             |                                                                |
| `/directory`                                                     | ディレクトリ                                             | クエリ: `q`・`category`・`from`・`to`・`sort`・`page`          |
| `/p/{handle}`                                                    | プロダクト詳細                                           | FR-PRDCT-010。ハンドル文字列は大文字小文字を区別しない         |
| `/@{handle}`                                                     | ユーザー公開プロフィール                                 | FR-UPROF-007。同上                                             |
| `/help`                                                          | ヘルプトップ                                             | クエリ: `q`                                                    |
| `/help/{handle}`                                                 | ヘルプ記事詳細                                           | FR-HELP-007                                                    |
| `/contact`                                                       | 問い合わせフォーム                                       |                                                                |
| `/inquiries/{id}`                                                | 問い合わせチャット                                       | FR-INQRY-007により本人のみ                                     |
| `/terms`・`/privacy`・`/legal`                                   | 利用規約・プライバシーポリシー・法的通知                 | 末尾に改訂履歴(FR-ADMAG-008)                                   |
| `/pricing`                                                       | 料金ページ(スポンサー広告の申し込みとUltrasプランの加入) | 決済導線はログイン必須。Ultrasの区画は機能フラグで表示を制御   |
| `/checkout/return`                                               | 決済後ランディング(FR-PYMNT-008)                         | `elements`モードのStripe Checkoutで`return_url`に設定する      |
| `/settings/*`                                                    | 各種設定(後述)                                           | ログイン必須                                                   |
| `/my/products`・`/my/products/new`・`/my/products/{handle}/edit` | 自身のプロダクト管理                                     | ログイン必須                                                   |
| `/auth/*`                                                        | 登録・ログイン・パスワードリセット等                     |                                                                |
| `/unsubscribe/{token}`                                           | 配信停止(FR-NOTIF-009)                                   | ログイン不要。RFC 8058のPOST先(FR-NOTIF-008)はイベントサーバー |
| `/api-docs`                                                      | 公開APIのSwagger UI(NFR-MAINT-007)                       |                                                                |

URL内のハンドル文字列は大文字小文字を区別せずに解決し、正規化した表記へリダイレクトはしない。検索エンジンによる重複コンテンツ判定を避けるため、各ページは`<link rel="canonical">`により現在設定されている表記のURLを正として出力する。

### 旧ハンドルの保持とリダイレクト

保持・リダイレクト・削除時の例外はFR-USER-018・FR-UPROF-010〜012・FR-PRDCT-018〜020・FR-ADMAG-021〜023・FR-HELP-011を正とする。

運営・権限者を装うなりすまし対策として、ユーザー及びプロダクトのハンドル文字列には、以下の予約語を大文字小文字の区別無く使用できない。

`admin`・`administrator`・`root`・`superuser`・`staff`・`moderator`・`mod`・`official`・`support`・`security`・`team`・`launchstadium`・`launch-stadium`・`launch_stadium`

## 共通レイアウト(利用者側)

- ヘッダーにはロゴ(トップページへ遷移)・ディレクトリ・ヘルプ・「ローンチする」・ログイン/ユーザーメニューを表示する
- ヘッダーの「ローンチする」は未ログイン時はログインページへ、ログイン済みならプロダクト登録ページへ遷移する
- ユーザーメニュー: プロフィール、自身のプロダクト、設定、ログアウト(FR-USER-011)
- フッターにはFR-HELP-006・LR-001で定めるリンクを常に表示する
- 検索欄は共通ヘッダーに置かず、ディレクトリとヘルプの各ページ内に置く

## 外部Webサイトへのリンク

外部Webサイトへのリンクは別タブで開き、`rel`属性を表示場所ごとに次のとおり付ける。

| 表示場所                                                                             | `rel`                              | 理由                                                       |
| ------------------------------------------------------------------------------------ | ---------------------------------- | ---------------------------------------------------------- |
| 予選マッチのカード(不戦勝表示を含む)                                                 | `noopener ugc`                     | 未審査のプロダクトのため                                   |
| Week・Yearトーナメントのカード                                                       | `noopener`                         | 当該WebサイトのSEO向上を支援するため、他は意図的に付けない |
| ディレクトリ・プロダクト詳細(説明文内のリンク、本人のみ閲覧できる未掲載のものを含む) | `noopener`                         | 投票で勝ち上がったプロダクトのため                         |
| プロフィール                                                                         | `noopener`とFR-UPROF-009での指定値 | 入力の自由度の高さを考慮                                   |
| プロダクトへのコメント                                                               | `noopener`とFR-COMNT-010での指定値 | 入力の自由度の高さを考慮                                   |
| スポンサー広告                                                                       | `noopener`とFR-SPONS-009での指定値 | 明示的な広告であるため                                     |

## スポンサー広告スペース

FR-SPONS-006の広告スペースを以下の配置とする。申し込まれた広告は枚数上限を設けず全て表示する。

| ティア | 位置                         | 表示内容                            | サイズ感                                                                                    |
| ------ | ---------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------- |
| Legend | ヘッダー直下のカードグリッド | ロゴ(`square-md`)・名称・タグライン | 画面幅により2列(〜767px)・3列(768〜1279px)・4列(1280px〜)で全件を並べ、横スクロールはしない |
| Gold   | メインコンテンツ横のカード列 | ロゴ(`square-md`)・名称・タグライン | PCは幅280pxのサイドバー、モバイルは一覧の2件毎に1枚挿入し、余りは一覧の下に縦並びで表示     |
| Silver | フッター直上                 | ロゴ(`square-sm`)・名称             | 1行に複数枚を折り返し表示                                                                   |

- 広告ラベル(FR-SPONS-010)の文言は「スポンサー」とし、ティアの色で表示する
- Gold及びSilverの広告一覧末尾には、ログイン済みユーザーに限りスポンサー広告の申し込み導線(`/pricing`へのリンク)を表示する
- 広告が0件のティアはスペースごと非表示にする。ただしログイン済みなら広告申し込み導線のためにスペースを残す

## トップページ

上から順に以下のセクションを表示する。該当マッチが無いセクションは非表示。
マッチの残り時間を「時:分:秒」のカウントダウンで表示し、終了時刻も併記する。

1. Yearトーナメントのマッチ(開催中の場合)。ラウンド名(1回戦/準々決勝/準決勝/決勝)と決勝日を見出しに表示
2. Weekトーナメントのマッチ(開催中の場合)。複数の週のトーナメントが重なる場合はFR-TOURW-009の順。第◯週とラウンド名を見出しに表示
3. 予選マッチ(開催中の場合)。全件をページネーションなしで表示

### 予選マッチの並び順

合計Upvote数(両プロダクトの和)が最も多いマッチを先頭に置き、それ以外は合計Upvote数が少ない順に並べる。注目のマッチを見せつつ、注目されていないマッチにも露出を回す意図である。同数の場合はマッチID順。並び替えはページ読み込み時に行い、閲覧中はリアルタイムに動かさない。

### マッチの不戦勝表示

不戦勝(対戦相手なし、FR-GAME-003・014、FR-TOURW-015・017、FR-TOURY-015・017)はUpvoteを受け付けないため対戦カードを出さず、該当の一覧末尾「不戦勝」セクション([表記規則](003-text-and-copy-rules.md#表記規則))に当該プロダクト情報のみを表示する。予選のペアリングの余り(FR-GAME-003)は1日のローンチ数が奇数の場合に最大1件のみ生じるが、マッチ直前の対戦相手の退会等及びブラケット内の不戦勝連鎖(FR-GAME-014、FR-TOURW-015・017、FR-TOURY-015・017)は件数に上限が無い。

### マッチの早期勝利表示

マッチ中に対戦相手側で投稿者の退会・停止またはプロダクトの非公開化が発生した場合(FR-GAME-013)、Upvote受付が打ち切られてマッチが終了し、勝者となったプロダクトは進行中の対戦カードから外れる。不戦勝表示と同じく予選一覧の末尾「不戦勝」セクション([表記規則](003-text-and-copy-rules.md#表記規則))に当該プロダクト情報のみを表示する。Week・Yearトーナメントのマッチ中の早期勝利(FR-TOURW-014・FR-TOURY-014)も、該当トーナメントの一覧末尾に同様に表示する。

### マッチカード

表示項目と導線はFR-GAME-006・FR-GAME-007、Upvoteボタンの活性条件はFR-VOTE-003・FR-VOTE-005を正とする。

- カードにはカテゴリを表示する
- 「サイトを開く」は外部Webサイトを別タブで開く。`rel`属性は[外部Webサイトへのリンク](#外部webサイトへのリンク)に従う
- Upvoteボタンは押下でトグル(Upvote/取り消し)。無効化時は理由を`aria-describedby`やツールチップで示す
- 中央のバーは両者のUpvote数の比率。0対0のときは空のバー
- カテゴリ横断マッチはカテゴリを両プロダクト分表示する
- 予選及び準決勝以前のトーナメントにおいて、不戦勝のプロダクトはマッチカードとして並べず、各セクションのマッチカード一覧の下に「不戦勝」一覧としてUpvoteボタンなしで表示する
  - 対戦相手が元々いない場合(FR-TOURW-017・FR-TOURY-017)に加え、対戦相手の退会・停止・非公開化でマッチが早期終了した場合(FR-GAME-013・FR-TOURW-014・FR-TOURY-014)もこの一覧に移すと共に、終了時点で確定したUpvote数を添える
- モバイルでは2つのプロダクトを縦に積み、Upvote比率バーをその間に置く

## ディレクトリ

表示項目・絞り込み・検索・ソート・ページネーションはFR-DIR-002・FR-DIR-005〜009を正とする。

- カテゴリフィルタの既定値は「全て」
- 期間のプリセットは「昨日/今週/今月/今年/全期間」。週・月・年は基準時刻(UTC-08:00)で区切り、URLクエリには`from`・`to`(YYYY-MM-DD)へ展開して持つ
- 並び順の「関連度」は検索語がある場合のみ選択でき、検索時の既定値とする。検索語が無い場合の既定値はローンチ日の新しい順
- Product of the Week/Year受賞プロダクトにはゴールドのバッジを付ける
- 項目ごとに勝利した予選マッチ情報も表示する。複数回勝利したプロダクトは基準勝利マッチ1件の情報を表示する
  - 基準勝利は、ローンチ期間で絞り込む場合は期間内の最新の勝利、それ以外は直近の勝利とする
  - ソートキーの「ローンチ日」「Upvote数」も基準勝利の値を用いる
- `page`クエリの範囲外は空状態を表示する

## プロダクト詳細(`/p/{handle}`)

表示項目はFR-DIR-003・FR-DIR-004・FR-COMNT-003〜004・FR-RATNG-001・FR-REPOT-001を正とする。PCでは本文とサイドバー(幅320〜352px、スクロールに追従)の2カラム、モバイルでは1カラムとし、サイドバーの内容はヘッダーの直後に置く。

本文には上から順に以下を配置する。

1. パンくずリスト: ディレクトリ > カテゴリ > プロダクト名
2. 未掲載の案内(投稿者本人が未掲載のプロダクトを閲覧する場合のみ): 「このページはあなたにだけ表示されています。」と、予選で勝利すると掲載される旨
3. ヘッダー: ロゴ(`square-md`)、カテゴリ、受賞回数、名称(ページの`h1`)、タグライン、投稿者(アバター・ニックネーム・ハンドル)とフォローボタン(本人には表示しない)、「リンクをコピー」、「サイトを開く」、初ローンチ日・ローンチ回数・通算成績(◯勝◯敗)
4. 開催中のマッチ(予選・トーナメントのマッチ中のみ): トップページと同じマッチカードを置き、閲覧者を問わずその場でUpvoteできる。トップページの該当マッチと同じ演出・残り時間表示とする
5. トロフィー(受賞がある場合のみ): Product of the Yearを先頭に、Product of the Weekは受賞が新しい順にトロフィーを棚に並べ、受賞した週(表記は[表記規則](003-text-and-copy-rules.md#表記規則))または年と受賞日を添える
6. スクリーンショット(任意項目のため0枚なら区画ごと非表示): `screenshot-thumb`を高さを揃えて原本の縦横比のまま横スクロールで並べ、クリックで`screenshot-full`をライトボックス表示する。ライトボックスは前後移動ボタン・左右キー・スワイプで移動でき、「3 / 10」の位置を表示する
7. 説明文(マークダウン描画): 高さ480pxを超える場合は折りたたみ、「続きを読む」で全文を表示する
8. マッチ履歴とコメント: ローンチ単位のブロックを新しいローンチから並べる(後述)
9. 通報リンク(ページ末尾、控えめだが見つけやすい位置。本人には表示しない)

サイドバーには以下を配置する。

- 投稿者本人向けの操作(本人のみ): 「あなたのプロダクト」として破線枠で区別し、進行状況・トーナメント参加費の決済・編集ボタン・再ローンチ予約ボタンをまとめる(後述)
- 5段階評価: 平均値と評価数、自身の評価入力(星5つ)と取り消し。評価が0件なら平均値の代わりに評価がまだ無いことを示す。本人には入力欄の代わりに自身のプロダクトは評価できない旨を示す(FR-RATNG-006)

アニメーション演出は開催中のマッチに限り、それ以外は読み物として静止させる。

### マッチ履歴とコメントのローンチ単位ブロック

各ブロックの見出しには「第◯回ローンチ」、ローンチ日、結果の要約(Product of the Week・ディレクトリ掲載・予選敗北・Week準々決勝敗退・キックオフ予定など)を表示する。

- マッチは新しい順に常に表示する。各マッチには種別とラウンド(予選・Week 準決勝・Year 決勝など)、マッチ日、対戦相手、Upvote数の比率バー、「自分対相手」のスコア([表記規則](003-text-and-copy-rules.md#表記規則))、勝敗を表示する
  - 対戦相手の表示は[公開範囲仕様](#プロダクト詳細の公開範囲)に従い、「非公開のプロダクト」はロゴの代わりに汎用アイコンを表示する
  - 同数で最終Upvote時間により勝敗が決まったマッチは「接戦」として枠を強調し、最終Upvote時間により勝敗が決まった旨を添える
  - 対戦相手がいない不戦勝(FR-GAME-003等)はUpvote数を出さず「対戦相手なし」「不戦勝」と表示する
  - 早期勝敗決定による不戦勝(FR-GAME-013・FR-TOURW-014・FR-TOURY-014)は、対戦相手を「非公開のプロダクト」とし、確定時点の自身のUpvote数のみを添える(相手のUpvote数と比率バーは出さない)
  - 各マッチの「サポーター◯人」を押すと、このプロダクトにUpvoteしたユーザーの一覧(FR-DIR-004)をマッチの下に開く。高さを制限した枠内で20件ずつ無限スクロールし、退会・停止したユーザーは表示されない旨を添える(FR-DIR-011)。対戦相手側のサポーターは表示しない
- コメントはローンチ毎に開閉でき、キックオフ済みで最も新しいローンチのみ既定で展開する。キックオフ前のローンチにはコメント欄を置かず、キックオフ後にコメントできるようになる旨を示す
- マッチ履歴が0件の場合(本人が予選前の未掲載プロダクトを閲覧する場合など)は、キックオフ日と当日はトップページで対戦が始まる旨を示し、本人には「リンクをコピーして応援を呼びかける」、他者にはトップページへの導線を添える

### コメント

- トップレベルのコメントは新しい順、返信は古い順に並べ、返信は3階層までインデントで表す(FR-COMNT-002)。「さらに読み込む」で次の10件を取得する(FR-COMNT-004)
- 投稿欄はマークダウンの書式ツールバー(見出しレベル1と画像を除く、FR-MDOWN-002)、「書く/プレビュー」の切り替え(FR-MDOWN-003)、文字数カウンターを持つ。トップレベルの投稿時には任意の5段階評価を添えられる(FR-RATNG-002、本人を除く)
- 未ログインの閲覧者には投稿欄の代わりにログインへの導線を、メールアドレス未確認のユーザーには確認が必要な旨と確認メールの再送導線を表示する(FR-USER-006)
- プロダクトの投稿者本人によるコメントには「投稿者」バッジを付ける。編集済みのコメントには「(編集済み)」を表示する
- 投稿日時は「3時間前」のような相対表現で表示し、ホバー・フォーカスで完全な日時を示す。30日以上前は日付で表示する
- 返信以外の操作は「…」メニューにまとめる。自身のコメントは編集(その場で投稿欄を開く)・削除(確認ダイアログを経る)、他者のコメントは通報とする(FR-REPOT-005)
- 退会・停止・本人削除・管理者による非公開化のいずれでも、置き換え表示は「このコメントは削除されました。」に統一し、アバター・名前・日時も表示しない。停止などの事情を推測させないためである。返信はそのまま残す(FR-COMNT-007)

### 投稿者本人向けの操作

投稿者本人には編集ボタンと再ローンチ予約ボタンを表示し、進行状況を見出しで示す。

- 再ローンチ予約ボタンを無効化するのは、次回ローンチの予約自体を禁止するFR-RELCH-004・FR-RELCH-005の間のみとし、理由を併記する。解禁日が確定している場合はその日付も併記し、FR-RELCH-004でトーナメントの参加資格を得る前は決済期限を解禁日として「参加しない場合は◯日に解除」と示す([再ローンチ規則](../overview/006-relaunch-rules.md#間隔制限の解釈)、文言は[エラーメッセージ](003-text-and-copy-rules.md#エラーメッセージ))
- 予選敗北後の間隔制限中(FR-RELCH-002・FR-RELCH-003)は選べるローンチ日が制約されるだけで予約自体はできるため、ボタンは有効のまま「このプロダクトは◯日以降のローンチ日を選べます。」を併記する
- マッチ直前・マッチ中は、編集画面でローンチ日・カテゴリの変更と削除ができない旨を添える(FR-PRDCT-012)
- トーナメント参加費の決済ボタンと決済期限は[トーナメント参加費の導線](#トーナメント参加費の導線)に従う

### メールアドレス未確認のユーザー

共通ヘッダーの直下に、確認が必要な操作(評価・コメント・フォロー・Upvote)と確認メールの再送導線を示す帯を表示する。各操作は無効化して理由を併記またはツールチップで示す。

### プロダクト詳細の公開範囲

投稿者本人が閲覧する場合を除き、ディレクトリに掲載されている(FR-DIR-001)プロダクト以外には404を返す。

上記を満たす場合でも、次のいずれかに該当するプロダクトには投稿者本人による閲覧を含め常に404を返す。

- 管理者が非公開化した(FR-ADMUG-007)
- 投稿者が退会済みまたは停止中である(FR-DIR-010と同じ判定)
- 投稿者が自分で論理削除した(FR-PRDCT-011)

404の画面は、存在しない・未掲載・閲覧不可のいずれの場合も同一とし、存在や非公開の理由を推測させない。

マッチ履歴の対戦相手が上記の常に404となるプロダクトである場合、または物理削除により紐付けを解除済み(FR-PRDCT-015)の場合は、名称を出さず「非公開のプロダクト」と表示する。それ以外で404となる(未掲載の)場合は、ロゴと名称を表示しリンクさせない。

## ユーザー公開プロフィール(`/@{handle}`)

表示項目はFR-UPROF-001・FR-FOLOW-005・FR-VOTE-010・FR-VOTE-011を正とし、上から順に以下を配置する。

1. ヘッダー: アバター(`square-lg`)、ニックネーム、ハンドル、ヘッドライン、フォロワー数、フォローボタン(本人には表示しない)、外部Webサイトリンク
2. 自己紹介(マークダウン描画)
3. タブ: ローンチしたプロダクト(FR-PRDCT-016) / Upvote履歴(FR-VOTE-010)
4. 通報リンク(ページ末尾)

フォロー中・フォロワーの一覧は本人の設定ページ内でのみ閲覧できる。

### ユーザー公開プロフィールの公開範囲

管理者により停止されたユーザーの公開プロフィールは、ログインユーザー自身のプロフィールである場合を除き404を返す。

## プロダクト登録・編集

入力項目と制約はFR-PRDCT-001〜009、外部WebサイトURLの制約はNFR-SECUR-044(プロフィール設定も同じ)を正とする。

- ローンチ日はカレンダーで選び、選択不可の日(FR-PRDCT-002、再ローンチ制限)はグレーアウトし理由をツールチップで示す
- ハンドルと外部WebサイトURLはフォーカスアウト時(UI-004)に検証し、その場でエラーを表示する
- 画像は選択後に編集ダイアログ(FR-FILEU-003)を経てアップロードする。SVGは編集ダイアログを省略する
- マッチ直前・マッチ中は、ローンチ日・カテゴリの編集欄と削除ボタンを無効化し、理由を表示する(FR-PRDCT-012)。予選ではペアリング後から、トーナメントでは組み合わせ決定後または前ラウンド勝利後から、マッチ終了までが該当する
- 予選勝利後〜Weekトーナメントの組み合わせ決定前、及びWeek優勝後〜Yearトーナメントの組み合わせ決定前は削除できる。削除、または退会によるプロダクトの論理削除(FR-PRDCT-013)の時点で参加資格を得ていた場合は、参加資格を失い(FR-TOURW-021・FR-TOURY-021)、決済した参加費は自動で全額返金される(FR-PYMNT-009)
- 掲載中・掲載予定のスポンサー広告があるプロダクトの削除確認には、広告が終了して返金されない旨を表示する(FR-SPONS-016)

## 料金ページ(`/pricing`)

スポンサー広告の申し込みとUltrasプランの加入を1ページにまとめ、上から順に以下を表示する。

1. Ultrasプラン: 月額価格、特典、自動更新と解約条件、「Ultrasに加入」ボタン。加入中は現在の状態と解約導線を表示。未加入ユーザーへのこの区画の表示は機能フラグで制御する(FR-ADMCF-018)
2. スポンサー広告: Legend/Gold/Silverの1日単価と表示位置の説明、申し込みフォーム(自身のローンチ済みプロダクトの選択、ティア、掲載開始日・終了日)、日数×単価の合計金額、「申し込む」ボタン
3. 法的通知(返金ポリシー・特定商取引法に基づく表記)へのリンク

- 未ログイン時は価格と説明のみ表示し、各ボタンはログインページへ誘導する
- 各ボタンは押下でFR-PYMNT-001の決済画面へ遷移する
- トーナメント参加費の決済はこのページには置かず、対象ローンチのプロダクト管理ページから行う(後述)

機能フラグ(FR-ADMCF-018)がオフの場合、このページは404を返す。

### 決済前の最終確認画面

決済画面(Stripe Payment Element)の入力欄より上に、特定商取引法12条の6に基づき次の事項を表示する。

- 分量・販売価格(税込)・支払方法(FR-PYMNT-001の決済手段)及び時期・役務の提供時期
- 申込みの期間に定めがある場合は、その旨と期間
- 申込みの撤回及び解除に関する事項([返金ポリシー](../legal/004-legal-notice-outline.md#返金ポリシー)の要旨)
- 役務の即時提供への同意と、提供開始により撤回権(EU・英国の消費者の14日間)を失う旨の了知を求めるチェックボックス。居住地を問わず表示し、未チェックの間は決済を確定できない

Ultrasプラン加入の決済画面ではこれに加えて、自動更新である旨・毎月の請求額・解約方法を表示する。

## トーナメント参加費の導線

決済画面には[決済前の最終確認画面](#決済前の最終確認画面)と同様の事項を表示し、申込みの期間は下記の決済期限とする。

### Weekトーナメント

- 予選勝利の結果通知メールと、自身のプロダクト管理ページ・プロダクト詳細ページ(本人のみ)に「Weekトーナメントに参加」ボタンと決済期限を表示する
- 決済期限はユーザーのタイムゾーンでの日時と相対表現を併記する。UIに表示する時刻はFR-TOURW-002の決済セッション作成期限とする([理由](../overview/002-pricing-and-plans.md#ui表示において決済期限を35分早める理由))。日曜日ローンチは猶予が短い([Weekトーナメント規則](../overview/004-week-tournament-rules.md#参加資格と日程))ため、結果通知メール内でも期限を強調する。期限まで残り48時間未満では、ページ上の期限表示を注意色で強調し「時:分:秒」の秒読みを添える
- Ultras加入中はFR-TOURW-003により自動的に参加資格を得るため、ボタンの代わりに「参加費免除」の状態表示を行い、参加のための操作は不要とする(免除条件は[トーナメント参加費の免除条件](../overview/002-pricing-and-plans.md#トーナメント参加費の免除条件)を参照)
- Ultras未加入者には決済ボタンの下に、Ultrasなら参加費が免除され敗北後は2日で再ローンチできる旨と料金ページへのリンクを添える。表示は機能フラグ(FR-ADMCF-018)に従う
- 決済サービスの障害時(縮退運転)は決済ボタンを無効化し、ボタンの近くに「現在ご利用いただけません」と閲覧やその他の操作は利用できる旨を表示する

### Yearトーナメント

- Week優勝(決勝勝利)の結果通知メール(FR-NOTIF-002)と、自身のプロダクト管理ページ・プロダクト詳細ページ(本人のみ)に「Yearトーナメントに参加」ボタンと決済期限を表示する
- 決済期限はユーザーのタイムゾーンでの日時と相対表現を併記する。UIに表示する時刻はFR-TOURY-002の決済セッション作成期限とする([理由](../overview/002-pricing-and-plans.md#ui表示において決済期限を35分早める理由))。Week優勝から決済期限までは次回Yearトーナメント決勝日の設定次第で最長63週空く([Yearトーナメント規則](../overview/005-year-tournament-rules.md#決勝日と日程))ため、ボタンと期限表示はWeek優勝直後から決済完了または期限到来まで表示し続ける
- Ultras加入中はFR-TOURY-003により自動的に参加資格を得るため、ボタンの代わりに「参加費免除」の状態表示を行い、参加のための操作は不要とする(免除条件は[トーナメント参加費の免除条件](../overview/002-pricing-and-plans.md#トーナメント参加費の免除条件)を参照)
