# 法律及びコンプライアンス準拠方針

要件定義書の法的要件(LR-001〜013)・データ要件(DR-001〜026)を、本サービスのどの機能・運用で満たすかを整理する。法令の条文解釈や汎用的なプライバシー実務は本書の対象外とし、法務レビューの前提資料として用いる。

## 前提

| 項目         | 方針                                                                                                                           |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| 準拠法・管轄 | 日本法に準拠し、東京地方裁判所を第一審の専属的合意管轄裁判所とする                                                             |
| 利用年齢     | 18歳以上。登録時の利用規約同意に年齢要件の表明を含め、生年月日は収集しない(DR-001)                                             |
| UI言語       | 日本語のみ。法務文書も日本語で提供する                                                                                         |
| 通貨         | USD(I18N-003)                                                                                                                  |
| 事業者情報   | 事業者名・所在地・連絡先メールアドレスは法的通知ページと、全てのメールの末尾の送信者情報(FR-ADMCF-024・FR-NOTIF-010)に記載する |

## 通知メールのオプトアウト(LR-005)

受信設定の初期値、送信者情報の設定と表示、配信停止手段、トークン、バウンス・苦情・拒否時の自動除外はFR-ADMCF-024・FR-NOTIF-008・FR-NOTIF-010〜012・016〜018・FR-NOTIF-022〜023を正とする。

| 項目               | 方針                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象               | FR-NOTIF-001・004・006・007の4種類(マッチ開始予告・勝敗結果・フォロー中ユーザーのマッチ開催・受賞結果)                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 対象外             | それ以外の通知メール ... 取引・運営上必要な通知                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 同意               | 受信設定の初期値はすべて受信しない(オプトイン、FR-NOTIF-008)。利用者が通知設定ページで種類ごとに受信を選んだ時点を同意とし、受信可否と最後に変更した日時を受信設定に保存する                                                                                                                                                                                                                                                                                                                                                    |
| 撤回の手段         | 次の3つで、どれも通知種別ごとに受信を停止する。(1)通知設定ページ(`/settings/notifications`、ログイン必須)のスイッチ。(2)メールソフトのワンクリックの配信停止(RFC 8058の`List-Unsubscribe`・`List-Unsubscribe-Post`、ログイン不要、FR-NOTIF-012)。(3)本文の配信停止のリンクから開く配信停止のページ(`/unsubscribe#token=<トークン>`、ログイン不要、確認のボタンで停止、FR-NOTIF-016)。勝敗結果と翌日のマッチ開始予告を統合したメールは、本文に両方のリンクを置き、ワンクリックの配信停止は勝敗結果を停止する(notificationsの仮4) |
| 配信停止のトークン | 利用者と通知種別の組ごとに1つ発行し、利用者が退会するまで有効とする(受信の停止・再開やアカウントの停止の間も変えない、FR-NOTIF-017・018)。退会の確定と同時に無効にする。保存するのはトークンを導出する種と照合用のハッシュだけで、平文はメールのURLでだけ示す。トークンで行えるのはその組の通知種別の受信の停止だけで、再開と設定の閲覧はできない                                                                                                                                                                               |
| 送信者情報         | 最上位管理者が管理画面で設定し(FR-ADMCF-024)、全てのメールの末尾に表示する。未設定の間は通知メールを送らない(FR-NOTIF-011、notificationsの仮3)。管理画面の送信者情報の区画に未設定のため送信していない旨を表示し、運営者がエラートラッキングで検知する                                                                                                                                                                                                                                                                          |

退会後も保持するデータ: 監査ログ(3年、仮名化IDのみ)、決済履歴(7年、仮名化IDのみ)、匿名化したコメント、匿名化したマッチ記録。仮名化ID(FR-USER-004)は本プロジェクトのデータベース内でユーザー主キーと外部キー関係を持たず、物理削除後はデータベース内の情報のみでは個人を識別できない。

ただしStripe側では、税務上の記録保存義務によりCharge・PaymentIntent・Invoiceが氏名・メールアドレス等をCustomerとは独立したスナップショットとして保持期間中保持し続ける。退会ユーザーの物理削除時にStripe Customerオブジェクト自体を削除しても、これらのスナップショットは消えない。一括削除機能(Redaction Jobs)は返金・異議申立ができなくなるため採用しない。

## データの保存場所(DR-012)

プライバシーポリシーに保存先を明示する。保存場所の値(管轄)は[本プロジェクト固有の値](../../../onboardings/project-values.md#workerとリソースの名前と識別子)を正とし、変更時はプライバシーポリシーの改訂履歴に記録する。

| データ                                         | 保存先                     | 保存場所                                                   |
| ---------------------------------------------- | -------------------------- | ---------------------------------------------------------- |
| アカウント・投稿・決済履歴等                   | Cloudflare D1              | 米国(管轄の指定により保証する)                             |
| 画像・添付ファイル・エクスポート               | Cloudflare R2              | 米国(管轄の指定により保証する)                             |
| アプリケーションログ                           | Cloudflare Workers Logs    | 保証しない(所在を限定しない処理)                           |
| レート制限カウント(一時的)                     | Cloudflare Durable Objects | 保証しない(所在を限定しない処理。ハッシュ化した一時的な値) |
| 通知・エクスポート等のジョブメッセージ(一時的) | Cloudflare Queues          | 米国(管轄の指定により保証する)                             |

委託先ごとの保存場所は次のとおりとする。1つの箇条に1つの委託先を`- **<委託先>(<サービス>)**: <保存または一時送信の場所>。<委託先側での保存の有無>。移転の根拠はプライバシーポリシー骨子の<委託先>の項を正とする。`の形で書き、[委託先の一覧](003-privacy-policy-outline.md#委託先の一覧)の順に並べる。上の表はCloudflareの資源ごとの一覧とし、他の委託先は表へ行を足さず箇条だけを足す。

- **Cloudflare(Workers・D1・R2・Queues・Durable Objects・Email Sending・Turnstile・Web Analytics)**: D1・R2・Queuesは米国の管轄で保存する(値は[本プロジェクト固有の値](../../../onboardings/project-values.md#workerとリソースの名前と識別子)を正とする)。所在を限定しない処理(Durable Objects・Workerの実行・画像配信のエッジのキャッシュ・Workers Logs・メール送信(Email Sending)・bot判定(Turnstile)・アクセス解析(Web Analytics))は保存場所を保証せず、Cloudflareの各地のデータセンターで行われ得る。サービス上の全データをCloudflare側で保存する。移転の根拠はプライバシーポリシー骨子の[Cloudflareの項](003-privacy-policy-outline.md#cloudflareworkersd1r2queuesdurable-objectsemail-sendingturnstileweb-analytics)を正とする。
- **Stripe(決済)**: 米国。メールアドレス・仮名化ID・購入の内容を送り、氏名・請求先住所・カード情報などは購入者がStripeへ直接渡す。決済の記録をStripe側で保存し、退会ユーザーの物理削除の後も税務上の保持期間中は残る([データ主体の権利への対応](#データ主体の権利への対応lr-006))。移転の根拠はプライバシーポリシー骨子の[Stripeの項](003-privacy-policy-outline.md#stripe決済)を正とする。
- **AWS(Rekognition)**: 米国東部(us-east-1)。判定用画像を一時送信し、判定サービス側では保存しない。移転の根拠はプライバシーポリシー骨子の[AWSの項](003-privacy-policy-outline.md#awsrekognition)を正とする。
- **Google Cloud(Natural Language API)**: 検索のキーワード抽出の対象のテキストを、処理のリージョンを指定せずに一時送信するため、処理する場所は保証しない。Google側では保存しない。移転の根拠はプライバシーポリシー骨子の[Google Cloudの項](003-privacy-policy-outline.md#google-cloudnatural-language-api)を正とする。

外部サービスへ一時送信する情報と保持しない旨は[委託先の一覧](003-privacy-policy-outline.md#委託先の一覧)を正とする。

## Cookieとトラッキング

- 認証Cookie(NFR-SECUR-001)を使用する。サービス提供に必須のため同意バナーを表示しない
- 決済画面で読み込むStripe.jsは不正検知(Stripe Radar)のため、本サービスのドメインへファーストパーティCookieとして設置する。[カードテスティング](https://docs.stripe.com/disputes/prevention/fraud-types#card-testing)等の不正決済防止に必須の措置で、同意バナーの対象外である
  - `__stripe_mid`(デバイス識別用、有効期間1年)、`m.stripe.com`へ定期送信する
  - `__stripe_sid`(決済セッション識別用、有効期間30分)
- Cloudflareのbot対策・チャレンジ(Turnstile・WAF等)により、本サービスのドメインへ次のCookieが設置され得る。不正アクセス防止に必須の措置で、同意バナーの対象外である([Cloudflareの一覧](https://developers.cloudflare.com/fundamentals/reference/policies-compliances/cloudflare-cookies/))
  - `__cf_bm`(bot判定用、無操作30分で失効)
  - `cf_clearance`(チャレンジ通過の記録用、有効期間はChallenge Passage設定に従う)
- アクセス解析はCloudflare Web Analytics(SW-006、Cookie・個人識別子を使用しない)を用いる
- 広告トラッキングとリターゲティングは行わず、広告・解析目的のサードパーティCookieも使わない
- Stripe Payment Elementでカード入力欄を表示するiframeは、Stripeが設定するサードパーティCookieを扱う。決済に必須のため、同意バナーの対象外である

(注7) 抑止記録は、通知メールを送らない宛先の記録である。照合用のメールアドレス(小文字)・最後の契機の種類と日時・期限だけを持ち、配信不能イベントに含まれる件名や配送サーバーの応答を保存しない。同じメールアドレスに新しい契機が届くと最後の契機と期限を更新し、期限なしの抑止は期限付きに戻らない。退会の処理での物理削除は、退会から14日以内(DR-002)に行う。利用者に登録済みかを確かめられない日は、利用者に紐づかない記録を削除しない。利用者に登録済みかの確認は、毎日照合用のメールアドレスの昇順で1,800件までとし、前日に確かめた続きから再開して、末尾まで確かめたら先頭に戻る。そのため、利用者に登録済みの記録が多くても全ての記録を数日かけて必ず一巡し、最後の契機から1年を過ぎた利用者に紐づかない記録は、1年を過ぎた後の確認の一巡のうちに削除する。続きの位置として、前日に最後に確かめた照合用のメールアドレスを1件だけ保持する。退会の処理で削除するメールアドレスが続きの位置であれば、続きの位置も同時に消して先頭に戻す。ただし退会の処理と確認の処理が同時に動き、確認の処理が退会の処理の後に続きの位置を保存した場合は、次に確認できた日の処理で上書きするまで残る。利用者に紐づかないことを確かめて削除した記録や期限切れで削除した記録のメールアドレスは、次の確認の起点として、次に確認できた日の処理で上書きするか先頭に戻すまで続きの位置に残る。

(注8) 同じメールを重複して送らないための記録で、送信要求の識別子・メール種別・送信側が渡した冪等のキー(措置の記録のIDなど、個人を表さない業務上の識別子)・送信日時だけを持ち、宛先・件名・本文を持たない。14日は、重複して届き得る送信要求をQueuesが保持する期間の上限である。

(注9) 利用者が利用規約・プライバシーポリシーに同意した日時から、その時点で公開されていた版を特定するため、公開した版は本文ごと削除せずに残す。公開した管理者のIDは管理画面にだけ表示し、利用者側の改訂履歴には表示しない。

(注10) 通知の記録は、同じ通知を重複して送らないための記録で、宛先の利用者のID・通知種別・対象のマッチやプロダクトの識別子・送った・送らなかった理由と日時を持ち、宛先のメールアドレス・件名・本文・トークンを持たない。通知イベントは他の機能が発行したマッチや受賞の識別子だけを持つ。

(注11) 措置の記録は、管理画面に最新の停止・非公開化の理由を表示し、送れなかった措置の通知メールを送り直すための記録である。理由は監査ログと同じく管理者が入力した500文字以内の文で、利用者や管理者の個人情報を含めない旨を入力欄に注記する。対象の利用者は利用者のIDで持ち、監査ログ(対象を仮名化IDで持つ)と異なり、利用者の物理削除の時に削除する。保持期間は監査ログと同じ3年とする。メールアドレス・検索文字列・通知メールの本文は持たない。

(注12) 週ごとの統計は、管理画面のダッシュボードに運営状況の推移を示すための記録である([週ごとの統計](../features/006-content-moderation.md#週ごとの統計))。週の開始日・5つの指標の集計値・確定の印・集計の日時だけを持ち、利用者・プロダクト・決済を識別できる情報を含まないため、退会と物理削除の対象とせずに無期限に保持する。物理削除で消えた利用者・プロダクトがあっても、確定した週の値は変えない。

(注13) 通報は、運営が対応を判断し、申出者へ対応結果を知らせるための記録である([通報の運用](../features/007-content-reporting.md#保持期間))。停止中のユーザーの通報は、ユーザーに結び付けずに未ログインユーザーの通報として扱う(content-reportingの仮6)。送信元IPアドレスは保存せず、未ログインユーザーの連絡先メールアドレスは対応結果の通知の宛先にだけ使い、管理画面・監査ログ・ログに表示しない。通報の対象のユーザー・プロダクトが物理削除された後も、通報と案件は対象への参照を消して残す。参照を消した案件は削除されたユーザー・プロダクト・コメントの識別子を持たないため、申出者の理由をそのユーザーの記録と結び付けられない。申出者の理由は申出者自身の申告で、データエクスポートで本人へ返す記録でもあり、削除された投稿者を指す記述を機械的に判別して消せないため書き換えず、管理画面と申出者自身のデータエクスポートにだけ示す。3年は監査ログの保持期間と同じで、案件に対応した操作の記録と突き合わせられる期間に合わせた。

## モデレーションと透明性

- 停止・非公開化は理由付きで行い投稿者へ通知する(FR-ADMUG-030)。監査対象の管理者操作は監査ログに記録し、対象ユーザーは仮名化IDで記録する(FR-ADMAG-001〜003)
- 停止解除・復元・評価の無効化の取り消しも理由を必須とし、画像の公開承認・公開拒否・個別の隔離・隔離の解除は任意の理由とともに監査ログに記録する(ugc-moderationの仮7・仮9)。措置の種類と波及の分担は[コンテンツモデレーションの運用](../features/006-content-moderation.md)を参照
- 運営者による代理の退会(FR-ADMUG-051)は、最上位管理者だけが管理画面のユーザー一覧の項目から理由を付けて行い、利用者本人の退会と同じ処理でデータを削除する。退会の依頼の受け付け・本人の意思の確かめ・退会の完了の知らせは、運営者がシステムの外のメールで行い、システムからはメールを送らない(ugc-moderationの仮4・仮5)。セッションが切れた停止中の利用者など、自分で退会できない利用者の消去の権利(LR-006)に応えるための手段である
- 通報は同一コンテンツの未完了の案件に集約し(FR-ADMUG-027、content-reportingの仮1)、繰り返し通報による過剰対応を防ぐ。措置・却下は理由付きで行い、申出者(と却下では投稿者)へ通知する。投稿者への通知と照会には申出者を特定できる情報と申出者の理由を含めない。権利侵害の申出の手順は[侵害コンテンツ削除請求フロー](005-rights-infringement-takedown-flow.md)、通報の規則は[通報の運用](../features/007-content-reporting.md)を参照

## 法務文書の改訂

利用規約・プライバシーポリシー・法的通知の編集と改訂履歴の表示はFR-ADMAG-007・008・010を正とする。画面の配置は[ページ構成の法務文書](../design/002-page-layouts.md#法務文書termsprivacylegal)と[管理画面の法務文書](../design/002-page-layouts.md#法務文書legal-documents)を参照。

- 下書きと公開: 最上位管理者が管理画面で本文を下書きとして保存し、変更概要を添えて公開する。下書きは利用者側に表示されず、公開した時点で直ちに最新版として表示される。施行日時を予約して公開する機能は設けない
- 過去版の掲示: 公開した版は変更・削除できず、公開ページの改訂履歴(版番号・公開日・変更概要)と、過去の各版のページ(`/{文書のパス}/revisions/{版番号}`)に本文ごと掲示し続ける。改訂履歴に公開した管理者は表示しない
- 記録: 法務文書の操作は監査ログに記録せず、公開した管理者と公開日時を版に記録する。利用者の同意日時から、その時点で公開されていた版を特定できる
- 周知: 重要な変更を利用者へ通知する機能は設けない。周知期間を設ける必要がある変更は、公開に先立ってピン留めしたヘルプ記事(フッターに表示される、FR-HELP-006)などで告知する運用とし、要否は法務レビューで判断する
- 初版の公開: stagingとprodでは、3文書の初版を公開するまで公開ページに「この文書は準備中です。」を表示する。prodの初版は本番公開の前に開発者が管理画面で公開する。プライバシーポリシーの初版の公開の前に、本文がCloudflareのTurnstile Privacy Addendumを参照していることを確かめる([プライバシーポリシーの大枠の記載上の注意](003-privacy-policy-outline.md#記載上の注意))
