# Product of the Year決定トーナメント規則

年間のProduct of the Week受賞プロダクト同士が、シングルエリミネーション方式でProduct of the Yearを決めるトーナメントである。本書では「トーナメント」と書けばYearトーナメントを指す。
規則そのものはFR-TOURY-001〜030・FR-ADMCF-001〜003・006・007を正とし、組み合わせ方式は[Weekトーナメント規則](004-week-tournament-rules.md)と共通部分が多いため、本書は差分と具体例を中心に記す。時刻は全て基準時刻(UTC-08:00)である。

## 決勝日と日程

決勝日の設定規則はFR-ADMCF-001〜003・006・007、参加資格と決済期限はFR-TOURY-001・004・005、トーナメント組み合わせ決定までに決済を反映できなかった場合の返金はFR-PYMNT-014、組み合わせ決定前のプロダクト削除・退会による参加資格の喪失はFR-TOURY-030(返金はFR-PYMNT-010)、組み合わせ決定の時点の非公開化・停止と参加数の上限(64)を超えた分による参加資格の停止はFR-TOURY-010・011(返金はFR-PYMNT-011)、1回戦の実施日はFR-TOURY-014、組み合わせ決定から決勝までの日程は[年次タイムライン](007-daily-timeline.md#年次タイムラインyearトーナメント)を正とする。

- FR-TOURY-001の対象判定はWeekトーナメントの優勝(決勝勝利)日時を基準とする。ローンチ週の翌週月曜23:35の決済期限を経て組み合わせが決まるため、優勝日時はローンチ週の翌週以降になり、参加数が多いWeekトーナメントではさらに後ろ倒しになる
- FR-RELCH-004([再ローンチ規則](006-relaunch-rules.md))により、1つのプロダクトが同一年のYearトーナメントに複数の資格で参加することはない
- 組み合わせ決定から1回戦までに空白日が生じる場合(N≤32)、その間はマッチが行われない。空白日中もWeekトーナメントや予選は通常通り行われる

### 決勝日と期限

対象年(決勝日を含む年。画面では「2027年」のように表記する)ごとに、決勝日Dを最上位管理者が設定した日曜日、設定が無ければ対象年5月の最終日曜日(既定の日)とする(FR-ADMCF-001・006)。期限と日程は決勝日を起点とする1つの規則で求め、画面・メール・決済・判定のどこでも同じ日時を使う。決勝日の6日前を決済期限日と呼ぶ。

| 時点           | 日時                                                                         | 対応要件          |
| -------------- | ---------------------------------------------------------------------------- | ----------------- |
| 変更期限       | D − 7日(日)0:00。これ以降は決勝日を変更できない                              | FR-ADMCF-007      |
| 受付期限       | D − 6日(月)23:00。決済の開始の締め切りで、UIには決済期限としてこの時刻を示す | FR-TOURY-004      |
| 決済期限       | D − 6日(月)23:35                                                             | FR-TOURY-004      |
| 組み合わせ決定 | D − 6日(月)23:45                                                             | FR-TOURY-009      |
| 1回戦          | 参加数に応じてD − 5日〜D([シード数の決定](#1-シード数の決定)の表)            | FR-TOURY-014      |
| 決勝           | D(日)。[ラウンドの遅れ](#ラウンドの遅れの回復)があれば遅らせた後の日         | FR-TOURY-024・025 |

決勝日が変更されたら、以後の期限・組み合わせ決定の時刻・対象期間・画面とメールに示す期限・[再ローンチ規則](006-relaunch-rules.md)の禁止の解除の日時を、変更後の決勝日から求め直す。

### 決勝日の設定

最上位管理者は、管理画面の設定ページ([ページ構成](../design/002-page-layouts.md#管理者側の設定settings))で、選べる日付の一覧から年ごとの決勝日を選び、確認を経て保存する。2026-10-24に開発者が確定した仮8により、次の規則とする。

- 設定できる対象年は、現在の年(UTC-08:00)とその翌年の2つとする
- 選べる日付は、対象年内の日曜日で、その日の0:00が現在から8日後以降のものに限る(FR-ADMCF-001・002)
- 前年の決勝日が設定されていると扱われ([前年の決勝日と初年度](#前年の決勝日と初年度))、指定した日付が前年の決勝日の64週間後以降である場合は選べない(FR-ADMCF-003)
- 翌年の決勝日が設定済みで、それが指定した日付の64週間後以降になる場合も選べない。翌年が未設定で、翌年の既定の日が指定した日付の64週間後以降になる場合は拒否せず、翌年の決勝日の設定を促す注意を表示する
- 変更期限以降と、その年の組み合わせ決定が始まった後は変更できない(FR-ADMCF-007)
- 設定を既定の日に戻す操作は設けない。既定の日を選んで保存できる
- 保存は、操作した管理者・対象年・変更前後の日付・500文字以内の任意の理由・日時を記録する監査ログ(操作種別「Yearトーナメント決勝実施日の変更」)と一体で確定する。画面を表示した後に別の管理者が同じ対象年を変更していた場合は、保存を拒否して最新の内容を読み直すよう案内する
- 選べる日付と検証の規則はサーバーの1か所に持ち、保存の時もサーバーが同じ規則で検証し直す。画面の一覧から外れた日付・日曜日でない日付・対象年の外の日付・8日後より前の日付・現在の年と翌年以外の対象年の保存は、サーバーが理由を返して拒否する

### 前年の決勝日と初年度

前年のYearトーナメントを開催した、または開催する予定(前年の組み合わせ決定がまだ来ていない)なら、前年の実効の決勝日(未設定なら既定の5月の最終日曜日)を「前年の決勝実施日が設定されている」と扱う(FR-TOURY-002、2026-10-24に開発者が確定した仮1)。前年に開催しなかった(本サービスの運営の開始前に前年の組み合わせ決定の時刻を過ぎた)ときだけ「設定されていない」と扱い、その年を初年度とする。管理者が明示的に設定した日だけを設定済みとする扱いは採らない。

### 対象期間と対象年

- Week優勝の日(Product of the Week賞の授与が確定した日)が、前年の決済期限日以降で、今回の決済期限日の前日以前であれば、その年のトーナメントの対象とする(FR-TOURY-001)。決済期限日の当日に確定したWeek優勝は翌年の対象とする
- 初年度は期間の起点を設けず、それまでに開催したYearトーナメントの対象にならなかった全てのWeek優勝を対象とする(FR-TOURY-003)
- 参加の枠は対象年を保存せず、組み合わせ決定を始めていない年のうち、決済期限日がWeek優勝の日より後の最も早い年を対象年とする。決勝日の変更で対象期間が変わっても、組み合わせ決定を始めていない枠は変更後の対象期間で判定し直し、既に得た参加資格は変えない

### 参加の枠と参加資格

Week優勝が確定するごとに、確定から数分以内にそのWeek優勝の参加の枠を作る。枠はWeek優勝の週と日時、受賞したローンチとそのローンチ日、そのローンチの予選勝利時のUpvote数と最終Upvote時間を確定した値のまま持ち、1つのWeek優勝に1つだけ作る。

| 枠の状態     | 意味                                                                                                                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 受付中       | 参加資格を得ていない。決済期限までの参加費の決済、またはUltrasの特典による免除で参加資格を得る                                                                                                           |
| 参加資格     | 参加費の決済またはUltrasの特典で参加資格を得た。Ultrasの解約や支払いの失敗による特典の終了で参加資格を失わない                                                                                           |
| 組み合わせ済 | 組み合わせ決定で組み合わせに入った                                                                                                                                                                       |
| 期限切れ     | 組み合わせ決定の時点で参加資格を得ていなかった。組み合わせ決定が始まった後に処理された、その対象期間のWeek優勝(遅れて届いたWeek優勝)の枠も同じ扱いとし、運用者がエラートラッキングで検知できるようにする |
| 喪失         | 組み合わせ決定の前の削除・退会、または組み合わせ決定の時点の論理削除で参加資格を失った(FR-TOURY-030)                                                                                                     |
| 除外         | 組み合わせ決定の時点の非公開化・停止(FR-TOURY-010)、または参加数の上限(64)を超えたこと(FR-TOURY-011)で参加資格を停止した                                                                                 |

- Week優勝の確定の時点で投稿者がUltrasの特典を受けられれば、決済を求めずにその時点で参加資格を与える(FR-TOURY-006)。Week優勝の確定の後、決済期限より前にUltrasへの加入が有効になれば、受付中の枠に参加資格を与え、その投稿者の未完了の参加費の決済を失効させる(FR-TOURY-007・FR-PPLAN-008)。決済期限の後の加入では、その年のトーナメントの参加資格を与えない
- 既に決済で得た参加資格の参加費は、後からUltrasに加入しても返金しない(FR-PPLAN-009)
- 決済期限の後に反映された決済は、そのローンチより新しい同じプロダクトのローンチ(取り消していないもの)が予約されていれば、参加資格を与えずに自動で全額返金する(FR-TOURY-008・FR-PYMNT-017、2026-10-24に開発者が確定した仮6)。参加資格を得る前の再ローンチの禁止は決済期限で解除されるため([再ローンチ規則](006-relaunch-rules.md))、解除の後に予約した新しいローンチと参加資格が並ばないようにする。新しいローンチが無ければ、組み合わせ決定(23:45)までに反映された決済に参加資格を与える。組み合わせ決定(23:45)より後に支払われた決済は決済の機能が反映の期限切れとして返金し(FR-PYMNT-014)、23:45より前に支払われても凍結の後に反映された決済は、Yearトーナメントの機能が参加資格を付与できないと答えて返金になる(FR-PYMNT-017)
- 組み合わせ決定の前に投稿者がプロダクトを個別削除するか退会すると、枠は参加資格を失い、以後は決済・Ultrasのどちらでも参加資格を与えない。参加費を決済していれば自動で全額返金し(FR-PYMNT-010)、個別削除では未完了の参加費の決済を失効させる
- 参加資格の有無は、Product of the Week賞・予選勝利によるディレクトリ掲載・既に授与した賞を変えない

### 組み合わせ決定の時点の凍結

決済期限日の23:45の組み合わせ決定は、決済の突合(23:40)・当日のマッチの確定・同じ時刻のWeekトーナメントの組み合わせと進行の後に行う([同時刻に走る処理の順序](007-daily-timeline.md#同時刻に走る処理の順序))。まず対象期間のWeek優勝に枠が無ければ枠を作り(Week優勝の知らせの処理が遅れた場合の補完)、次にその年のトーナメントを凍結する。凍結の後は、決済の反映・Ultrasの加入・削除・退会・Week優勝のどれが届いても、その年の枠の参加資格を変えない。凍結と同時に起きた変更で組み合わせの対象が揺れないようにするためである。凍結の後に処理されたその対象期間のWeek優勝は、期限切れの枠として記録する。凍結の後は次の順に行う。

1. 受付中と参加資格の枠を分類する。参加資格を得ていない枠の投稿者が、Week優勝の確定から決済期限までの間にUltrasの特典を受けられる状態だった場合は参加資格を与える。それ以外の受付中の枠は期限切れにする
2. 参加資格の枠のうち、プロダクトが論理削除済みなら喪失、非公開化中または投稿者が停止中なら除外とし、残りを組み合わせの対象にする
3. 対象が64を超えれば、[参加数の上限](#参加数の上限64)により超えた分を除外する
4. [組み合わせ決定の手順](#組み合わせ決定の手順)で組み合わせを決め、1回戦のマッチの予定を作る。参加数0なら賞を授与せずに終え、参加数1なら即時に受賞とする。組み合わせに入った枠と除いた枠の結果を枠ごとに記録する
5. 喪失・除外の枠の参加費を決済していれば、自動で全額の返金を依頼し、投稿者へ返金の旨と理由をメールで知らせる(退会済みには送らない)

組み合わせ決定が途中で中断しても、次の実行が凍結済みの続きから行い、組み合わせと返金を重ねない。障害で決済期限日の23:45に組み合わせ決定を行えなかった年も、次の実行が曜日によらず同じ手順で行う。

### 参加数の上限(64)

FR-TOURY-012により2回戦の参加数Pは最大32であり、参加数は64以下でなければならない。参加数65以上は、組み合わせ決定の翌日から決勝日までの6日間に7ラウンドを収められない。決勝日の間隔を64週未満に保つ設定の制約([決勝日の設定](#決勝日の設定))があっても、Week優勝の日は参加数に応じて週ごとに最大9日ほどずれ、初年度は対象期間の起点が無く、翌年の決勝日が未設定のまま既定の日になる場合もあるため、参加数は64を超え得る。

組み合わせ決定の時点で参加資格を得た表示できるプロダクトが64を超えたら、Week優勝の日時が新しい順に64件を組み合わせの対象とし、残りを組み合わせから除いてそのトーナメントの参加資格を停止する(FR-TOURY-011、2026-10-24に開発者が確定した仮2)。初年度・決勝日の間隔・Week優勝の日の偏りのどれで超えても同じ扱いにする。予選勝利時のUpvote数の多い順・参加を受け付けた順に選ぶ扱いは採らない。組み合わせ決定を再実行しても同じ枠を選ぶ。

### 非公開化・停止・上限による除外と返金

組み合わせ決定の時点でプロダクトが非公開化中、または投稿者が停止中なら、そのプロダクトを組み合わせから除き、そのトーナメントの参加資格を停止する。組み合わせ決定の後に復元・停止解除があっても、そのトーナメントには加えない(FR-TOURY-010、2026-10-24に開発者が確定した仮3)。マッチの開始時点までの復元を待って相手の不戦勝にする扱いは採らない。

非公開化・停止と参加数の上限で除外したプロダクトの参加費を決済していれば、自動で全額返金する(FR-PYMNT-011、2026-10-24に開発者が確定した仮4)。停止は利用者の規約違反によるものでも事業者側の都合であり、上限による除外は参加者の責めによらないため、[返金ポリシー](../legal/004-legal-notice-outline.md#返金ポリシー)の「組み合わせ決定の時点のユーザー停止やプロダクト非公開化に伴うトーナメント参加資格停止」と「Yearトーナメントの参加数の上限(64)を超えたことに伴うトーナメント参加資格停止」の行に従う。一方、組み合わせ決定の後の停止・非公開化・退会によるマッチの不戦敗(FR-TOURY-022・023)は、参加資格を使い始めた後の結果であるため、返金ポリシーの「トーナメントの不戦勝・不戦敗・両者敗北」の行に従い返金しない。

返金を依頼したときは、返金の旨と理由(組み合わせ決定前の削除、組み合わせ決定の時点の非公開化・停止、参加数の上限)を投稿者へメールで知らせ、退会済みの利用者には送らない(2026-10-24に開発者が確定した仮7。[文言](../design/003-text-and-copy-rules.md#yearトーナメントの返金の知らせの本文))。返金の依頼は同じ枠について1回だけ行い、依頼に失敗しても日次の再処理で依頼し直す(FR-PYMNT-012)。返金できる残額が既に無いと決済の機能が答えた購入(管理者による返金の後など)は返金済みとして依頼を終え、依頼の形式の誤りで拒否された購入は日次の再処理の対象から外す。どちらも運用者がエラートラッキングで検知できるようにし、返金の知らせのメールは送らない(2026-11-17に開発者が確定したG4。Weekトーナメントと同じ扱い)。返金の実行・決済履歴への反映は決済の機能が行う([決済実装方針](../features/004-payments.md#返金の分担))。

## 組み合わせ決定の手順

### 1. シード数の決定

[Weekトーナメントの手順](004-week-tournament-rules.md#1-シード数の決定)と同じだが、FR-TOURY-012により2回戦の参加数Pには上限32を設ける。

N = 33〜64のとき、Pは上限の32となる。N=64ではS=0のため全プロダクトが1回戦から対戦し、N=33ではS=31のためほぼ全てがシードとなる。

| N   | P   | S   | 1回戦マッチ数 | 2回戦参加数 | 1回戦実施日 |
| --- | --- | --- | ------------- | ----------- | ----------- |
| 1   | —   | —   | —             | —           | 即時受賞    |
| 2   | 1   | 0   | 1             | —           | 決勝日      |
| 3   | 2   | 1   | 1             | 2           | 1日前       |
| 13  | 8   | 3   | 5             | 8           | 3日前       |
| 20  | 16  | 12  | 4             | 16          | 4日前       |
| 32  | 16  | 0   | 16            | 16          | 4日前       |
| 33  | 32  | 31  | 1             | 32          | 5日前       |
| 40  | 32  | 24  | 8             | 32          | 5日前       |
| 64  | 32  | 0   | 32            | 32          | 5日前       |

### 2. シードの選出

Weekトーナメントの手順([シードの選出](004-week-tournament-rules.md#2-シードの選出))と同じ。ここでの「予選」は、Product of the Week受賞に至ったローンチの予選である。

### 3. 非シードの1回戦組み合わせ

FR-TOURY-013により非シードをローンチ日が早い順に並べ、隣接する2個ずつを対戦相手とする。Yearトーナメントの参加プロダクトは異なる週のWeek優勝者であるためローンチ日は重複しないが、実装上の安全策として同日の場合は[Weekトーナメントと同じタイブレーク](004-week-tournament-rules.md#3-非シードの1回戦組み合わせ)を適用する。

### 4. 2回戦以降

Weekトーナメントの手順([2回戦](004-week-tournament-rules.md#4-2回戦の組み合わせ)、[3回戦以降](004-week-tournament-rules.md#5-3回戦以降))と同じ。

## ラウンドの進行

各トーナメントマッチは実施日の0:00に開始し23:40に終了する(FR-TOURY-015)。あるラウンドの全マッチの結果が確定したら、実施日の23:45までに次ラウンドのマッチの予定を翌日に作る(FR-TOURY-024)。予定はマッチの確定の直後と23:45の2つの経路から作り、どちらが先に動いても、何度動いても1回分の予定になる。各マッチにはラウンドの番号と、該当すれば準々決勝・準決勝・決勝の段階を記録する。

### ラウンドの遅れの回復

障害により次ラウンドの予定を実施日の0:00までに作れなかった場合は、そのラウンドの実施日を、予定を作った時点の翌日に遅らせ、以降のラウンドも1日ずつ遅らせる(FR-TOURY-025)。このため決勝が決勝日の後になり得る。遅れは運用者がエラートラッキングで検知できるようにする。トップページの区画とブラケットのページの決勝日・実施日は、遅らせた後の日を示す。

例えば[上記の例](#組み合わせの例n--13)で、2026-05-22(金)の準々決勝の予定を同日0:00までに作れず05-22の0:10に作った場合、準々決勝は05-23(土)、準決勝は05-24(日)、決勝は決勝日の翌日の05-25(月)に行う。

## 勝敗判定・不戦勝・参加数が少ない場合

Weekトーナメント(FR-TOURW-014〜016・018〜021・023〜026)と同一の規則をFR-TOURY-017〜019・021〜024・026〜029で定める。解説は[Weekトーナメント規則](004-week-tournament-rules.md#各マッチの勝敗判定)を参照。

## 終了と賞

決勝で勝者が確定するか、あるラウンドの参加数が1になればトーナメントを終え、そのプロダクトにProduct of the Year賞を授与する(FR-TOURY-027・029)。あるラウンドの参加数が0になるか、同じラウンドの全プロダクトが敗者になれば、賞を授与せずに終える(FR-TOURY-028)。賞は1つの対象年に1回だけ授与し、対象年・受賞日時・受賞したローンチを記録する。

## ブラケットのページ

組み合わせを決定した対象年ごとに、ログイン不要の公開のブラケットのページ(`/tournaments/year/{年}`、例: `/tournaments/year/2027`)を設け、トップページのYearトーナメントの区画と決勝の区画、プロダクト詳細ページのトロフィー、組み合わせに入った枠の参加費の導線から導く(2026-10-24に開発者が確定した仮5)。トップページの区画はその日のラウンドだけを示し、ブラケットのページが組み合わせと結果の全体を示す。

- ラウンドごとにマッチを並べ、対戦するプロダクト・シードの番号・Upvote数・勝敗・不戦勝・実施日と、受賞したプロダクト(または受賞なし)を示す
- まだ予定を作っていないラウンドの枠は「シード3」「1回戦第3試合の勝者」のように、どこから勝ち上がる枠かを示す
- 表示できないプロダクト(非公開化・論理削除・投稿者の退会や停止)は「非公開のプロダクト」として名前とリンクを出さない
- 4桁の年でない指定・存在しない年・組み合わせを決定していない年は404とする
- 画面の構成は[ページ構成](../design/002-page-layouts.md#yearトーナメントのブラケットtournamentsyear年)を正とし、Weekトーナメントのブラケットのページと同じ表示の規則に従う

## Weekトーナメントとの差分まとめ

| 項目                   | Weekトーナメント                             | Yearトーナメント                                     |
| ---------------------- | -------------------------------------------- | ---------------------------------------------------- |
| 対象                   | 同一週の予選勝利ローンチ                     | 対象期間内のWeek優勝プロダクト                       |
| 参加数上限             | なし(129以上で翌週と重複)                    | 64。超えた分はWeek優勝の日時が古い順に除外(仮2)      |
| 2回戦参加数Pの上限     | なし                                         | 32                                                   |
| 組み合わせ決定         | 翌週月曜日23:45                              | 決勝日の6日前(月曜日)23:45                           |
| 1回戦                  | 組み合わせ決定の翌日(火曜日)                 | 参加数に応じて決勝日から逆算                         |
