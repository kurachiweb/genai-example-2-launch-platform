# トーナメントのブラケットの表示

単一敗退のトーナメントの組み合わせと結果の全体を、トーナメントの種類によらず同じ部品で表示する規約を定める。サーバーでの表示の組み立て(位置と枠の表し方)、GraphQLの型と親の値の置き換え、種類によらない画面の4つの部品、ラウンドの列とタブ、横スクロールの領域、開催中だけの定期再取得と自動更新の切り替え、APIサーバーの深さの上限とフラグメントの扱い、及びテストを扱う。

ブラケットの形・組み方・記録・進行は「[単一敗退のブラケット](../backend/017-single-elimination-brackets.md)」に、定期再取得の共通の値と止める手段は「[表示中の画面の定期再取得](010-live-refresh-queries.md)」に、自動更新の切り替えは「[集計値と残り時間を表示し続ける画面](013-live-scoreboard.md#自動更新の切り替え)」に、見出し・ランドマーク・タブの操作は「[アクセシビリティ規則](004-accessibility-rules.md)」に、ルートの`loader`と取得の補助は「[データ取得](006-data-fetching.md)」に、操作とフラグメントの置き場所は「[GraphQL通信](../coding/004-graphql-communication.md#操作の置き場所と名前)」に従う。

## 前提と用語

部品の置き場所は、`<APIサーバーのアプリ>`と画面のアプリの`src/`からのパスで示す。`<ドメイン>`は種類によらないブラケットの部品のディレクトリの名前、`<種類>`はトーナメントの種類ごとに置き換える。参加の対象は、参加者が持ち込む集約(作品・チームなど)を指す。

| 部品                                                                            | 置き場所                                                                                                                                               | 役割                                                                                                                     |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `buildBracketRoundsView`                                                        | `<APIサーバーのアプリ>`の`application/<ドメイン>/bracket-view-builder.ts`                                                                              | ブラケットの記録と対戦の表示から、ラウンド・位置・枠の表示の形を作る純粋な関数                                           |
| ラウンド・位置・枠のGraphQLの型                                                 | 種類ごとのスキーマモジュールの`type-defs.ts`・`mappers.ts`                                                                                             | 表示の形をそのまま返す型と、親の値の置き換え                                                                             |
| ラウンドと優勝した参加の対象のフラグメント                                      | 画面のアプリの`graphql/fragments/bracket/`                                                                                                             | 種類によらない部品の引数の型                                                                                             |
| `BracketRoundColumn`・`BracketRoundTabs`・`BracketMatchCard`・`BracketChampion` | 画面のアプリの`components/bracket/`                                                                                                                    | ラウンドの列・ラウンドのタブ・位置の対戦・優勝                                                                           |
| 表示の判定と文言                                                                | 画面のアプリの`components/bracket/bracket-view-model.ts`・`bracket-messages.ts`                                                                        | 枠の描き分け・勝敗・対戦の状態・既定のタブ・優勝の状態                                                                   |
| `TournamentBracketPage`・`TournamentBracketError`                               | 画面のアプリの`components/<ドメイン>/`                                                                                                                 | 種類によらないブラケットのページの本体(見出し・参加数とシード数・自動更新の切り替え・優勝・列とタブ)と、取得の失敗の表示 |
| 開催中の判定・取り直しの間隔・文言の型                                          | 画面のアプリの`components/<ドメイン>/`(`isTournamentBracketLive`・`tournamentBracketRefetchIntervalOf`・`bracketViewPropsOf`・`TournamentBracketCopy`) | ブラケットの値から開催中と取り直しの間隔を決め、種類ごとの文言の形を定める                                               |
| ブラケットのページの経路と包み                                                  | 画面のアプリの`components/<種類>/`と`routes/<ブラケットのページのパス>`                                                                                | 種類ごとの照会・文言・期間の表記・head・自動更新の状態                                                                   |

| 用語               | 意味                                                                                                 |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| 位置               | ラウンドの中の1つの対戦の場所。対戦の予定を作る前は対戦を持たない                                    |
| 枠                 | 位置の2つの側のそれぞれ                                                                              |
| 未来の枠           | まだ参加者が決まっていない枠。シードの枠か、前のラウンドの位置の勝者が入る枠                         |
| 空の枠             | 誰も入らないと確定した枠。対戦の相手がいない不戦勝の側                                               |
| 予定前の枠         | 参加者は決まっているが、その位置の対戦の予定をまだ作っていない枠                                     |
| 表示できない参加者 | 対戦はあるが、非公開化・論理削除・保有者の停止や退会・紐付けの解除のために参加の対象を示せない参加者 |
| 開催中             | トーナメントが終了していない間。結果と集計値が変わり得る                                             |

本文中の`<列とタブを切り替える画面幅>`などのプレースホルダーの本プロジェクトの値は、技術ドキュメントに写さず、プロジェクト固有の値の文書「[本プロジェクト固有の値](../../../onboardings/project-values.md)」に置く。

## 表示の組み立て

`buildBracketRoundsView({ record, matchViews, now })`は、ブラケットの記録(形・参加者・位置)と、記録済みの対戦のIDから対戦の表示への対応から、ラウンドの一覧を作る。種類ごとの照会は記録と対戦の表示を読んで渡すだけにし、組み立てを写さない。

- 関数は種類によらない部品に置き、種類ごとの部品とデータベースの実装を読み込まない。静的解析の規則(`no-restricted-imports`)で、組み立てのファイル・テスト・補助から種類ごとの部品への読み込みを禁じる。
- 表示の形は、形だけから求めた全ての位置の出どころ(「[表示用の配置](../backend/017-single-elimination-brackets.md#表示用の配置)」)と、記録した位置を照らして作る。進行の規則と同じ組み方を写さない。

### ラウンドと実施日

- 開催中は形の全てのラウンドを、終了したブラケットは最後に記録したラウンドまでを並べる。位置が1つも残らないラウンドは並べない。参加0・1はラウンドを並べない。
- ラウンドの実施日は、記録した位置の実施日の最大にする。記録の無いラウンドは、記録した1回戦の日と日程の方針(現在時刻を渡して作り直す)で、前のラウンドの翌日(遅れの後は現在の業務日付の翌日以降)とする。1回戦の日の無いブラケットに記録の無いラウンドがあれば`RangeError`にする。
- ラウンド名は共用部品のラウンド名の規則で、ラウンドの枠の数から求める。

### 位置と枠の表し方

枠は、抽選番号・シードの番号・未来の枠の表記・参加の対象・集計値・結果の6つの値で表す。

| 位置と枠の状態                                           | 抽選番号 | シード        | 未来の枠の表記                                 | 参加の対象・集計値・結果 |
| -------------------------------------------------------- | -------- | ------------- | ---------------------------------------------- | ------------------------ |
| 対戦のある位置の側                                       | あり     | S以下なら番号 | なし                                           | 対戦の表示の側の値       |
| 予定前の位置のシードの枠                                 | あり     | 番号          | シードの表記(「シード3」など)                  | なし                     |
| 予定前の位置の非シードの枠                               | あり     | なし          | なし                                           | なし                     |
| 勝者が確定した前の位置から入る枠(予定前)                 | あり     | S以下なら番号 | 勝ち上がる元の表記(「1回戦第3試合の勝者」など) | なし                     |
| 勝者がまだ決まっていない前の位置から入る枠               | なし     | なし          | 勝ち上がる元の表記                             | なし                     |
| 空の枠(相手のいない不戦勝の側・両者敗北の位置から入る枠) | なし     | なし          | なし                                           | なし                     |

- 位置を挿入して予定を作る前の位置は、紐付けを解除した参加者を除いて側を詰めているため、側の順でなく抽選番号で配置の出どころを選んで表記を付ける。
- 記録の無い位置は、そのラウンドの予定を作り終えた(後のラウンドに記録があるか、そのラウンドに予定の作成の途中でない位置がある)なら、両側が空と確定した位置として並べない。予定を作る前のラウンドでも、両側が空の位置は並べない。
- 対戦があり、その側の参加の対象が無い(null)枠は表示できない参加者である。
- 優勝は、ブラケットの結果が優勝のときだけ優勝の参照から抽選番号を求めて返す。

### GraphQLの型

ラウンド・位置・枠のGraphQLの型は、表示の形の項目をそのまま公開する。コード生成の設定の`mappers`で、3つの型の親の値を表示の形の型に置き換え、リゾルバは親の値の項目を読むだけにする。種類ごとの照会は組み立ての結果の`rounds`をそのまま返せる。

## 画面の部品

種類によらない4つの部品は、ラウンドのフラグメントの型(`readonly <ラウンドのフラグメント名>Fragment[]`)と優勝した参加の対象のフラグメントの型を引数に取る。種類ごとの型と文言を読み込まない。賞の名前など種類で変わる文言は、呼び出し元から受け取る。

| 部品                 | 要素と見出し                                                       | 内容                                                       |
| -------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------- |
| `BracketRoundColumn` | `section`と`h2`(ラウンド名と実施日)、位置の`ol`                    | 1つのラウンドの位置を縦に並べる                            |
| `BracketRoundTabs`   | タブの一覧(名前は「ラウンド」などの画面に見えない文言)とタブの中身 | ラウンドをタブで切り替え、中身に`BracketRoundColumn`を描く |
| `BracketMatchCard`   | `article`と`h3`(ラウンド名と位置)、2つの側の一覧                   | 対戦の状態、各側のシード・参加の対象・集計値・勝敗         |
| `BracketChampion`    | `section`と`h2`(賞の名前)                                          | 優勝した参加の対象、表示できない優勝、受賞なし             |

- 見出しの階層は、ページの`h1`、優勝とラウンドの`h2`、位置の`h3`にする。見出しとタブの操作で、キーボードと読み上げで全ての位置をたどれる。
- 実施日は業務日付で示し、閲覧者のタイムゾーンで日をずらさない。日付だけを示す部品で`<time datetime>`に業務日付を入れる。
- 列の中の位置は縦に散らして並べ(`justify-around`)、後のラウンドの位置が前のラウンドの対になる2つの位置の間に来るようにする。
- 参加の対象の名称は、公開中の対象なら対象の詳細のページへのリンクにし、表示できない参加者は汎用のアイコンと表示できない旨の固定の文言にしてリンクを出さない。

### 枠の描き分け

枠は次の順に判定して描く(`slotDisplayOf`)。

1. 未来の枠の表記があれば、表記を描く。表記がシードを示すため、シードの印を重ねない。
2. 抽選番号が無ければ、空の枠(「対戦相手なし」など)を描く。
3. 位置に対戦が無ければ、予定前の枠として抽選番号の表記(「抽選番号5」など)を描く。
4. 参加の対象が無ければ、表示できない参加者を描く。
5. それ以外は、参加の対象の画像と名称を描く。

- 勝敗は、側の結果の勝利を勝利、不戦勝と相手の退場による勝利を不戦勝、敗北のうち対戦の決着が票なし・両者の不戦敗のものを両者敗北、それ以外の敗北を敗北にする。
- 対戦の状態は、対戦が無ければ予定、あれば対戦の段階(予定・受け付け中・集計中・確定)をそのまま示す。
- 集計値の数値の前に、支援技術にだけ項目の名前を伝える。

### 既定のタブと優勝の状態

- 既定のタブは、確定していない位置を持つ最初のラウンドにし、全て確定していれば最後のラウンドにする。ラウンドが無ければタブを描かない。
- 優勝の区画は、受賞したなら優勝した参加の対象(参加の対象が無ければ表示できない優勝)を、受賞せずに終えたなら受賞なしを描き、終了の前は何も描かない。参加1でラウンドが無い受賞も同じく描く。

### 種類ごとのページと共用の本体

ページの本体(`TournamentBracketPage`)と取得の失敗の表示(`TournamentBracketError`)は種類によらない部品にし、種類ごとのページは照会・文言・期間の表記を渡す包みにする。

- 種類ごとの文言(題名・賞の名前・参加数とシード数の文・失敗の文)は、文言の型(`TournamentBracketCopy`)の値として種類のディレクトリに置き、本体は種類の文言を読み込まない。ページのheadの題名は本体が描かないため文言の型に含めず、種類のディレクトリの関数として経路の`head`から使う。
- 本体は、種類の照会の結果のブラケットが満たす構造の型(`TournamentBracketPageView`)を受ける。種類の照会の結果の型を本体に持ち込まない。
- 見出しに添える基準の日(決勝の日など)のように、種類によって有無が変わる表示は、本体に任意の受け口を足す。受け口を省いた種類の表示を変えないことを、本体のブラウザテストで確かめる。
- 経路の`loader`・`head`・`errorComponent`・`notFoundComponent`と、自動更新の状態(`useState`)は種類ごとの経路に置く。
- 本体のテストは架空の種類の文言とブラケットの値のフィクスチャで行い、種類の文言を読み込まない。種類ごとのページのテストは、種類の照会と文言が本体に渡ることを確かめる。

## 列とタブ

画面幅`<列とタブを切り替える画面幅>`以上はラウンドを列にして左から順に横に並べ、それ未満はラウンドをタブで切り替えて1列で示す。

- サーバーの描画で画面幅を知らずに済むよう、列とタブの両方を描き、CSSで片方を隠す。どちらも同じラウンドの値から描く。
- 列は、名前付きの横スクロールの領域(`section`に`aria-label`、`overflow-x: auto`)に入れ、ページ全体を横にスクロールさせない。列の幅は下限を持つグリッドの列(`grid-flow-col`と`auto-cols-[minmax(<列の最小幅>,1fr)]`)にする。
- 横スクロールの領域は`tabIndex={0}`でフォーカスできるようにする。列の中にリンクの無い表示(未来の枠など)だけが並ぶ場合も、キーボードで横にスクロールできるためである。フォーカスの輪郭を領域に描く。
- 横スクロールの領域を配置の基準(`relative`)にする。読み上げ専用の文言の絶対配置が領域の外を基準にすると、ページ全体が横にスクロールする。

## 開催中だけの定期再取得

ブラケットのページは、開催中だけ`<定期再取得の間隔>`ごとに取り直し、自動更新の切り替えを置く。終了したトーナメントは結果と集計値が変わらないため、取り直さず、切り替えも置かない。

```typescript
const { data } = useSuspenseQuery({
  ...bracketQueryOptions(viewer, key),
  ...LIVE_REFRESH_QUERY_OPTIONS,
  refetchInterval: (query) =>
    tournamentBracketRefetchIntervalOf(query.state.data?.bracket, autoRefresh),
  refetchOnWindowFocus: (query) =>
    isTournamentBracketLive(query.state.data?.bracket),
  refetchOnMount: false,
});
```

- 開催中の判定は取得した値(トーナメントの状態)で行う(「[取得した値による判定](010-live-refresh-queries.md#取得した値による判定)」)。
- 開催中の判定と取り直しの間隔は、種類によらない部品の関数(`isTournamentBracketLive`・`tournamentBracketRefetchIntervalOf`)にブラケットの値(照会の結果の中のブラケット)を渡して求める。照会の結果の形は種類ごとに違うため、関数は照会の結果を受けない。
- 自動更新の切り替えはオンから始め、オフの間は定期の取り直しだけを止め、画面へ戻ったときの取り直しは続ける。
- 切り替えの説明(`aria-describedby`で結び付ける文)は、このページが取り直すもの(ブラケット)だけに触れる文言を切り替えの部品の引数で渡す。他のページと共有する切り替えの既定の説明が残り時間や演出に触れていても、ブラケットのページはそれらを持たないためである。
- `loader`はパスの引数の形式を、フロントエンドとバックエンドの共用部品の解析(APIサーバーの照会も同じ関数で確かめる)で確かめ、形式に合わない値は照会せずに404にする。画面とAPIサーバーに同じ形式の正規表現を別々に書かない。開催中は表示中に取り直すため、`loader`は鮮度を0にして毎回新しく取得し、部品は表示した時点では取り直さない(`refetchOnMount: false`)。照会の結果がnull(組み合わせ前など)なら404にし、部品が取り直しでnullを受けたときも同じ404の画面にする(「[loaderとの組み合わせ](010-live-refresh-queries.md#loaderとの組み合わせ)」)。
- 同じ経路のまま別のトーナメントへ移ったときに、既定のタブと自動更新の状態を初めから作り直すよう、ページの部品をパスの引数ごとに作り直す(`key`)。

## APIサーバーの深さの上限とフラグメント

ブラケットの照会は、照会の項目・ラウンド・位置・枠・参加の対象・参加の対象の入れ子の項目と深い。フラグメントの展開もAPIサーバーの深さの上限の1段に数えるため、ラウンドのフラグメントを照会から展開すると1回の展開でも上限を超える(「[操作の置き場所と名前](../coding/004-graphql-communication.md#操作の置き場所と名前)」)。

1. ラウンドと優勝した参加の対象のフラグメントのファイルは置き、コード生成でフラグメントの型だけを作る。種類によらない部品はこの型を引数に取る。
2. 種類ごとの照会には、ラウンドのフラグメントと同じ項目を直接書く。浅い位置の項目(優勝した参加の対象など)だけフラグメントを展開する。照会のファイルに、直接書く理由とテストの場所をコメントで残す。
3. 照会の結果の型とフラグメントの型の一致を、単体テストの`expectTypeOf<…>().toEqualTypeOf<…>()`で固定する。フラグメントか照会の一方だけを変えると型検査で落ちる。

```typescript
test('ブラケットのラウンドと優勝した参加の対象は、共用の2つのフラグメントの型と一致する', () => {
  type Bracket = NonNullable<ClientBracketQuery['bracket']>;

  expectTypeOf<
    Bracket['rounds'][number]
  >().toEqualTypeOf<BracketRoundFieldsFragment>();
  expectTypeOf<
    Bracket['champion']
  >().toEqualTypeOf<BracketMatchProductFieldsFragment | null>();
});
```

- 種類を加えるときも同じ手順で照会を書き、既存のフラグメントと部品を使う。

## テスト

- 表示の組み立ては単体テストで、参加0・1・2・3・8・13のブラケットについて、予定前・開催中・終了の各時点のラウンドの並び、枠の表し方の表の各行、両側が空の位置の除外、紐付けを解除した参加者を除いた予定前の位置の表記、記録の無いラウンドの実施日(遅れの後を含む)、終了の後のラウンドを並べないことを確かめる。
- 表示の判定は単体テストで、枠の描き分けの順、勝敗と対戦の状態の対応、既定のタブ、優勝の状態を確かめる。
- 4つの部品はブラウザテストで、見出しの階層と名前、枠の各表示、表示できない参加者にリンクが無いこと、タブの切り替え、アクセシビリティの自動検査の違反が0件であることを確かめる。
- ブラケットのページはブラウザテストで、画面幅ごとに列とタブのどちらが見えるか、横スクロールの領域の名前とフォーカス、開催中だけの切り替えと定期の取り直し、終了したトーナメントで取り直さないこと、形式に合わない引数とnullの404を確かめる。
- 照会の結果とフラグメントの型の一致は、上の単体テストで固定する。
