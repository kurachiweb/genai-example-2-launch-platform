# 管理画面の検索と措置の操作

管理画面で利用者・投稿・コメント・ファイルなどの対象を検索して一覧し、停止・非公開化・無効化・隔離などの状態を変える操作(措置)を確認のダイアログから行う画面の規約を定める。検索条件をURLのクエリで保つ正規化と、APIの入力への変換、一覧の取得と失敗の表示、措置の操作を対象と理由の入力と変化の有無の結果にそろえること、確認のダイアログ(理由の要否・監査ログの記録・影響の示し方・失敗の表示)、確定の後の照会の無効化と結果の知らせ、ロールによる出し分け、個人情報の検索の注記、隔離中の画像と利用者の入力の表示、及びテストを扱う。

URLのクエリで条件を持つ一覧の一般の規約は「[URLのクエリで条件を持つ一覧](014-url-state-listing.md)」に、取得の補助と`loader`・カーソルで区切る一覧の前後のページは「[データ取得](006-data-fetching.md)」(特に「[失敗を画面の中で表示する取得](006-data-fetching.md#失敗を画面の中で表示する取得)」)に、画面シェル・ロールによる出し分け・失敗の文言の選び方は「[管理画面のシェルと区画](009-admin-console-shell.md)」に、共通部品の`ConfirmActionDialog`・`AdminDataTable`・`PageNavigation`は「[共通化する部品](005-shared-components.md)」に、APIサーバーの側の記録の確定は「[集約をまたぐ管理操作の記録](../backend/021-cross-aggregate-admin-action-records.md)」に従う。

## 前提と用語

TanStack Router・TanStack Query v5・TanStack Startを前提とする。部品の置き場所は、共通部品の配置先・共用部品の配置先と、管理者側のアプリの`src/`からのパスで示す。`<ドメイン>`は措置の機能のディレクトリの名前、`<対象>`は一覧の対象(`users`・`comments`など)に置き換える。

| 部品                                                                                                      | 置き場所                                                                                  | 役割                                                                                                   |
| --------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 措置の種類の定義(対象の種類・理由の要否・通知の要否)                                                      | 共用部品の`<ドメイン>/<ドメイン>-actions.ts`                                              | 画面とAPIサーバーが共有する措置の規則                                                                  |
| 状態・理由の表示名                                                                                        | 共用部品の`<ドメイン>/<ドメイン>-labels.ts`                                               | 上流の値(小文字)から表示名を引く                                                                       |
| 検索パラメータの型と正規化(`to<対象>Search`・`<対象>ListArgsOf`・`<対象>SearchAt`・`<対象>FilterScopeOf`) | `components/<ドメイン>/shared/<ドメイン>-search.ts`                                       | URLのクエリを検索条件にそろえ、APIの入力と前後のページの位置を作る                                     |
| 一覧の取得と変換・措置の操作の設定・照会の無効化                                                          | `graphql/admin-<ドメイン>-<対象>.ts`                                                      | 生成物の型を画面の型へ変え、ルートの`loader`と措置の操作の設定を提供する                               |

| 措置の実行のフック                                                                                        | `components/<ドメイン>/shared/use-<ドメイン>-mutation.ts`                                 | 措置の操作の実行・影響する照会の無効化・結果の知らせ                                                   |
| 措置の確認のダイアログ                                                                                    | `components/<ドメイン>/shared/<ドメイン>-action-dialog.tsx`                               | `ConfirmActionDialog`に措置の定義の理由の要否と監査ログの記録を渡す                                    |
| 措置の確認のダイアログの置き場所                                                                          | `components/<ドメイン>/shared/<ドメイン>-dialog-host.tsx`・`<ドメイン>-dialog-context.ts` | 一覧の単位に確認のダイアログを1つ置き、行の操作に開く関数を文脈で渡す                                  |

| 最新の措置の理由                                                                                          | `components/<ドメイン>/shared/<ドメイン>-note.tsx`                                        | 状態の日時と最新の措置の理由を、利用者の入力として文字列で示す                                         |
| 文言                                                                                                      | `components/<ドメイン>/shared/<ドメイン>-messages.ts`                                     | 見出し・列・絞り込み・確認・成功・変化なし・状態の文言(単体テスト付き)                                 |

| 用語         | 意味                                                                                                                             |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 措置         | 管理者が対象の状態を変える操作。監査ログと措置の記録を残す                                                                       |
| 措置の種類   | `<対象の種類>.<動詞>`の形の、APIサーバーと共有する種類(`user.suspend`など)。理由の要否・通知の要否・対象の種類を定義に持つ       |
| 画面の操作   | 確認と結果の文言を選ぶ単位。原則は措置の種類と同じで、同じ措置を別の文言で行う操作(公開の拒否を削除の措置で行うなど)だけを加える |
| 検索条件     | 一覧の絞り込みの項目(検索語・状態・期間など)の組。ページの位置(`after`)を含まない                                                |

本プロジェクトの一覧の名前・検索語の上限・1ページの件数・措置の種類と文言は、技術ドキュメントに写さず、プロジェクト固有の値の文書「[本プロジェクト固有の値](../../../onboardings/project-values.md)」とサービスの文言規則に置く。

## 検索条件の保持

検索条件とページの位置は検索パラメータに持ち、URLを共有・再読み込みすると同じ一覧を開ける。一覧ごとに、Zodのスキーマ(Zodは共通部品の`utilities/validation/zod.ts`の`z`から読む)で検索パラメータを検索条件の型へそろえる関数を置き、ルートの`validateSearch`に渡す。

```typescript
const USER_SEARCH_SCHEMA = z.object({
  handle: searchTerm,
  email: emailTerm,
  status: oneOf(USER_STATUS_VALUES),
  after: cursor,
});

// ルーターは検証の結果をURLの元の値に重ねるため、元の値を残さないよう常に全ての項目を返す
export const toUserSearch = (search: Record<string, unknown>): UserSearch => {
  const { handle, email, status, after } = USER_SEARCH_SCHEMA.parse(search);
  return { handle, email, status, after };
};
```

- 不正な値(手で書き換えたURL・古い共有のURL)は、項目ごとに`.catch(undefined)`で未指定にする。APIの拒否でページ全体を失敗させない。
- 検索語は前後の空白を除き、APIサーバーの検索語の上限の書記素数で切り詰め、空なら未指定にする。ルーターの既定のクエリの解析は数の形の値を数として渡すため、数も文字列へ戻して受ける(「[ルーターの既定のクエリの解析](014-url-state-listing.md#ルーターの既定のクエリの解析)」)。
- メールアドレスは前後の空白を除き、上限の長さを超えれば未指定にする。列挙の値は許可した値の一覧に含まれるときだけ受け、IDはAPIサーバーと同じ形式(大文字のULIDなど)のときだけ受ける。
- 期間の開始日と終了日は暦の日付の形のときだけ受け、開始日が終了日より後ならAPIが拒否するため両端とも未指定にする。APIへは、日時の表示と同じ閲覧者の地域の暦で、開始日の0時を含み終了日の翌日の0時を含まない範囲に変える。
- 既定の値(タブの既定の選択など)はURLに書かない。既定の値と同じ値を受け取ったら未指定にする。
- ページの位置は空でなく長さの上限以下の文字列だけを受け、形式の検証はAPIサーバーの`invalid_cursor`に任せる。
- URLを作るときは、値の無い項目を持たない検索パラメータにする。条件を保ったままページの位置だけを替える`<対象>SearchAt(search, after)`と、ページの位置を除いた条件を項目の順によらない1つの文字列にする`<対象>FilterScopeOf(search)`を置き、前後のページの記録の条件に使う(「[失敗を画面の中で表示する取得](006-data-fetching.md#失敗を画面の中で表示する取得)」)。
- 絞り込みの変更は、ページの位置を外して1ページ目に戻す。

## 一覧の取得

- ルートは`validateSearch`・`loaderDeps`・`loader`・`head`・`component`だけを持ち、ページの部品は`components/pages/`に置く。`loaderDeps`は検索条件から作るAPIの入力の型(`<対象>ListArgsOf(search)`)で、生成物の型に依らない。
- `loader`は`graphql/admin-<ドメイン>-<対象>.ts`の読み込みの関数で、取得の失敗を`.catch(() => undefined)`で握ってキャッシュに残す。ページの部品は`useQuery`で読み、失敗を一覧の中の再試行で示す。同じ画面の中の遷移で待たず、直前の結果を残す(「[loaderと再読み込みの間](014-url-state-listing.md#loaderと再読み込みの間)」)。
- 詳細のページの`loader`は、IDの形式の誤りと`null`の結果で`notFound()`を投げる。
- 変換は、GraphQLの列挙(大文字)を共用部品の上流の値(小文字)へ写し、画面の型を表示名の表から引ける形にする。未知の値は`null`にする。部品は生成物の型に直接依存しない(「[操作の置き場所](006-data-fetching.md#操作の置き場所)」)。
- ページ・画像・最新の措置の理由・利用者の要約は、対象によらない共通の変換(`admin-<ドメイン>-shared.ts`)で同じ形にそろえる。

## 措置の操作

措置ごとのGraphQLの変更の操作は、変数の名前と結果の項目が違う。`graphql/`の変換で、全ての措置を「対象のIDと理由」の入力と「変化の有無」の結果にそろえた操作の設定にし、画面からは措置の種類だけで呼べるようにする。

```typescript
export interface ModerationActionInput {
  readonly targetId: string;
  readonly reason: string;
}

export interface ModerationOutcomeView {
  // 偽は既に同じ状態だった
  readonly changed: boolean;
}

export function moderationActionOptions<TResult, TVariables>(definition: {
  readonly document: PersistedDocument<TResult, TVariables>;
  readonly variablesOf: (input: ModerationActionInput) => TVariables;
  readonly outcomeOf: (result: TResult) => ModerationOutcomeView;
}): ModerationActionOptions;
```

- 措置の種類から操作の設定を引く表は、対象の種類ごとの変換のファイルに置き、措置の実行のフックが種類で振り分ける。
- 同じ措置を別の文言で行う操作(公開の拒否を削除の措置で行うなど)は、画面の操作として措置の種類と別に名前を持ち、措置の種類への写像で同じ操作の設定を使う。確認と結果の文言は画面の操作で引く。

### 確認のダイアログ

措置は確認のダイアログ(共通部品の`ConfirmActionDialog`)を経て行う。措置のダイアログは次を渡す。

| 項目                   | 値                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| `reason`               | 措置の種類の定義の理由の要否(`required`・`optional`)                                                        |
| `audited`              | 常に真。監査ログに記録される旨と、理由の欄の個人情報の注意を示す                                            |
| `title`・`description` | 対象の名前(ニックネーム・名称)を含む確認の文。影響は`description`の文の中で示す                             |
| `failureMessageOf`     | `(error) => errorMessageOf(error, <アプリのプロファイル>.contactAvailable)`                                 |
| `onConfirm`            | 措置の実行のフックを呼ぶ。理由を任意とする措置の空の理由は空文字で送り、APIサーバーが理由なしとして記録する |

- `description`は段落(`<p>`)の中に描かれるため、影響を一覧の要素(`<ul>`)で渡さず、文で示す。一覧を渡すと不正な入れ子になり、自動検査とハイドレーションで失敗する。
- 失敗は、ダイアログを閉じずに理由の入力を保ったまま、ダイアログの中に`role="alert"`で示す。APIサーバーの想定内の失敗(他の操作で状態が変わった・対象が見つからないなど)はサーバーの文言のまま示す。管理者側に問い合わせの画面が無い場合は、問い合わせを促す文を出さない(「[失敗の文言の選び方](009-admin-console-shell.md#失敗の文言の選び方)」)。
- 確定の後に取り直した状態で示す操作が替わっても(停止の後に停止の解除になるなど)、ダイアログが閉じる間は開いた時の操作の確認を示し続ける。行の操作は、押した時に措置の種類・対象・確認の文言を決めて置き場所へ渡し、置き場所はそれを状態に持つ。
- 措置のボタンの読み上げの名前には対象の名前を含め、一覧の行ごとのボタンを区別できるようにする。
- 取り消せない措置(代理の退会など)のダイアログは、措置のダイアログの上に作り、取り消せない旨と、システムの外で行う手順があればその旨を説明に含める。

#### 一覧の単位の置き場所

確定や対象の不在の失敗で一覧を取り直すと、操作を押した行が消える(状態で絞った一覧から外れる、削除された対象が一覧から消えるなど)。確認のダイアログを行の部品の中に置くと、行と一緒にダイアログと失敗の文言も消えるため、ダイアログは一覧(表・詳細の区画・タブの区画)の単位に1つ置く。

```tsx
export function ModerationDialogHost({
  fallbackFocusRef,
  children,
}: {
  // 確定した後と、開いた元の操作が消えた後の移り先(一覧の見出しなど)
  readonly fallbackFocusRef: RefObject<HTMLElement | null>;
  readonly children: ReactNode;
}): ReactNode;

export function useOpenModerationDialog(): (request: {
  readonly operation: ModerationOperation;
  readonly targetId: string;
  readonly copy: ModerationDialogCopy;
}) => void;
```

- 置き場所は、一覧の見出し・表・続きの読み込みを包み、文脈で開く関数を渡す。行の操作は文脈から開く関数を読み、ボタンだけを描く。置き場所の外で開く関数を読むと例外にする。
- 開くたびに数を変えてダイアログを作り直し(`key`)、閉じる動きの最中に別の行で開き直しても前の理由の入力を残さない。閉じる動きの間も題名を保つため、閉じても対象を残す。
- 閉じた後のフォーカスは「[処理の後のフォーカス](004-accessibility-rules.md#処理の後のフォーカス)」に従う。確定した時は一覧の見出し(`tabIndex={-1}`)へ移す(押した操作が別の操作に替わる・消えるため)。取り消しと失敗の後に閉じた時は押した操作へ戻し、押した操作が取り直しで消えていれば一覧の見出しへ移す。対象の不在の失敗の取り直しを閉じるまで遅らせた時(下の詳細のページ)は、閉じた後の取り直しで押した操作が消え得るため、押した操作が残っていても見出しへ移す。押した操作は開いた時の`document.activeElement`で覚え、閉じる時に`isConnected`で残っているかを確かめる。
- 詳細のページの措置(詳細の対象そのものへの措置と、詳細の区画の行の措置)は、取り直しで詳細の対象が消えると、ページごと見つからない表示に替わり、処理中の確認のダイアログも外れて文言が出ず、フォーカスが`<body>`へ落ちる。そのため詳細のページでは、対象の不在の失敗の取り直しを確認のダイアログを閉じるまで遅らせ(措置の実行のフックの`deferTargetMissingRefresh`、置き場所の同名の指定)、ダイアログの中に文言を示して理由の入力を保ち、閉じた時に影響する照会を無効にする。閉じずに画面を離れてダイアログが外れた時も、外れる時に同じ照会を無効にする。詳細の対象そのものへの措置は行の中ではないため置き場所を使わず、措置のダイアログに直接指定する。
- 詳細のページは、取り直しで対象が消えた時に、ルートの`notFound()`へ投げず、自分の位置に見つからない表示を描く。見つからない表示は、描き替えの確定と同じ時点(`useLayoutEffect`)でフォーカスが`<body>`にある時だけ、見出しで名前を持つ不在の区画(`tabIndex={-1}`)へフォーカスを移す。最初の表示(`loader`が不在を確かめてルートの`notFoundComponent`で描く表示)ではフォーカスを移さない。区画の行が消えただけで詳細の対象が残る時は、閉じた後のフォーカスを区画の見出しへ移す。

### 確定の後の反映

措置の実行のフックは、操作を実行し、影響する照会を無効にしてから、結果を知らせる。失敗は例外のまま確認のダイアログへ返す。

```typescript
const AFFECTED_QUERIES: Readonly<Record<TargetKind, readonly Invalidate[]>> = {
  user: [
    invalidateUserQueries,
    invalidatePostQueries,
    invalidateCommentQueries,
    invalidateImageQueries,
  ],
  comment: [invalidateCommentQueries],
  image: [invalidateImageQueries, invalidateUserQueries, invalidatePostQueries],
};
```

- 措置は対象の一覧以外の表示も変える(利用者の停止は投稿の公開状態・コメントの状態・画像の隔離理由を、評価の無効化は詳細の平均を変える)。対象の種類ごとに影響する照会を表にし、まとめて無効にする。表示していない照会は古い印が付くだけで取り直さない。
- 状態が変わった措置は監査ログの記録を残すため、監査ログの検索の照会も条件とページの位置を問わず無効にする。無効にしないと、照会の鮮度の期間の間に監査ログの画面を開き直しても記録が出ない。変化なしの措置は記録を残さないため、監査ログの照会を無効にしない。
- 無効化の後に知らせる。変わったら成功の通知(「◯◯しました。」)、変化なしなら情報の通知(「既に◯◯です。」)にする。変化なしを失敗として扱わない。
- 対象が見つからない失敗(`GraphQLClientError`で、コードが措置の対象の不在のコードの一覧にあるもの)は、表示中の一覧が古いことを示す。照会の操作の不在のような、措置の対象でないものの不在のコードは含めない(`_not_found`の接尾辞では判定しない)。影響する照会を無効にしてから失敗を投げ直し(詳細のページでは閉じるまで遅らせる)、確認のダイアログの中に文言を示して理由の入力を保つ。一覧は取り直されて消えた対象の行が除かれる。監査ログの照会は、記録が残らないため無効にしない。他の失敗(権限・競合・入力の誤りなど)では照会を無効にしない。行ごとに状態と行える操作を示す案件の一覧で、完了済み・競合の失敗でも取り直す場合は「[取り直す失敗](021-registered-action-dialogs.md#取り直す失敗)」に従う。

## ロールによる出し分け

- 一覧と詳細は、全ての管理者のロールが見られる。措置のボタンは、措置に要るロールの`RoleGate`で包み、足りない管理者には出さない(「[ロールによる操作の出し分け](009-admin-console-shell.md#ロールによる操作の出し分け)」)。
- 取り消せない措置や影響の大きい措置は最上位のロールに限る。画面の出し分けは表示の都合で、APIサーバーが同じロールを確かめる。

## 個人情報の検索の注記

メールアドレスのように個人情報で検索できる絞り込みは、APIサーバーが検索を監査ログに記録してから結果を返す(「[操作と同じ一括の書き込みに含める](../backend/008-audit-logging.md#操作と同じ一括の書き込みに含める)」)。画面は、その入力欄の説明として記録される旨を示し(`aria-describedby`)、検索の値をログやエラートラッキングへ送らない。

## 対象の表示

### 公開中の画像と隔離中の画像

隔離中の画像は画像の変換配信から配信されないため、変換配信の画像を受け取る部品では表示できない。APIサーバーの照会は、画像のファイルごとに同じオリジンの中継の経路(`path`)と変換配信の画像(`image`。隔離中・削除待ち・保存未完了は`objectKey`が`null`)の両方を返す。管理者の画像の部品は、次のように表示の経路を選ぶ。

- 隔離理由が無く`objectKey`がある画像は、変換配信の画像の部品(`MediaPicture`)で画像配信のオリジンから表示する(「[画像の表示](005-shared-components.md#画像の表示)」)。画像配信のオリジンは画面のCSPの`img-src`に環境の値として加わっている。
- 隔離中の画像と`objectKey`が`null`の画像は、管理者側のサイトと同じオリジンの中継の経路から原本を表示する。`src`は`path`にし、寸法の分からない原本は表示の枠に`object-contain`で収める。
- 読み込みの失敗と、削除済み・未設定(`null`)では、代わりの表示(`MediaPlaceholder`)にする。
- サーバーの描画の画像がハイドレーションの前に読み込みに失敗すると、`error`の事象を受け取れない。要素を結び付けた時点で`complete`が真かつ`naturalWidth`が0なら失敗として扱う。
- 中継の経路の閲覧の判定(管理者の主体だけが読める)はAPIサーバーが行う。

### 利用者の入力

- 措置の理由・コメントの抜粋などの利用者と管理者の入力は、マークダウンやHTMLとして解釈せず、改行を保った文字列(`whitespace-pre-wrap`・`break-words`)で示す。マークダウンの本文(投稿の説明文など)だけを表示部品で描く。
- 最新の措置の理由は、状態が持つ日時(停止の日時など)を優先し、無ければ措置の記録の日時を示す。記録が保持期間を過ぎて消えていれば、記録が無い旨を示す。

## テスト

- 検索条件の正規化(単体テスト): 項目ごとの不正な値の未指定、検索語の空白と上限の切り詰め、数の形の値、メールアドレスの上限、列挙とIDの形式、逆転した期間、既定の値の省略、全ての項目を返すこと、APIの入力への変換(期間の境界と地域の暦)、ページの位置だけを替えること、条件の文字列が項目の順によらないこと。
- 変換(単体テスト): 列挙の写像と未知の値、ページの続きの有無、措置の操作の変数と結果、照会の無効化のキー、`loader`が失敗を握ること。
- 措置のダイアログと実行のフック(ブラウザテスト): 理由の要否、監査ログの注記、影響を含む説明、成功と変化なしの通知、失敗をダイアログの中に示し理由を保つこと、影響する照会の無効化と状態が変わった時だけの監査ログの照会の無効化、対象の不在の失敗だけで影響する照会を無効にすること、閉じる間に確認が替わらないこと、ロールによる出し分け、自動のアクセシビリティ検査。
- 一覧のページ(ブラウザテスト): 対象の不在の失敗で一覧を取り直して行が消えてもダイアログと文言と理由が残ること、閉じると一覧の見出しへフォーカスが移ること。詳細のページでは、対象の不在の失敗で文言と理由が残り、閉じると取り直して見つからない表示に替わり、フォーカスが`<body>`でなく不在の区画にあること、最初の表示ではフォーカスを移さないこと。ダイアログを開いている間は背後の一覧が支援技術から隠れるため、行が消えたことは隠れた要素も含める照会(`includeHidden: true`)で確かめる。
- 画像(ブラウザテスト): 公開中の画像の画像配信のオリジンからの`<picture>`と`srcset`、隔離中と`objectKey`が`null`の画像の同じオリジンの経路の表示、読み込みの失敗と`null`の代わりの表示、ハイドレーションの前の失敗。
- テストの種別と命名は「[テストの種別と命名](../testing/001-test-strategy.md#テストの種別と命名)」に従う。
