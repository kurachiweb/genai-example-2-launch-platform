# 集計値と残り時間を表示し続ける画面

期間を限った投票などの集計値と、受け付けの終了までの残り時間を、利用者が開いたまま見続ける画面の規約を定める。区画を置き場所と順で登録するページの構成、サーバーの時刻との差の補正、境界の時刻での取り直しと結果を待つ取り直し、並び順を保った定期の取り直し、操作の結果の反映、bot判定のトークンの共有、ページ全体で1つの自動更新の切り替えと演出の停止、読み上げとコントラスト、及びテストを扱う。

投票の受け付けと集計値の保存は「[期間を限った投票](../backend/014-time-boxed-voting.md)」に、定期再取得の共通の値と止める手段は「[表示中の画面の定期再取得](010-live-refresh-queries.md)」に、境界の時刻のタイマーは「[表示中の境界の取り直し](012-business-date-calendar.md#表示中の境界の取り直し)」に、演出の停止と視差効果の軽減は「[アクセシビリティ規則](004-accessibility-rules.md)」に、登録口の区画の取得と変更は「[データ取得](006-data-fetching.md)」に従う。

## 前提と用語

部品の置き場所は、共通部品のディレクトリと、画面のアプリの`src/`からのパスで示す。`<ページ>`は区画を並べるページ、`<ドメイン>`は集計値を持つ機能ごとに置き換える。

| 部品                                                        | 置き場所                                                                                                                             | 役割                                                                    |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| `LIVE_REFRESH_INTERVAL_MS`・`LIVE_REFRESH_QUERY_OPTIONS`    | 共通部品の`utilities/query/live-refresh.ts`                                                                                          | 定期再取得の間隔と共通の値                                              |
| `RecoverableSlot`                                           | 共通部品の`components/state/recoverable-slot.tsx`                                                                                    | 区画ごとのエラーの境界と読み込み中の表示                                |
| `useTurnstileToken`・`TurnstileWidget`・`sendWithTurnstile` | 共通部品の`components/bot-protection/`・`utilities/bot-protection/`                                                                  | bot判定のウィジェットとトークンの取り出し                               |
| `useBoundaryRefresh`                                        | 画面のアプリの`components/time/use-boundary-refresh.ts`                                                                              | 境界の時刻のタイマーによる取り直し                                      |
| 区画の型・置き場所の並べ方                                  | 画面のアプリの`components/<ページ>/<ページ>-section-types.ts`・`<ページ>-section-order.ts`                                           | 区画の契約と、置き場所ごとの並べ替え                                    |
| 区画の登録口                                                | 画面のアプリの`composition/<ページ>-sections.ts`                                                                                     | 各機能が区画を追記する一覧                                              |
| 自動更新の切り替え                                          | 画面のアプリの`components/<ページ>/auto-refresh-switch.tsx`。複数のページが使う場合は`components/<ドメイン>/auto-refresh-switch.tsx` | ページ全体の定期の取り直し・毎秒の数値の更新・演出を止める`Switch`      |
| `useServerCountdown`                                        | 画面のアプリの`components/<ドメイン>/use-server-countdown.ts`                                                                        | サーバーの時刻に合わせた残りの秒数                                      |
| bot判定の提供部品と取り出しのフック                         | 画面のアプリの`components/<ドメイン>/<操作>-bot-protection.tsx`・`<操作>-turnstile.ts`                                               | ページに1つのウィジェットのトークンを、ページの全ての操作のフックへ渡す |

| 用語               | 意味                                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 区画               | ページに登録口から並べる部品。自分でデータを取得し、該当しなければ何も描かない                                          |
| 置き場所           | 区画を並べるページの領域(上部の行・本文の列・横の列など)                                                                |
| 定期の取り直し     | `refetchInterval`による`<定期再取得の間隔>`ごとの取り直し                                                               |
| 境界の時刻         | サーバーの答えが変わる時刻(受け付けの終了・翌日の開始など)                                                              |
| 境界の取り直し     | 境界の時刻の直後にタイマーで行う取り直し                                                                                |
| 結果を待つ取り直し | 境界の取り直しがまだ変化の前の状態を返す間に、回数を限って続ける取り直し                                                |
| 毎秒の数値の更新   | 残り時間など、表示中に1秒ごとに変わる数値の描き直し                                                                     |
| 演出               | 「[前提と用語](004-accessibility-rules.md#前提と用語)」の演出。利用者の操作に直接応えるもの以外の動き・点滅・自動の更新 |
| 申告               | 区画が、自分が定期の取り直し・毎秒の数値の更新・演出を持つかどうかをページへ伝えること                                  |
| サーバーの時刻     | 取得の応答に含めた、応答を作った時点のサーバーの時刻(ISO形式の日時文字列)                                               |

本文中の`<結果を待つ取り直しの上限>`などのプレースホルダーの本プロジェクトの値は、技術ドキュメントに写さず、プロジェクト固有の値の文書「[本プロジェクト固有の値](../../../onboardings/project-values.md)」に置く。

## 区画の登録とページの構成

後から加わる機能が区画を追加できるよう、ページは区画を登録口から置き場所ごとに`order`の順で並べる。区画にはページが知る値だけを文脈で渡す。

```typescript
export interface PageSectionContext {
  // 区画が自分の取得の基準に使う、ページの値
  readonly board: {
    readonly date: string;
    readonly phase: 'LIVE' | 'RESULT';
    readonly serverTime: string;
  };
  readonly viewer: { readonly signedIn: boolean };
  // ページ全体の自動更新の切り替えの状態
  readonly autoRefresh: boolean;
  // 定期の取り直し・毎秒の数値の更新・演出を持つ間はtrueを申告し、無くなればfalseにする
  readonly reportAutoUpdating: (active: boolean) => void;
}

export interface PageSection {
  // '<spec名>.<名詞句>'
  readonly id: string;
  readonly placement: 'banner' | 'main' | 'aside' | 'bottom';
  readonly order: number;
  readonly component: ComponentType<PageSectionContext>;
}
```

- ページは区画ごとに`RecoverableSlot`で包み、1つの区画の失敗をその位置に留める(「[登録口に登録された区画の取得](006-data-fetching.md#登録口に登録された区画の取得)」)。
- 区画が何も描かない(`null`)とき、グリッドや列に空の枠と間隔を残さない。区画の末尾に隠した目印の要素を置き、目印のある枠だけを`display: contents`にする(`has-[>[data-<ページ>-section-rendered]]:contents`)。`display: contents`の要素はフォーカスできないため、再試行の後にフォーカスを移す読み込み中と失敗の間は通常の箱のまま残す。
- 一覧の何件ごとかに区画を差し込む登録口は、`every`(何件ごと)と、部品へ渡す何番目かの位置(1から)を持つ。割り切れるときは最後の項目の後にも差し込む。差し込みもエラーの境界で包む。
- 登録口と区画の部品が互いを読み込むと循環するため、差し込みの登録口を使う区画は、登録する側が差し込みを渡して作る関数(`<区画>Of(inserts)`)にする。
- ページの見出しは区画に持たせず、ページが`h1`を置く。見た目に見出しが無いページは`sr-only`の`h1`にし、再試行の後のフォーカス先にするなら`id`と`tabIndex={-1}`を付ける。

## サーバーの時刻との差の補正

残り時間は、閲覧者の時計ではなくサーバーの時刻で数える。閲覧者の時計は数分ずれていることがあり、そのまま使うと受け付けの終了の前に0を示したり、終了の後も数え続けたりする。

```typescript
const createServerClock = () => {
  let latest: {
    readonly serverTime: string;
    readonly offsetMs: number;
  } | null = null;
  return {
    serverNow: (serverTime: string): number => {
      const now = Date.now();
      if (latest?.serverTime !== serverTime) {
        latest = { serverTime, offsetMs: Date.parse(serverTime) - now };
      }
      return now + latest.offsetMs;
    },
  };
};
```

- 取得の応答にサーバーの時刻を含め、その値を最初に読んだ時点の閲覧者の時計との差を、次の取得でサーバーの時刻が変わるまで使い続ける。
- 自動更新の切り替えがオフの間に取り直しで届いたサーバーの時刻も、届いて描き直した時点で差を記録する。オンに戻した時点で記録すると、届いてから戻すまでの時間だけずれる。
- `useSyncExternalStore`で読み、サーバーの描画のスナップショットは`null`にする。サーバーの描画とハイドレーションの時刻は異なるため、残り時間はハイドレーションの後にだけ示し、それまでは置き換えの表示(`--:--:--`など)にする。
- 次の描き直しは、表示の秒が変わる時刻(`残り % 1000 || 1000`ミリ秒後)に`setTimeout`で予約する。`setInterval`の1秒ごとは誤差を積み重ねる。秒は切り上げ、0で止める。
- 0になった時に取り直しを持たない。取り直しは境界の取り直しに任せる(「[境界の時刻での取り直し](#境界の時刻での取り直し)」)。

### 毎秒の数値の読み上げ

毎秒変わる数字を支援技術に読ませ続けない。

```tsx
<span aria-hidden="true">{digits}</span>
<span aria-live="off" className="sr-only">
  {reading}
</span>
<span>
  (<DateTime value={endsAt} format="time" />
  終了)
</span>
```

- 数字は`aria-hidden`にし、分単位の文(「終了まであと12時間34分」・1分未満は「終了まであと1分未満」など)を`aria-live="off"`の見えない文で添える。利用者が読みに行ったときだけ読まれ、毎秒の変化は通知されない。
- 終了の時刻を`<time>`要素で併記する(「[マークアップの規約](001-markup-conventions.md)」)。括弧などの記号と文言は`<time>`の外に置く。
- 自動更新の切り替えがオフの間は、毎秒の更新を止め、ラベル・数字・読み上げの文を描かずに終了の時刻だけを残す。止まった数字は誤った残り時間に見える。

## 境界の時刻での取り直し

受け付けの終了や翌日の開始など、サーバーの答えが変わる時刻を過ぎたら、`useBoundaryRefresh`で取得を無効にして取り直す(「[表示中の境界の取り直し](012-business-date-calendar.md#表示中の境界の取り直し)」)。

- 境界の取り直しは、ページ(ルートの部品)が区画のエラーの境界の外で行う。区画の描画が失敗しても、ページの値(時間帯・サーバーの時刻)が境界で切り替わり、他の区画が新しい時間帯で描かれる。
- 結果を待つ取り直しの回数を数える区画は、同じ境界の並びで`useBoundaryRefresh`を呼び、数えの基準だけを置き直す。子の部品の効果がページの効果より先に掛かるため、取り直しの前の回数が基準になり、境界の取り直しそのものが1回目に数えられる。
- 境界の取り直しは自動更新の切り替えで止めない。境界の時刻の取り直しは時間帯の切り替えで、自動で更新され続ける情報ではない。

## 結果を待つ取り直し

境界の時刻の直後は、サーバーの日次の処理(確定・開始)がまだ終わっておらず、境界の取り直しが変化の前の状態(集計中・開始待ち)を返す。変化を待っている間は、自動更新の切り替えによらず、`<定期再取得の間隔>`ごとに`<結果を待つ取り直しの上限>`回まで取り直す。

```typescript
export const refetchIntervalOf = ({
  board,
  autoRefresh,
  updatesSinceBaseline,
}: RefreshInput): number | false => {
  if (board === undefined) {
    return false;
  }
  const awaiting = isAwaitingChange(board);
  if (autoRefresh && (awaiting || hasLiveItem(board))) {
    return LIVE_REFRESH_QUERY_OPTIONS.refetchInterval;
  }
  if (awaiting && updatesSinceBaseline < FOLLOW_UP_REFETCH_LIMIT) {
    return LIVE_REFRESH_QUERY_OPTIONS.refetchInterval;
  }
  return false;
};
```

- 回数は取得の更新の回数(`dataUpdateCount`と`errorUpdateCount`の和)と基準の差で数え、失敗した取り直しも数える(「[止める手段](010-live-refresh-queries.md#止める手段)」の回数を限った一時的な再取得と同じ数え方)。基準は、ページを表示した時点と最後の境界の時刻のうち後の時点の回数にする。
- 値が変わらない取り直しと失敗でも回数の表示を描き直すよう、取得に`notifyOnChangeProps: ['data', 'dataUpdatedAt', 'errorUpdateCount']`を渡す。値が同じだと構造の共有で`data`が変わらず、上限に達しても描き直されない。
- 上限に達しても変化の前の状態のままなら、区画の見出しの下に常に置いた`role="status"`の文を、ページを開き直す案内に切り替える。案内は自動更新の切り替えがオフの時だけ出す。オンの間は定期の取り直しが続き、変化を待ち続ける。
- 反映が済んだかどうかの判定は、取得した値の状態(集計中・開始待ちが無くなったこと)で行う。

## 並び順を保った定期の取り直し

集計値で並べた一覧は、並べ替えをページを表示した時だけ行い、定期の取り直しでは値だけを差し替える。取り直しのたびに並びが動くと、押そうとしたボタンが別の項目に替わり、支援技術の読み上げの位置も変わる。

```typescript
// 取り直した項目を最初に表示した順に並べ、その順に無い項目は取得した順で末尾に加える
export const orderBy = <T extends { readonly id: string }>(
  order: readonly string[],
  items: readonly T[],
): T[] => {
  const byId = new Map(items.map((item) => [item.id, item]));
  const known = new Set(order);
  return [
    ...order.flatMap((id) => {
      const item = byId.get(id);
      return item === undefined ? [] : [item];
    }),
    ...items.filter(({ id }) => !known.has(id)),
  ];
};
```

- 最初の描画の順(IDの並び)を`useState`の初期値で持ち、取り直した値をその順で描く。取り直しで消えた項目は除く。
- 業務日付が変わったら、`key={<業務日付>}`で部品を作り直し、新しい日の一覧はサーバーの順で並べる。
- `refetchInterval`と`refetchOnWindowFocus`は取得した値で判定する関数にする(「[取得した値による判定](010-live-refresh-queries.md#取得した値による判定)」)。受け付け中の項目か、変化を待つ状態がある間だけ取り直し、結果が全て確定した後と項目の無い日は止める。
- 定期の取り直しは区画の購読(`useQuery`の監視)ごとに働く。同じ取得をページと区画の両方が購読するときは、`refetchInterval`を区画の側だけに持たせ、ページの側は`refetchOnMount: false`で読むだけにする。

## 操作の結果の反映

投票などの操作は、楽観的に表示を変えず、サーバーが返した値で反映する。

- 操作の応答は変わった項目の最新の値を返し、成功したら`setQueryData`で一覧の取得の該当する項目だけを差し替える。一覧に無い項目は何もしない。他の項目は次の定期の取り直しに任せる。
- 失敗したら表示を変えずに、失敗の文言を通知する(`notify.error`)。競合(受け付けの終了の後の操作など)は理由の文言で示す。
- 送信中は押した項目のボタンを`aria-busy`にし、同じ部品の2回目の押下を無視する。同じイベントの中の2回目の押下は描き直しの前に届くため、送信中かどうかを`useRef`でも持つ。
- 操作に応える演出(票が移った側の盛り上がりなど)は、サーバーの結果で閲覧者の票が別の選択肢へ移ったときだけ動かす。
- 未ログインの閲覧者が操作を押したら、ログインを求めるダイアログを開き、戻り先に現在のURLを渡す。

## bot判定のトークンの共有

操作のボタンが一覧の項目ごとにあるページでも、bot判定のウィジェットはページに1つだけ置く。項目ごとに置くと、項目の数だけ判定が走る。

```tsx
export function VoteBotProtection({
  children,
}: {
  readonly children: ReactNode;
}) {
  const turnstile = useTurnstileToken();
  return (
    <VoteTurnstileContext value={turnstile}>
      {children}
      <TurnstileWidget {...turnstile.widgetProps} action={BOT_ACTIONS.vote} />
    </VoteTurnstileContext>
  );
}
```

- 提供部品がウィジェットを1つ描き、コンテキストでトークンの取り出し口を渡す。操作のフックはコンテキストから取り出し口を受け取り、提供部品の外で呼ばれたら例外を投げる。
- 操作のたびに`sendWithTurnstile`で新しいトークンを取り出す。最初のトークンが届く前の送信がbot判定に失敗した時は、次のトークンで1回だけ送り直す(「[変更](006-data-fetching.md#変更)」)。
- 同じ部品を使う他のページは、自分のページを提供部品で包む。ページの区画として描かれる部品は、ページの提供部品をそのまま使う。
- 操作の対象がある間だけ区画を提供部品で包む(対象が無い間はウィジェットを置かない)場合、包むかどうかが切り替わると内側の区画は作り直され、切り替わる前の値を持たない。切り替わりの前後の値の比較で行う処理(対象の出現・消滅での取り直しなど)は、包む側のページが行う。

## 自動更新の切り替え

定期的に取り直す区画・毎秒の数値の更新・演出が複数の区画にあるページは、区画ごとの`Switch`の代わりに、ページの上部に1つの「自動更新」の切り替えを置き、状態を全ての区画へ渡す(「[演出の停止手段の義務](004-accessibility-rules.md#演出の停止手段の義務)」・「[ページ全体で1つの切り替え](010-live-refresh-queries.md#ページ全体で1つの切り替え)」)。各区画の見出しの近くには切り替えを置かない。

| 切り替え | 止めるもの                             | 止めないもの                                                                                   |
| -------- | -------------------------------------- | ---------------------------------------------------------------------------------------------- |
| オフ     | 定期の取り直し・毎秒の数値の更新・演出 | 境界の取り直し・結果を待つ取り直し(上限まで)・操作の後の反映と無効化・画面へ戻った時の取り直し |

- 状態はページの部品が`useState(true)`で持ち、ページを開くたびにオンから始める。区画には文脈の`autoRefresh`で渡し、区画は受け取った状態で`refetchInterval`・毎秒の更新・自分の演出を止める。
- 切り替えは、ページが登録した区画とは別に、区画のエラーの境界の外に描く。区画が失敗しても切り替えは消えない。
- 切り替えは、ページに定期の取り直し・毎秒の数値の更新・演出のいずれかがある間は描き、どれも無ければ描かない。結果が確定して定期の取り直しが止まっても、演出が残るなら描く。判定には、ページ自身の値(時間帯が受け付け中である・演出を持つ項目がある)と、区画の申告を合わせて使う。
- 区画は、定期の取り直し・毎秒の数値の更新・演出を持つ間は`reportAutoUpdating(true)`を、無くなれば`false`を申告する。ページは区画のエラーの境界が例外を捕まえた時と区画が外れた時に、その区画の申告を消す。消す処理は、境界の内側に置いた部品の効果の後始末で行う(境界が区画を外すとアンマウントされる)。
- 区画の失敗で消すのはその区画の申告だけで、ページ自身の値や他の区画の申告が残る間は切り替えを描き続ける。失敗した区画の申告だけが理由だった場合は、ページに止める対象が残らないため描かない。「区画の失敗で消えない」は切り替えの描き場所の規則で、「どれにも当たらなければ描かない」は描く条件の規則であり、両立する。
- `Switch`(`role="switch"`・`aria-checked`)に名前「自動更新」を`<Label>`で付け、`LIVE_REFRESH_INTERVAL_MS`から作った秒数で、取り直しの間隔と止める範囲(数値の取り直し・残り時間・演出)の説明を`aria-describedby`で関連付ける。秒数を文言に直接書かない。

### 演出の停止

演出の可否はCSSだけで決める。ページの根の要素に切り替えの状態を`data-auto-refresh="on"`・`"off"`で付け、演出のアニメーションと遷移を、視差効果を減らす設定でない時の、属性が`on`の要素の子孫にだけ掛ける。

```css
/* 演出が止まっている間の静止の位置 */
[data-vote-marker] {
  transform: translateX(calc(var(--marker-rest) * 100%));
}

@media (prefers-reduced-motion: no-preference) {
  [data-auto-refresh='on'] [data-vote-marker] {
    transform: translateX(calc(var(--marker-at) * 100%));
    transition: transform var(--marker-duration) var(--marker-easing);
  }

  [data-auto-refresh='on'] [data-scoreboard-flag] {
    animation: flag-wave 1.8s ease-in-out infinite;
  }
}
```

- 演出の部品は切り替えの状態を受け取らず、`data-*`の目印だけを持つ。1つの属性で、後から加わる区画の演出も含めてページ全体を止められ、サーバーの描画とブラウザの描画が一致する。
- 属性の無いページでは演出は既定で止まる。同じ部品をページの外(詳細のページなど)で使い、演出を動かすなら、そのページが自分の停止の手段を置いて属性を付ける。
- 止めた状態でも意味の分かる静止の姿(比率の境目に置いた印など)を、演出の規則の外に書く。
- スクリプトで動かす演出(`motion/react`など)はCSSの規則が効かないため、切り替えの状態と視差効果を減らす設定(`useReducedMotion`)の両方で止める。

## 読み上げとコントラスト

- 票の数を見せるボタンの名前は、見えている数を含める(「<選択肢の名前>に投票 1,234票」など)。見えている文言が名前に含まれないと、音声入力の利用者が見えている文言で押せない(達成基準2.5.3)。押した状態は`aria-pressed`で伝える。
- 押せない理由(自分の選択肢・受け付けの終了・利用者の状態)は、`aria-disabled`とツールチップと`aria-describedby`で示し、フォーカスできるままにする(「[操作できない状態](004-accessibility-rules.md#操作できない状態)」)。
- 比率のバーなどの図は`role="img"`にし、両方の名前と数を並べた代替テキストを付ける。装飾の背景の絵は`aria-hidden`にする。
- 負けた側などの状態を、文字色だけで示さない。状態の色のトークン(負けの色など)が背景との比で4.5:1に届かない場合は文字に使わず、枠の線の種類や画像の彩度などの文字以外の印と文言で示す(「[コントラスト](004-accessibility-rules.md#コントラスト)」)。
- 項目ごとの配色(選択肢ごとの色など)をトークン以外の値で持つ場合は、配色の一覧を1つのファイルにまとめ、ライト・ダークの両方で文字と背景の比を測る。

## テスト

- 残り時間だけを示す部品(TanStack Queryの取得を含まない)は、偽のタイマー(`vi.useFakeTimers({ now, toFake: ['Date', 'setTimeout', 'clearTimeout'] })`)で、サーバーの時刻と閲覧者の時計をずらして補正されること、秒の切り上げと0での停止、オフの間に届いたサーバーの時刻の補正、サーバーの描画で`null`になることを確かめる。
- TanStack Queryの取得と境界の取り直しを含むページ・区画のテストは、描画の前に`Date`・`setTimeout`・`clearTimeout`・`setInterval`・`clearInterval`を偽にし、取得の結果の通知を`notifyManager.setScheduler(queueMicrotask)`でタイマーを使わずに届ける(「[マウントの後に呼ぶ確定](006-data-fetching.md#マウントの後に呼ぶ確定)」)。境界の取り直しは`setTimeout`で待つため、`setTimeout`を偽にしないと確かめられない。テストの後は`vi.useRealTimers()`と、既定の通知のスケジューラーに戻す。このテストで、切り替えをオフにした後に間隔の数倍進めて定期の取得が無いこと、境界の時刻の1秒後に取り直すこと、結果を待つ取り直しが上限まで続き、上限で`role="status"`の文が案内に替わること(オンでは替わらないこと)を確かめる。
- 定期の取り直しだけを確かめる部品のテストは、`setInterval`と`clearInterval`だけを偽にし、`setTimeout`は偽にしない(「[ブラウザテスト](010-live-refresh-queries.md#ブラウザテスト)」)。
- 並び順は、取り直しで集計値の順が変わっても最初の順のまま値だけが替わること、業務日付の変化で作り直されることを確かめる。
- 切り替えの描画は、ページ自身の値で描くこと、区画の申告だけで描くこと、申告した区画が失敗すると消え、ページ自身の値がある間は残ること、どれも無いと描かないことを確かめる。
- 演出は、`emulateReducedMotion`(「[前提と用語](004-accessibility-rules.md#前提と用語)」)と切り替えのオフ・属性の無いページで、目印の要素の計算済みのスタイルにアニメーションが掛からないことを確かめる。
- 自動検査(`axe-core`)の違反が0件であることを、ライト・ダークの両方で確かめる。
- E2Eテストは定期の取り直しを待たず、操作の結果と再読み込みの後の表示で確かめる。
