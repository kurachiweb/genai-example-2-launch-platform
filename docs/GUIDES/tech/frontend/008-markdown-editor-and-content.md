# マークダウンの入力欄と表示部品

利用者がマークダウンで書く項目の、表示部品と入力欄の使い方を定める。描画の指定と表示部品、折りたたみ、目次の作り方、入力欄のフォームとの結合と検証規則、値の受け渡しと文字数のカウンターと保存される原文の関係、編集領域の遅延読み込みと読み込みの制限、編集領域・ツールバー・リンクのダイアログの振る舞い、アクセシビリティの規約、検索語の強調表示部品、テストの書き方を扱う。サニタイズの規約は「[マークダウンのサニタイズ](../security/004-markdown-sanitization.md)」に従う。

## 前提と用語

画面を持つアプリにTanStack Start、マークダウンの描画にunified(remark・rehype)、入力欄の編集領域にMilkdownのCrepe(内部でProseMirrorとVueを使う)を使う構成を前提とする。部品の置き場所と読み込み方は「[共通化する部品](005-shared-components.md#前提と用語)」に従い、共通部品または共用部品のディレクトリからのパスで示す。アクセシビリティの規則は「[アクセシビリティ規則](004-accessibility-rules.md)」に従う。

## 表示部品

### 描画の指定

| 項目                | 内容                                                                                                                       |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `siteOrigin`        | 同じタブで開くリンクの判定の基準のオリジン(例:`https://app.example`)。`useMarkdownOptions`が補う                           |
| `externalLinkRel`   | 別のオリジンへのリンクに付ける`rel`(`noopener`・`noreferrer`・`nofollow`・`ugc`・`sponsored`から選ぶ)。空なら付けない      |
| `sameOriginLinkRel` | 同じオリジンへのリンクに付ける`rel`。省略すると付けない                                                                    |
| `idScope`           | 本文の識別子(英小文字と数字の1〜32文字)。省略すると接頭辞は`user-content-`、指定すると`user-content-<本文の識別子>-`になる |

- 指定が不正なら`renderMarkdown`が`MarkdownOptionsError`を投げる。不正な項目の名前を`field`に持つ。不正な指定は、`http`・`https`のオリジンでない`siteOrigin`、許可していない値か重複した値を含む`rel`、形式に合わない`idScope`である。
- `rel`は表示場所(利用者の投稿・運営の文書など)ごとに決め、利用者の投稿の外部リンクには`ugc`などを付ける。
- 1つのページに複数の本文を置く時は、本文ごとに異なる`idScope`を渡す(「[接頭辞とDOM clobbering](../security/004-markdown-sanitization.md#接頭辞とdom-clobbering)」)。
- 表示部品は見出しレベル1・画像・Raw HTMLを描画せず、元の記法の文字列として表示する(「[文字列にする構文](../security/004-markdown-sanitization.md#文字列にする構文)」)。リンクの参照先の扱いは「[参照先の制限](../security/004-markdown-sanitization.md#参照先の制限)」に従う。

### 本文の表示

マークダウンの本文は、共用部品の`renderMarkdown`の結果を`MarkdownContent`へ渡して表示する。`MarkdownContent`は、サニタイズ済みの型の値だけを受け取り、生のHTMLを挿入する唯一の部品である(「[生のHTMLの例外の1箇所と検査](../security/004-markdown-sanitization.md#生のhtmlの例外の1箇所と検査)」)。

```tsx
const options = useMarkdownOptions({ externalLinkRel: ['noopener', 'ugc'] });
const rendered = useRenderedMarkdown(body, options);

return <MarkdownContent rendered={rendered} size="sm" />;
```

- `useMarkdownOptions`は、表示場所ごとの`rel`と本文の識別子に、ルーターの文脈の公開設定の利用者側のオリジン(`clientSiteOrigin`)をサイトのオリジンとして補う。管理者側の画面でも、同じタブで開くリンクは利用者側のページのオリジンで判定する。
- `useRenderedMarkdown`は、本文と指定の値が同じ間は描画をやり直さない。呼び出し側は描画のたびに指定のオブジェクトや配列を作り直してよい。描画は時刻・乱数・実行環境に依存しないため、ページのサーバー側の描画とブラウザの初期化は同じ描画結果になり、表示は食い違わない。
- `size`は`'base'`(既定。640px未満は小さい文字)と`'sm'`(常に小さい文字)から選ぶ。コメントやプレビューは`'sm'`にする。
- 文字組みは`@tailwindcss/typography`の`prose`で付け、本文の補助のスタイル(表の枠・タスクリスト・脚注)は`styles/markdown.css`に置く。コードブロックの配色はトークン`code-block`・`code-block-foreground`を使う。GFMの表の列揃え(`align`)は`markdown.css`の規則で`prose`の`text-align`を上書きする。
- 表は名前付きの領域(`role="region"`)の横スクロールの枠に入り、Tabキーで枠へ移動して矢印キーでスクロールできる。
- タスクリストのチェックボックスは表示だけのもので操作できず(`disabled`)、項目の文字列を名前(`aria-label`)に持つ。
- 脚注の一覧の見出し「脚注」は視覚的に隠し、参照位置へ戻るリンクは「本文の参照位置へ戻る」の名前を持つ。
- 代表的な長さの文書の描画は300ms以内に収まることを、共用部品の単体テストで計測している。入れ子が深すぎる、または解析で処理が重くなる入力は、原文を1つの段落の文字列として表示する(「[解析の負荷のガード](../security/004-markdown-sanitization.md#解析の負荷のガード)」)。
- 全文検索の索引には、同じ解釈のプレーンテキスト(`extractSearchText`)を使う(「[マークダウンの原文の保存](../db/004-full-text-search.md#マークダウンの原文の保存)」)。

### 折りたたみ

本文の高さを表示場所ごとに抑える時は、`MarkdownContent`の代わりに`CollapsibleMarkdownContent`を使う。propsは`MarkdownContent`と同じものに、折りたたむ高さ(`collapsedHeight`、px)と下端のぼかしの色のクラス(`fadeClassName`、既定は`from-background`)を加える。

```tsx
<div className="rounded-xl border bg-card p-6">
  <CollapsibleMarkdownContent
    rendered={rendered}
    collapsedHeight={240}
    size="sm"
    fadeClassName="from-card"
  />
</div>
```

- ページのサーバー側の描画とブラウザの初期化は、初めから`collapsedHeight`で折りたたんだ表示にし、切替ボタンとぼかしを含めない。高さを知らない間に全文を出してから縮めると、初期化の後に表示がずれるためである。
- マウントの後に`ResizeObserver`で本文の高さを測り、`collapsedHeight`を超える時だけ下端のぼかしと切替ボタン(`READ_MORE_LABEL`・`COLLAPSE_LABEL`)を出す。超えない時は高さの制限を外し、ボタンを出さない。本文や幅が変わると測り直す。
- 切替ボタンは`aria-expanded`で展開の状態を、`aria-controls`で本文の枠を支援技術へ伝える。ぼかしは`aria-hidden`で、ポインターの操作を妨げない。
- 折りたたんだ部分のリンクや表の枠へキーボードでフォーカスが移ると展開し、フォーカスした要素を切り取って隠さない。
- ページ内の移動(脚注の参照・見出しのアンカー・フラグメント付きのURLでの表示)で折りたたんだ本文の中がスクロールすると展開し、移動先(`location.hash`が指す本文の中の要素。無ければフォーカスした要素)を見える位置に表示し直す。移動先の脚注などはフォーカスできないため、フォーカスでの展開だけでは本文の中だけがスクロールして先頭が隠れたまま戻せなくなるためである(WCAG 2.2の達成基準2.4.11)。初期化の前の移動やTabキーでスクロールした状態は、初期化の時に確かめて同じく展開する。
- ぼかしは本文の下に重ねるため、`fadeClassName`は本文を置く面の背景色(カードの上なら`from-card`)にそろえる。

### 目次の作り方

目次は`renderMarkdown`の結果の`headings`から作る。各要素は見出しのレベル(`depth`、2〜6)・最終的なID(`id`、接頭辞を含む)・文字列(`text`)を本文の順に持つ。

```tsx
<nav aria-label="目次">
  <ul>
    {rendered.headings.map((heading) => (
      <li key={heading.id} data-depth={heading.depth}>
        <a href={`#${heading.id}`}>{heading.text}</a>
      </li>
    ))}
  </ul>
</nav>
```

- `id`は本文の中の見出しの`id`と同じ値で、接頭辞を付け直さずに`#`の後へそのまま置く。
- 脚注の一覧の中の見出しは含めない。見出しレベル1は表示部品が見出しにしないため現れない。
- IDは見出しの文字列から作る(「[接頭辞とDOM clobbering](../security/004-markdown-sanitization.md#接頭辞とdom-clobbering)」)。同じ文字列の見出しが続くと`-1`・`-2`…が付くため、目次のキーと参照は`text`ではなく`id`を使う。
- 本文の中の`[見出しへ](#見出し)`のようなリンクも同じ規則で接頭辞付きのIDへ書き換わるため、目次と本文のリンクは同じ見出しを指す。
- 目次を折りたたみ付きの本文と併せて置く場合は、目次のリンクでの移動で折りたたみが展開する(「[折りたたみ](#折りたたみ)」)。

## 入力欄

### フォームとの結合

フォームでマークダウンを入力させる時は、`MarkdownEditor`(`components/markdown-editor/markdown-editor.tsx`)を`AppForm`の中の`FormField`の子として描く(「[フォーム](005-shared-components.md#フォーム)」)。子の関数が受け取る値を、名前の異なるpropsへ対応付けて渡す。

```tsx
<FormField
  control={form.control}
  name="body"
  label="コメント(必須)"
  description="マークダウンで書けます。"
>
  {(control) => (
    <MarkdownEditor
      value={control.value}
      onValueChange={control.onChange}
      onBlur={control.onBlur}
      ref={control.ref}
      labelId={control.labelId}
      describedById={control['aria-describedby']}
      invalid={control['aria-invalid'] === true}
      disabled={control.disabled === true}
      maxGraphemes={2000}
      placeholder="コメントを入力してください"
      preview={previewOptions}
    />
  )}
</FormField>
```

| props                                 | 内容                                                                                                  |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `value`・`onValueChange`・`onBlur`    | フォームの値(原文)と、変更・離脱の処理                                                                |
| `ref`                                 | `focus`だけを持つ値を受け取る。`AppForm`がエラーの欄へフォーカスを移す時に使う                        |
| `labelId`・`describedById`・`invalid` | 編集領域の名前・説明・不正な状態                                                                      |
| `disabled`                            | 編集とツールバーの操作を受け付けない。欄は`FormField`の`disabled`で無効にし、子へ渡る`disabled`を渡す |
| `maxGraphemes`                        | カウンターの上限(書記素の数)。検証規則の上限と同じ値にする                                            |
| `placeholder`                         | 空の時の案内の文                                                                                      |
| `preview`                             | プレビューの描画の指定。表示場所と同じ`rel`を渡し、本文の識別子は`'preview'`にする                    |

- 編集領域は`contenteditable`の要素で`<label for>`で名前を付けられないため、`labelId`を`aria-labelledby`に使う。`labelId`は子の関数の値に列挙されないプロパティとして入るため、`{...control}`では渡らない。`control.labelId`で明示して渡す。
- `MarkdownEditor`の`disabled`だけを指定すると、React Hook Formが欄を無効と扱わず、送信の値と検証から外れない。欄を無効にする時は`FormField`の`disabled`を使う。
- `ref`の`focus`は「書く」へ切り替えてから編集領域へフォーカスを移し、読み込みの前と失敗の間は要求を保留して、読み込めた時に移す。

### 検証規則

マークダウンの項目の検証規則は、共用部品の`markdownTextSchema({ label, maxGraphemes, required })`で作る。画面のフォームのスキーマと、APIサーバーの入力の検証(「[引数の検証](../backend/004-graphql-server.md#引数の検証)」)の両方で同じ規則を使う。

```typescript
import { markdownTextSchema } from '<共用部品の配置先>/validation/markdown-text-schema.ts';
import { z } from '<共通部品の配置先>/utilities/validation/zod.ts';

const schema = z.object({
  body: markdownTextSchema({
    label: 'コメント',
    maxGraphemes: 2000,
    required: true,
  }),
});
```

| 順序 | 判定                                                                          | 文言                                                              |
| ---- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1    | 使用できない文字(孤立したサロゲート、タブ・LF・CR以外のC0制御文字、DEL)を含む | 「<項目名>に使用できない文字が含まれています。」                  |
| 2    | 必須で、空白だけ                                                              | 「<項目名>を入力してください。」                                  |
| 3    | 書記素の数が上限を超える                                                      | 「<項目名>は<上限>文字以内で入力してください。」(上限は3桁区切り) |

- 文字列でない値はZodの既定の失敗になる。値は変換せずにそのまま返す。
- 見出しレベル1・画像・Raw HTMLは検査しない。表示部品が文字列として表示するため、入力を拒む必要が無い。
- `maxGraphemes`は1以上の整数で指定する(違えば`RangeError`)。
- 共通部品の部品(`components/**`)とサーバーの部品(`server/**`)は検証規則を読み込まない(「[画面を持つアプリの静的解析](../coding/001-javascript-typescript-conventions.md#画面を持つアプリの静的解析)」の`frontend/direction/*`)。フォームのスキーマは、そのフォームを持つアプリのルートや画面の部品で作る。

### 値の受け渡しとカウンター

- 編集領域の変更の通知は、入力が止まってから約200ms後に届く。外枠はこれを約150msの間隔に間引いてフォームへ渡し、フォーカスが外れた時は通知を待たずに編集領域から最新の値を読んで渡してから離脱を伝える。送信ボタンの押下はフォーカスを外すため、送信時の値は最新である。
- 編集領域の直列化が文書の末尾に付ける改行は、フォームへ渡す前に1つだけ除く(文書の末尾の改行はマークダウンの意味を変えない)。このため「abc」は「3 / 2,000」と数えられ、見た目で上限ちょうどの入力は検証を通る。外部から渡された値との比較も、末尾の改行を1つ除いた値で行う。記法の正規化だけの違いは、内容を変えていなければ渡さない。
- `value`がフォームへ渡した値と異なる時(送信の後に空にするなど)は、編集領域の内容を置き換える。置き換えた値は送り返さない。
- カウンターは`value`の書記素の数と上限を「1,234 / 2,000」で示し、超えると注意色にする。数は利用者のロケールによらず日本語の3桁区切りで、サーバー側の描画とブラウザで同じ表示になる。支援技術へは、上限を超えた時と上限以内に戻った時だけ読み上げる。
- カウンターが数えるのは保存される原文であり、検証規則も同じ原文を数える。原文は記法(`**`・`[]()`・エスケープの`\`など)を含むため、見た目の文字数より大きくなり得る。
- 編集領域は記法を統一してマークダウンへ書き戻すため、保存される原文は利用者の入力した記法と異なり得る。見出しレベル1と画像はエスケープした文字列(`\# 見出し`・`!\[代替テキスト]\(…)`)で保存される。画像の文字列は再保存で1回だけ`(<URL>)`の形へ変わり、以後は変わらない。
- 原文を保存し、描画結果のHTMLを保存しない(「[マークダウンの原文の保存](../db/004-full-text-search.md#マークダウンの原文の保存)」)。

### 遅延読み込み

- 外枠(「書く」「プレビュー」のタブ・ツールバー・カウンター)はサーバー側の描画を含めて常に描く。編集領域は`ClientOnly`の中で、ブラウザでマウントした後にだけ`React.lazy`で遅延読み込みする。読み込むまでは同じ大きさの仮の表示(現在の値の描画結果。空ならプレースホルダーの文)と、支援技術にだけ伝える「読み込み中」の通知と、操作できないツールバーを出す。
- 編集領域のモジュールを読み込めない時は、失敗の文言と「再試行」のボタンを`role="alert"`で出す。再試行は新しい遅延読み込みの部品を作って読み込み直し(失敗した読み込みは同じ結果を返し続けるため)、読み込めたら編集領域へフォーカスを移す。値はフォームの状態にあるため失われない。
- 読み込み関数は、自身の`import()`が未決の間に届いたViteの読み込みの失敗の通知(`vite:preloadError`)の既定の動作を止め、`start/preload-recovery.ts`によるページの再読み込み(同じフォームの未保存の値が失われる)を起こさせない。`preload-recovery.ts`は、通知の全ての聞き手が終わってから既定の動作が止められたかを確かめ、止められた通知では再読み込みせず印も書かない。未決の間に別の遅延読み込み(画面遷移のチャンクなど)が失敗した場合も再読み込みしないが、その失敗はその読み込みの例外として既存の扱いに届く。
- 読み込みの後の編集領域の描画の失敗は、外へ伝えず`start/observability/report-error.ts`の`reportUnexpectedError(error, 'render')`で想定外の失敗として報告し(「[送信の入口](007-frontend-observability.md#送信の入口)」)、同じ失敗の表示と再試行を出す。失敗を受けると、編集領域から受け取った制御器を手放してツールバーを操作できない状態に戻し、リンクのダイアログを閉じる。失敗の表示にも現在の値の描画結果を出す。モジュールの読み込みの失敗は再試行で回復するため報告しない。
- 編集領域の作成(`editor.create()`)の拒否も、描画の失敗と同じに扱う。`@milkdown/react`の`useEditor`は作成の拒否をコンソールへ出すだけのため、編集領域は作成の処理を包んで拒否を受け取り、次の描画で拒否の理由を投げて読み込みの境界に捕まえさせる(想定外の失敗として報告し、失敗の表示と再試行を出す)。拒否された編集領域は作成の途中で始めた組み立てを続けて後から通知を届け得るため、拒否の後の通知(準備の完了・内容の変更・フォーカスの離脱など)は外枠へ伝えない。
- 「プレビュー」では`preview`の指定で描画した本文を`MarkdownContent`(`size="sm"`)で表示し、空白だけなら空の文言を出す。プレビューの間は編集領域を破棄せずに隠し、ツールバーは`aria-disabled`にする。

### 読み込みの制限

編集領域の実装のパッケージ(`@milkdown/*`・`vue`・`@vue/*`、推移的に`prosemirror-*`)は、ページの最初の読み込みとサーバー側の描画に含めない。

- 静的解析が、パッケージの読み込みを遅延読み込みのモジュールの中に、遅延読み込みのモジュールの動的`import()`を読み込み関数の中に限る(`frontend/editor-isolation`・`frontend/restricted-syntax`。「[画面を持つアプリの静的解析](../coding/001-javascript-typescript-conventions.md#画面を持つアプリの静的解析)」)。遅延読み込みのモジュールへの静的なimportとexport-fromは全ファイルで禁止し、相対パスの途中に`crepe/`を含む指定を全て遅延読み込みのモジュールとみなす。読み込み関数自身もパッケージを動的`import()`できない。読み込み関数には`frontend/restricted-syntax/editor-loader`を、遅延読み込みのモジュールの中には`frontend/restricted-syntax/editor-module`・`frontend/editor-isolation/editor-module`を掛け、生のHTMLの禁止と依存の向きの制限は外さない。規則を足す時は共通部品の`config/frontend-lint.ts`へ加え、アプリの静的解析の設定で同じ規則を設定し直さない。
- 遅延読み込みのモジュールは`React.lazy`のため既定のエクスポートの部品を1つ持ち、Milkdown・Vue・CrepeのCSSをディレクトリの外へ出さない。外枠とツールバーは、制御器の型だけで編集領域とつながる。
- CrepeのCSSは、使う機能(ProseMirror・リセット・カーソル・プレースホルダー・選択時のツールバー)と表のCSSだけを取り込む。全機能を読み込む`style.css`とテーマのCSSは、KaTeXとWebフォントを取り込むため使わない。Crepeの配色とフォントの変数はデザイントークンとOSのフォントの並びへ対応付ける(`crepe/crepe-theme.css`)。
- Vueのビルド時の機能フラグ(オプションAPI・本番の開発者ツール・ハイドレーションの不一致の詳細)は、共通部品の`config/vue-feature-flags.ts`の`VUE_FEATURE_FLAGS`で無効に定義し、利用側アプリのVite設定・ブラウザテストの設定と、共通部品のブラウザテストの設定・カタログの設定(`.storybook/main.ts`)の`define`に渡す。未定義だと開発時に警告が出て、使わない機能のコードも残る。
- 遅延読み込みのモジュールが読み込むパッケージの入口は、共通部品の`config/editor-prebundled-dependencies.ts`の一覧に集め、ブラウザテストの設定とカタログの設定がこれを事前バンドルする(「[部品を追加するとき](005-shared-components.md#部品を追加するとき)」)。
- 編集領域がページの最初の読み込みとサーバー側の描画に含まれないことは、共通部品のディレクトリで`bun run check:editor-chunks`を実行して確かめる。入力欄を静的に読み込む検査用の入口(`test/bundle/editor-entry.tsx`)をViteでブラウザ向けとサーバー側の描画向けにビルドし、入口から静的な読み込みをたどったチャンクにエディタの実装のパッケージのモジュールが無く、動的な読み込みの先に3種類(Milkdown・Vue・ProseMirror)とも有ることを、Rolldownの出力のチャンクの情報(含むモジュール・静的な読み込み・動的な読み込み)で確かめる。違反があれば、静的な範囲のモジュールと動的な読み込みの先に無い種類を表示して終了コード1で終える。ビルドの出力はファイルへ書かない。
  - マニフェスト(`manifest.json`)はチャンクの中のモジュールの一覧を持たず、サーバー側の描画向けには出力されないため使わない。
  - サーバー側の描画向けは、Workersへ配るアプリと同じく依存を外部化せずにまとめる。ブラウザ向けは、画面のアプリのビルドならTanStack Startのコンパイラが消すサーバー専用のファイル(`*.server.ts`)とNode.jsの組み込みモジュールを外部化する。
  - 手動で実行する検査で、一括検査とCIには含めない。エディタのパッケージの版を更新した時、入力欄・読み込み関数・遅延読み込みのモジュールの読み込みを変えた時に実行する。判定(`scripts/editor-chunk-isolation.ts`)は単体テストで確かめる。

### 編集領域

遅延読み込みのモジュールの編集領域は、表示部品が描画しない記法を内容に入れず、キーボードの利用者を閉じ込めない。

- 見出しレベル1と画像は、行頭の`# `の入力・ショートカット・マークダウンやHTMLの貼り付け・既存の値の読み込み・外部からの値の置き換えのどの経路でも、表示部品と同じ文字列(先頭に`# `を付けた段落、`![代替テキスト](URL)`)に置き換える(`crepe/forbidden-node-normalizer.ts`)。保存される原文では文字列としてエスケープされ、見出しレベル1と画像の構文は現れない。行頭の`##`〜`######`と空白の入力は同じレベルの見出しにする。
- 置き換えは入力や貼り付けと同じ取り消しの単位になり、取り消すと置き換える前の見出しレベル1ではなく入力の前に戻る。
- 文字列にした画像のURLは、読み直すとGFMのURLの自動リンクでリンクになる。表示部品も同じ規則でリンクにする。
- ファイルの貼り付けとドロップは何も挿入せず、ブラウザの既定の動作(画像の挿入やファイルを開く遷移)も止める(`crepe/file-transfer-guard.ts`)。文字列を伴う貼り付け(表計算ソフトなどからのコピー)は文字列だけを取り込む。ドロップの位置を示す機能がプラグインより先にドロップを挿入するため、編集領域の指定の段階で止める。
- Tabキー・Shift+Tabキーはリストと表の中でも前後の要素へフォーカスを移す。リストの階層の変更と表のセルの移動は`Mod-]`・`Mod-[`(macOSは`⌘`、それ以外は`Ctrl`)だけに割り当て、見出しレベル1のショートカットは外す。
- 編集領域の中の`⌘[`・`⌘]`・`Ctrl+[`・`Ctrl+]`は、リストや表の外で割り当てが何もしない時もブラウザの既定の動作を止める。macOSのブラウザが戻る・進むに割り当てており、入力中のページから離れないためである。
- `Mod-k`と選択時のツールバーのリンクの項目は、リンクのダイアログを開く。Crepeのリンクのツールチップは名前の無いボタンを持つため組み込まない。選択時のツールバーの操作の名前(太字・斜体・取り消し線・コード・リンク)は`utilities/messages/markdown-messages.ts`の定数を使う。
- リンクの設定と解除は、選択の範囲ではなくリンク全体に掛ける。
- Crepeのリストの機能は組み込まない。リストの項目が`ul > div > li`の構造になり、`axe-core`の`list`・`listitem`の規則に違反するためである。素の`ul`・`ol`・`li`を`crepe/crepe-theme.css`で整形する。
- タスクリストの項目のチェックの箱は疑似要素の飾りで支援技術へ届かないため、項目の先頭に視覚的に隠した「完了」「未完了」を装飾として置く(`crepe/task-item-state.ts`)。装飾は文書に含まれず、マークダウンへ書き戻されない。
- CJKの文字に隣接する強調と取り消し線を表示部品と同じに解釈するため、remark-cjk-friendlyとremark-cjk-friendly-gfm-strikethroughを登録する。強調は書き戻しをMilkdownの文字列化の設定が上書きするため解析だけを拡張する入口(`/parseOnly`)を、取り消し線は書き戻しも拡張しないと句読点の後の文字が文字参照になるため書き戻しも拡張する入口(`/bidi`)を使う。表示部品はどちらも`/parseOnly`を使う。
- 編集領域の要素は`role="textbox"`・`aria-multiline="true"`・`aria-labelledby`・`aria-describedby`と、状態に応じて`aria-invalid`・`aria-disabled`を持つ。`disabled`の間は読み取り専用にする。

### ツールバーとリンクのダイアログ

`MarkdownToolbar`と`MarkdownLinkDialog`(`components/markdown-editor/`)は、遅延読み込みのモジュールの外に置き、編集領域とは制御器の型だけでつながる。

| 部品                 | 主なprops                                                                                                          | 振る舞い                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MarkdownToolbar`    | `controller`・`activeActions`(選択中の書式)・`controlsId`(編集領域の`id`)・`disabled`・`inactive`・`onRequestLink` | 項目は`editor-actions.ts`の一覧(操作・種類・名前・アイコン)。押すと制御器で操作を実行して編集領域へフォーカスを戻し、リンクの項目は`onRequestLink`を呼ぶ                                                                                                                                                                                                                        |
| `MarkdownLinkDialog` | `open`・`controller`・`onOpenChange`                                                                               | 開くたびに選択中のリンクから始め、`http://`・`https://`・`mailto:`・`#`で始まる値(大文字小文字を区別せず、前後の空白を除く)だけを設定する。`http://`・`https://`の値は、表示部品がリンクにするURLとして解釈できてホストを持つものに限る(`https://`だけの値は受け付けない)。既存のリンクがある時だけ解除の操作を出す。閉じ方によらず、開いた元ではなく編集領域へフォーカスを戻す |

- ツールバーはRadix UIの`Toolbar`(`role="toolbar"`・名前「書式」)で、Tabの停止位置を1つだけ持ち、矢印キー・`Home`・`End`で項目を移る(端から反対の端へ回る)。各項目は名前と同じ文言の`title`を持つ。
- 項目の種類(`kind`)が切り替え(`toggle`:見出し・太字・斜体・箇条書き・番号付きリスト・引用・コード・コードブロック)の項目だけが、選択中の書式を`aria-pressed`で示す。挿入(`insert`:表)の項目は`aria-pressed`を持たず、ダイアログを開く(`dialog`:リンク)項目は`aria-pressed`の代わりに`aria-haspopup="dialog"`を持つ。
- 切り替えの操作は、押下中に押すと書式を外す。見出しとコードブロックは段落に戻し、箇条書き・番号付きリスト・引用は入れ子を含めて外へ出るまで持ち上げる(`crepe/editor-commands.ts`)。
- 制御器を受け取る前と`disabled`の間は項目を`disabled`にし、ツールバーごとTabの停止位置から外す。編集領域は読み込みの後にだけ存在するため、制御器を受け取るまでツールバーの`aria-controls`を出力しない。プレビューの表示中など一時的に操作させない間は`inactive`で`aria-disabled`にし、フォーカスは受けるが押しても何もしない。
- 形式に合わない値で設定すると、欄の下にエラーを表示して欄を`aria-invalid`にし、欄へフォーカスを戻す。以降は入力のたびに判定し直す。

## アクセシビリティの規約

入力欄と表示部品は「[アクセシビリティ規則](004-accessibility-rules.md)」に加えて次を守る。部品ごとの伝え方の一覧は「[状態とエラーの伝え方](004-accessibility-rules.md#状態とエラーの伝え方)」にある。

| 対象                       | 規約                                                                                                                                               |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tabキー                    | 編集領域の中でTabキー・Shift+Tabキーを奪わない。リストの階層と表のセルの移動は`Mod-]`・`Mod-[`だけで行う                                           |
| キー操作の説明             | `Mod-]`・`Mod-[`の操作は、画面に見えない説明(`EDITOR_KEYBOARD_HINT`)として編集領域の`aria-describedby`に加えて伝える。ツールバーには重ねて付けない |
| 編集領域の名前             | 表示しているラベルの要素のID(`labelId`)を`aria-labelledby`に使う                                                                                   |
| ツールバー                 | Tabの停止位置は1つで、矢印キーで項目を移る。切り替えの項目だけが`aria-pressed`を持ち、リンクの項目は`aria-haspopup="dialog"`を持つ                 |
| リンクのダイアログ         | 閉じ方によらず編集領域へフォーカスを戻す。形式の誤りは欄の`aria-invalid`と欄の下の文言で示す                                                       |
| 読み込み中・読み込みの失敗 | 読み込み中は`role="status"`の見えない文言と仮の表示の`aria-busy`、失敗は`role="alert"`の文言と再試行のボタン                                       |
| 文字数の上限               | 超えた時と戻った時だけ変わる`aria-live="polite"`の見えない文言で伝え、入力のたびには読み上げない                                                   |
| タスクリスト               | 表示ではチェックボックスに項目の文字列の名前を付け、編集領域では状態の見えない文言を置く                                                           |
| 表                         | 表示では横スクロールの枠を名前付きの領域にしてキーボードでスクロールできるようにする                                                               |
| 折りたたみ                 | 切替ボタンの`aria-expanded`・`aria-controls`。フォーカスやページ内の移動の先を隠さない                                                             |

- 全ての表の枠が同じ名前のため、1つのページに表が複数あると`axe-core`のベストプラクティスの規則`landmark-unique`が報告する。WCAG 2.2のAAの規則の違反ではない。

## 検索語の強調

検索結果の項目の見出しや要約のうち検索語に一致した箇所は、`HighlightedText`に表示する文字列(`text`)と検索語の配列(`terms`)を渡して`<mark>`で強調する。

```tsx
<p className="text-sm text-muted-foreground">
  <HighlightedText text={item.summary} terms={[query]} />
</p>
```

- 一致の範囲は共用部品の`findHighlightRanges`が求め、全文検索と同じく大文字小文字・全角半角・発音区別符号の違いを無視して、語の先頭からの一致だけを強調する(「[強調表示との一致](../db/004-full-text-search.md#強調表示との一致)」)。範囲は元の文字列の位置のため、表示する文字列は正規化せずにそのまま渡す。
- `terms`の各要素は空白で区切って別々の検索語として扱うため、検索欄の入力をそのまま1要素として渡してよい。一致が無い時と検索語が無い時は、文字列をそのまま表示する。
- 部品は文字列を要素で包まず、置いた親の要素(見出し・段落・リンクなど)の中に直接表示する。文字の大きさや折り返しは親の要素で指定する。
- `<mark>`の塗りはプライマリの薄い塗り(ライトは`bg-primary/15`、ダークは`bg-primary/25`)にし、文字色は親の文字色によらず`text-foreground`にする。控えめな文字色(`text-muted-foreground`)のままでは、塗りの上でコントラスト比4.5:1を下回るためである。
- 強調は塗りと文字色だけで示す。

## テスト

- 表示部品と入力欄のブラウザテストは、「[ブラウザテスト](004-accessibility-rules.md#ブラウザテスト)」に従って`runAxe`の違反0件も確かめる。
- 入力欄を描画する部品のテストは、`start/observability/report-error.ts`を`vi.mock`で差し替える。Vitestのブラウザテストの設定はTanStack Startのコンパイラを通らないため、差し替えないとサーバー専用の依存(`node:async_hooks`)の読み込みで失敗する。
- 読み込みの待機や失敗は、`load-crepe-editor.ts`を`vi.mock`で包み、読み込みの関数を差し替えた`loadCrepeEditor`で再現する。
- ツールバーとリンクのダイアログは、制御器の各関数を偽物(`vi.fn`)にした値を渡して部品だけを確かめてよい。
- 描画とサニタイズの規則は共用部品の単体テストで確かめる(「[攻撃パターン集の追加の手順](../security/004-markdown-sanitization.md#攻撃パターン集の追加の手順)」)。

## 既知の制限

- 編集領域のドロップの位置を示す機能は、破棄の時に30msのタイマーを消さない。ドラッグの直後30ms以内に入力欄を破棄すると、エラートラッキングへ1件の誤報が届く。エディタのパッケージを更新した時に再確認する。
- 遅延読み込みのチャンクの評価の途中で投げられた例外は、モジュールの読み込みの失敗として扱われ、想定外の失敗として報告されない。
- 作成が拒否された編集領域は、作成中の状態のまま終わり、破棄(`editor.destroy()`)が作成の終わりを待ち続けるため、破棄を省く。作成の途中まで組み立てたエディタの表示は破棄されず、文書から外れた要素として残る。
