# 本番準備のチェックリスト

**最終更新:** 2026-11-23
**対象spec:** launch-readiness(設計書の「Supporting References」の表を写した文書)
**関連:** [検証の記録](release-verification-report.md)・[プロジェクト固有の値](project-values.md)・[デプロイ手順](../GUIDES/tech/operations/001-deployment.md)

この文書は、本番リリースの前に開発者が実施する項目と、stagingの検証で開発者が行う作業を、実施者・確認方法・元のspecとともに並べる。結果は記入欄に書き、検証の詳細は[検証の記録](release-verification-report.md)に書く。

## 読み方

- 本番の項目は段階AからEの順に行う。前の段階の項目が終わってから次の段階へ進む。「順」の番号は段階を通した実施の順である。
- 「実施者」の欄の意味は次のとおり。
  - 開発: 開発者だけが行う作業。AIエージェントが行わない操作(下の一覧)を含むか、外部サービスの画面の操作を要する。
  - AI: AIエージェントが行う作業。prodの状態を変えない作業(PRの作成・検査・設定値の照合など)に限る。
  - AI・開発: 両方が関わる作業。括弧の中がそれぞれの担当を示す。
- 「記入」の欄には実施日(UTC)・実施者・結果を書く。結果は成功・失敗・保留のいずれかとする。保留の理由と依存する作業の番号は検証の記録に書く。
- 秘密の値(キー・トークン・パスフレーズ)と個人情報(メールアドレス・IPアドレス)は、この文書にも検証の記録にも書かない。値の登録先とフォルダの名前だけを書く。
- 固有の値(ホスト名・価格の名前・Infisicalのフォルダ)は含めてよい。Workerのシークレットのキーは[キーの一覧](project-values.md#workerのシークレットのキーの一覧)を正とし、B-06の実施時に照合する。

### 開発者だけが行う操作

AIエージェントは次の操作を行わない。実施者が「開発」の項目は、この操作を含むか、外部サービスのアカウントの画面を要する。

- prodへのデプロイ(リリースのプルリクエストのマージを含む)
- prodのシークレットの登録・削除
- リモートのデータベースへの書き込み(`--remote`を付けたD1の操作)
- 外部サービスのアカウントの設定(ダッシュボード・Stripe・Sentry・監視サービスなど)
- PRの承認とマージ

詳細な一覧は[デプロイ手順のAIエージェントが実行しない操作](../GUIDES/tech/operations/001-deployment.md#aiエージェントが実行しない操作)に従う。
