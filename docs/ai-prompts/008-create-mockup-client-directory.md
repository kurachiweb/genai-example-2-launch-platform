`mockups`アプリの`client/p`ディレクトリ内にて、利用者側ディレクトリページのデザインモックアップを作ってください。
デザインを考えるために、`README.md`の要件定義書や`docs/GUIDES/service`ディレクトリ内のドキュメントを一通り読み、方針決定や判断に悩む点の解決のため数十回私に質問してください。
作成済みのモックアップ画面に合わせるため次の指示に従ってください。

- デザイン/タイポグラフィ/UI/UXは[トップページモックアップ](../../mockups/src/routes/client/top/index.tsx)や[プロダクト詳細モックアップ](../../mockups/src/routes/client/p/$handle/index.tsx)のテイストに合わせてください。
- モックアップ内の、ユーザーが入力する内容を模した仮のテキストは英語で、短い/長い文章、長い英単語を交えた多様なものを生成してください。
- モックアップ内の、本来ユーザーがアップロードする画像の位置には、ユーザープロフィール画像やプロダクトロゴ及びスクリーンショット等に似せた3色以上のSVGアートを表示してください。
- ダークモード切り替えも実装し、`prefers-reduced-motion`などアクセシビリティも考慮してください。

ただし、トップページと異なりスポンサー広告は表示しないでください。

参考：`docs/GUIDES/service/design/002-page-layouts.md`の「[ディレクトリ](../GUIDES/service/design/002-page-layouts.md#ディレクトリ)」セクション

【表示する状態一覧】
利用者側プロダクト詳細ページ同様、URL内のクエリパラメータ及び`position: fixed`で右下に表示する状態切り替えラジオボタン群(折りたたみ可能)により、以下の状態を切り替えて画面内で起こりうるあらゆるケースをカバーすること。なお検索・絞り込み・並び替え・ページ番号はこのリストには含めない。

- ユーザーログイン状態
  - 未ログイン
  - ログイン済
  - ログイン済(メールアドレス未確認) ... 共通ヘッダー直下にメールアドレス確認の帯を表示する。閲覧・検索は制限しない
  - ログイン済(プロダクトの投稿者本人) ... 一覧に自身のプロダクトを含める
- 検索・絞り込み・並び替え・ページ番号 ... 状態切り替えパネルには置かず、ページ内の検索欄・各選択欄・ページネーションの操作で切り替え、本番と同じURLクエリ(`q`・`category`・`from`・`to`・`sort`・`page`)に保持する。状態切り替え用のクエリキーはこれらと重複させない
  - 検索キーワード無し ... 並び順の「関連度」は選択不可とし、既定はローンチ日の新しい順
  - 検索キーワードあり ... 並び順の既定は関連度。上限50文字の検索語でもレイアウトが崩れないようにする
  - カテゴリ・ローンチ期間で絞り込み ... カテゴリの既定は「全て」。期間はプリセット(昨日/今週/今月/今年/全期間)から選ぶ
  - `page`が範囲外 ... 空状態を表示し、1ページ目への導線を添える
- 該当件数
  - 多数(1,234件・62ページ) ... ページ番号の省略表示と、端数(14件)となる最終ページを確認できるようにする
  - 少数(3件) ... 1ページに収まる
  - 0件 ... 空状態。条件の指定中は条件の見直し・解除、条件なし(掲載プロダクトが1件も無い)ならローンチ予約への導線を添える
- プロダクト
  - 受賞バッジ
    - 受賞プロダクト無し
    - 受賞プロダクトあり ... Product of the Week(1回)・Product of the Week(複数回)・Product of the WeekとProduct of the Yearのプロダクトを一覧内に混在させ、ゴールドのバッジを付ける
  - 予選の勝利回数
    - 全て1回
    - 複数回の勝利を含む ... 基準勝利マッチ1件のみを表示する。基準勝利はローンチ期間で絞り込む場合は期間内の最新、それ以外は直近の勝利とし、期間の切り替えで表示するマッチが変わることを確認できるようにする
  - 基準勝利マッチのUpvote数
    - 多い(1,234対1,198) ... 3桁区切りと桁数の多いスコアでレイアウトが崩れないか確認する
    - 少ない(3対1)
    - 同数(30対30) ... 最終Upvote時間により勝敗が決まった「接戦」として強調し、その旨を添える
  - 不戦勝による掲載(FR-GAME-003・FR-GAME-014)
    - 無し
    - あり ... 対戦相手がいないため、Upvote数を出さず「対戦相手なし」「不戦勝」と表示
  - FR-GAME-013による早期勝敗決定での掲載
    - 無し
    - あり ... 「不戦勝」に確定時点の自身のUpvote数のみを添え、対戦相手は「非公開のプロダクト」と表示
  - 基準勝利マッチの対戦相手の公開状態
    - 全て掲載中 ... 敗北後に再ローンチして掲載された場合を想定し、名称からプロダクト詳細ページへ遷移
    - 全て未掲載 ... ロゴと名称を表示しリンクしない
    - 全て非公開 ... 名称を出さず「非公開のプロダクト」と汎用アイコンを表示
    - 上記3種の混在 ... 一覧内に並べる
- カテゴリの登録数 ... 管理者が上限なく追加できるため。いずれもシステム標準の「その他」を含める
  - 標準(10件程度)
  - 多数(40件程度) ... カテゴリ選択欄が長くなっても操作しやすいか確認する
- 画像の読み込み状態
  - 正常
  - 読み込み失敗または隔離中 ... ロゴ(対戦相手を含む)とプロフィール画像は名称やニックネームの頭文字を書記素単位で表示する。絵文字で始まる名称も混在させる
- ユーザー入力テキストの長さ
  - 標準
  - 上限に近い長さ ... 名称50文字・タグライン100文字・カテゴリ名30文字、長い英単語でレイアウトの崩れを確認する
- ページの動作状態
  - 通常
  - ローディング ... スケルトン表示。一覧項目のロゴ・名称・ボタンの形を保つ
  - 条件変更後の再読み込み ... 検索欄・絞り込み欄は操作できる状態を保ち、一覧部分のみ読み込み中を示す
  - 取得エラー ... 再試行ボタンと問い合わせへの導線を表示し、技術的詳細は出さない
