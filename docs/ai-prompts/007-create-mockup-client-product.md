`mockups`アプリの`client/p/$handle`ディレクトリ内にて、利用者側プロダクト詳細ページのデザインモックアップを作ってください。
デザインを考えるために、`README.md`の要件定義書や`docs/GUIDES/service`ディレクトリ内のドキュメントを一通り読み、方針決定や判断に悩む点の解決のため数十回私に質問してください。
利用者側トップページのモックアップ(mockups/src/routes/client/top/index.tsx)に合わせて次の指示に従ってください。

- デザイン/タイポグラフィ/UI/UXはそのトップページのテイストに合わせてください。
- モックアップ内の、ユーザーが入力する内容を模した仮のテキストは英語で、短い/長い文章、長い英単語を交えた多様なものを生成してください。
- モックアップ内の、本来ユーザーがアップロードする画像の位置には、ユーザープロフィール画像やプロダクトロゴ及びスクリーンショット等に似せた3色以上のSVGアートを表示してください。
- ダークモード切り替えも実装し、`prefers-reduced-motion`などアクセシビリティも考慮してください。

ただしトップページと異なりスポンサー広告は表示しないでください。

参考：`docs/GUIDES/service/design/002-page-layouts.md`の「プロダクト詳細(`/p/{handle}`)」セクション

【表示する状態一覧】
利用者側トップページ同様、URL内のクエリパラメータ及び`position: fixed`で右下に表示する状態切り替えラジオボタン群(折りたたみ可能)により、以下の状態を切り替えて画面内で起こりうるあらゆるケースをカバーすること。

- ユーザーログイン状態
  - 未ログイン
  - ログイン済
  - ログイン済(メールアドレス未確認) ... 評価の入力とコメントの投稿を制限(FR-USER-006)
  - ログイン済(このプロダクトの投稿者本人) ... 編集ボタンと再ローンチ予約ボタンを表示。自身のプロダクトのため評価と通報はできない(FR-RATNG-006・FR-REPOT-005)
- プロダクトの公開状態
  - 掲載済み ... ディレクトリに掲載されている
  - 未掲載(予選前・予選敗北のみ) ... 投稿者本人にだけ表示し、他のユーザーには404
  - 閲覧不可 ... 管理者による非公開化・投稿者の退会や停止・論理削除により、投稿者本人にも404
- プロダクトの進行状況 ... 投稿者本人の場合のみ、編集ボタンと再ローンチ予約ボタンの周辺に反映
  - 再ローンチ可能 ... 制限なし
  - ローンチ予定あり(予選前) ... 再ローンチできない理由を表示
  - 予選マッチ中 ... 同上
  - 予選敗北後の間隔制限中 ... 再ローンチ予約ボタンを無効化し、選べる最初のローンチ日を併記
  - 予選勝利後・Weekトーナメント参加前 ... 「Weekトーナメントに参加」ボタンと決済期限(ユーザーのタイムゾーンでの日時と相対表現)、参加しない場合の再ローンチ解除日を表示
  - 予選勝利後・Weekトーナメント参加前(決済期限が迫っている) ... 日曜日ローンチは猶予が24時間と短いため、決済期限を目立たせる
  - Weekトーナメント参加中 ... 再ローンチできない理由を表示
  - Week優勝後・Yearトーナメント参加前 ... 「Yearトーナメントに参加」ボタンと決済期限(最長で約63週先)を表示
  - Yearトーナメント参加中 ... 再ローンチできない理由を表示
- Ultras加入状態 ... 投稿者本人の場合のみ影響
  - 未加入 ... 敗北後の再ローンチ間隔は7日
  - 加入中 ... 敗北後の再ローンチ間隔は2日。参加前の状態では決済ボタンと決済期限の代わりに「参加費免除」を表示
- 受賞バッジ
  - 無し
  - Product of the Week(1回)
  - Product of the Week(複数回) ... 受賞した週ごとに表示
  - Product of the WeekとProduct of the Year ... Yearの受賞にはWeekの優勝が前提
- 5段階評価
  - 128件(平均4.6)、自分は未評価
  - 128件(平均4.6)、自分も評価済み(4)
  - 1件(平均4.0)
  - 0件 ... 平均値の代わりに評価がまだ無いことを表示
- スクリーンショットの枚数
  - 10枚 ... 縦長・横長・正方形を混在させ、横スクロールとライトボックス拡大を確認できるようにする
  - 1枚
  - 0枚 ... 任意項目のため区画ごと非表示
- 画像の読み込み状態
  - 正常 ... プロフィール画像未設定のユーザーを一部混在させる
  - 読み込み失敗または隔離中 ... ロゴとプロフィール画像は名称やニックネームの頭文字、スクリーンショットは薄灰色の背景に「画像を表示できません」
- ユーザー入力テキストの長さ
  - 標準
  - 上限に近い長さ ... 名称50文字・タグライン100文字・ニックネーム25文字、長文の説明文とコメント(見出し・リスト・表・コードブロック・引用を含むマークダウン)、長い英単語や長いURLでレイアウトの崩れを確認する
- マッチ履歴の件数と種別
  - 0件 ... 空状態。次の行動への導線を添える
  - 予選1件のみ
  - 予選とWeekトーナメント(1回戦〜決勝) ... 5件程度
  - 再ローンチを重ねた予選・Week・Yearトーナメントの全種別 ... 10件以上。ローンチ毎のコメント区画も3つにする
- マッチ履歴の各マッチのUpvote数
  - 左側が130、右側が100
  - 左側が4、右側が30
  - 両方30 ... 競っていることが分かるよう強調表示
  - 両方0
- 不戦勝の履歴
  - 無し
  - あり ... 対戦相手がいないため、Upvote数を出さず「不戦勝」と表示
- FR-GAME-013・FR-TOURW-014・FR-TOURY-014による早期勝敗決定の履歴
  - 無し
  - あり ... 「不戦勝」に確定時点のUpvote数を添え、対戦相手は「非公開のプロダクト」と表示
- マッチ履歴の対戦相手の公開状態
  - 全て公開中 ... 名称からプロダクト詳細ページへ遷移
  - 全て未掲載 ... 名称のみ表示しリンクしない
  - 全て非公開 ... 名称を出さず「非公開のプロダクト」と表示
  - 上記3種の混在 ... 履歴内に並べる
- トップレベルのコメント件数 ... ログイン済状態なら、そのうち1件は自分のコメント(編集・削除可)
  - 22件超 ... 「さらに読み込む」で続きを取得(トップレベルのコメントはページ毎に10件)
  - 3件
  - 0件 ... 空状態。次の行動への導線を添える
- コメントの返信と削除表示
  - 返信なし
  - 3階層までの返信 ... インデントで表現
  - 3階層までの返信と、削除された旨の表示 ... 退会・停止・本人削除・管理者による非公開化のコメントを置き換え、返信は残す(FR-COMNT-007)
- ページの動作状態
  - 通常
  - ローディング ... スケルトン表示。ロゴ・名称・ボタンの形を保つ
  - 取得エラー ... 再試行ボタンと問い合わせへの導線を表示し、技術的詳細は出さない
  - 縮退運転 ... 外部サービス障害を想定し、閲覧は維持したまま決済ボタンなど影響する操作の近くに「現在ご利用いただけません」を表示
